### Turbovec - Rust로 구현한 벡터 검색용 Google TurboQuant | GeekNews

- Turbovec은 Google Research의 TurboQuant를 기반으로 한 Rust 벡터 인덱스로, 1,000만 개 float32 문서가 차지하는 31GB를 4GB로 줄이면서 FAISS보다 빠르게 검색함
- 별도 학습이나 매개변수 조정 없이 벡터를 즉시 추가하며, ARM의 NEON과 x86의 AVX-512·AVX2를 활용한 SIMD 검색으로 측정된 모든 구성에서 FAISS IndexPQFastScan 을 앞섬
- 100K 벡터·1K 쿼리·k=64 벤치마크에서 4비트 검색은 FAISS보다 ARM에서 평균 3.5배, x86에서 3.4배 빨랐고 2비트에서는 각각 26%, 20% 빨랐음
- sync(path) 는 변경분만 충돌 안전하게 저장하고, 검색 시 허용 목록을 SIMD 커널 내부에서 적용하며,IdMapIndex 는 안정적인 외부 ID와 O(1) 삭제를 지원함
- Python과 Rust에서 로컬로 실행되며 LangChain·LlamaIndex·Haystack·Agno와 연동할 수 있어, 메모리·지연 시간·데이터 외부 반출을 제한해야 하는 RAG 구성에 사용할 수 있음
프로젝트 개요
- Turbovec는 데이터와 무관하게 동작하고 별도 학습 단계가 없는 TurboQuant 양자화기를 구현한 Rust 벡터 인덱스이며 Python 바인딩도 제공함
- 2비트 또는 4비트로 벡터를 압축하며, 1,536차원 FP32 벡터 하나를 6,144바이트에서 2비트 기준 384바이트로 줄여 16배 압축함
- 벡터를 추가하면 바로 인덱싱되므로 말뭉치가 커져도 재학습, 매개변수 조정, 전체 재구축이 필요 없음
- 관리형 서비스 없이 머신이나 VPC 안에서 실행되며, 오픈소스 임베딩 모델과 결합해 외부 연결이 차단된 RAG 스택을 구성할 수 있음
검색과 필터링
- 검색 커널은 데이터베이스 벡터를 복원하지 않고 쿼리를 같은 공간으로 한 번 회전한 뒤 코드북 값을 이용해 직접 점수를 계산함
- 아키텍처별 SIMD 경로를 제공함
 - ARM은 NEON SDOT ·SMMLA 를 사용함
 - 최신 x86은 AVX-512 VNNI·vpermb ·AVX-512BW를 사용함
 - 지원 기능에 따라 AVX2와 스칼라 경로로 대체됨
- ARM은 NEON 
- search() 에 ID 허용 목록이나 슬롯 비트마스크를 전달하면 필터를 SIMD 커널 내부에서 적용함
 - 허용 슬롯이 없는 32개 벡터 블록은 LUT 조회와 점수 계산 전에 건너뜀
 - 점수를 계산한 블록 안의 비허용 슬롯은 힙 삽입 단계에서 제외함
 - 선택 범위가 좁을수록 결과를 사후 폐기하는 대신 SIMD 계산 자체를 대부분 피할 수 있음
- 결과 수는 min(k, n_allowed) 이며, 허용된 고유 벡터가k 보다 적으면 대체 결과로 채우지 않음
- SQL, BM25, ACL, 시간 범위 등으로 후보 ID를 먼저 좁힌 뒤 해당 집합 안에서 밀집 벡터 재순위를 수행하는 하이브리드 검색을 지원함

- 기본 TurboQuantIndex 는 벡터 추가, 검색, 전체 파일 저장·불러오기를 제공함
- IdMapIndex 는 삭제 후에도 유지되는uint64 외부 ID를 지원하며,remove(id) 는 ID 맵 관리와 swap-and-pop을 이용해 O(1) 로 동작함

TurboQuant 압축 과정
- 정규화 단계에서 각 벡터의 크기를 단일 float로 따로 저장하고 벡터를 초구면 위의 단위 방향으로 변환함
- 모든 벡터에 같은 무작위 직교 행렬을 곱하면 각 좌표가 입력 데이터와 무관한 Beta 분포를 따르며, 고차원에서는 N(0, 1/d) 에 수렴함
- 선택적인 TQ+ 좌표별 보정은 유한 차원에서 좌표 분포가 기준 형태에서 벗어나는 문제를 다룸
 - 좌표마다 이동과 스케일 두 값을 맞춰 경험적 분위수를 코드북의 가장 바깥 중심점에 대응시킴
 - 확률 수준은 고정값이 아니라 비트 폭에 따라 2비트에서 약 0.933, 4비트에서 약 0.996을 사용함
 - 약 1,024행의 무작위 대표 표본으로 index.calibrate(sample) 을 한 번 호출하면 이후 모든 추가 작업에 같은 보정을 재사용함
 - 보정하지 않은 인덱스는 기본 TurboQuant로 동작하며 calibration_state 가 상태를 반환함
 - 분포 이탈이 큰 구성에서는 R@1이 최대 2.2%포인트 향상됨
- Lloyd-Max 스칼라 양자화는 알려진 분포를 바탕으로 평균제곱오차를 최소화하는 경계와 중심점을 사전 계산함
 - 2비트는 좌표당 4개, 4비트는 16개 버킷을 사용함
 - 데이터로 코드북을 학습하지 않음
- 양자화한 좌표 값은 바이트 안에 비트 단위로 조밀하게 저장함
- 길이 재정규화 점수는 스칼라 양자화가 내적을 체계적으로 낮게 추정하는 편향을 보정함
 - 인코딩할 때 회전된 단위 벡터와 중심점 복원 벡터의 내적을 구해 ||v|| / ⟨u, x̂⟩ 를 저장함
 - 검색 커널이 힙 삽입 전에 후보 점수에 이 값을 곱해 내적 추정의 하향 편향을 제거함
 - 기존 벡터별 스칼라 저장 공간을 활용하므로 추가 저장 공간과 검색 시간 비용이 없음
 - 인코딩 시 벡터당 d차원 내적 한 번이 추가되며, 1,536차원 벡터 100만 개에서는 추가 시간이 1초 미만임
- 인코딩할 때 회전된 단위 벡터와 중심점 복원 벡터의 내적을 구해 
- Lloyd-Max 코드북의 왜곡은 Shannon 왜곡률 하한의 2.7배 이내임
검색 성능과 재현율
- 검색 벤치마크는 100K 벡터, 1K 쿼리, k=64에서 5회 실행 중앙값을 사용함
- ARM의 GCP c4a-standard-8 Google Axion 8 vCPU 환경에서 모든 구성이 FAISS FastScan보다 빨랐음
 - 4비트는 평균 3.5배로 셀별 3.4~3.7배였음
 - 2비트는 평균 26%로 셀별 22~29% 빨랐음
- x86의 Intel Xeon Platinum 8481C Sapphire Rapids 8 vCPU 환경에서도 모든 구성이 앞섬
 - 4비트는 평균 3.4배로 셀별 3.2~3.5배였음
 - 2비트는 평균 20%로 셀별 5~32% 빨랐음
- 재현율 비교는 100K 벡터와 k=64에서 FAISS IndexPQ 의 LUT256·8비트·float32 LUT를 기준으로 사용했으며, FAISS 서브 양자화기 수를 TurboQuant 비트율에 맞춤
- OpenAI 1,536·3,072차원 데이터에서 TQ+는 4개 셀 중 3개에서 R@1이 FAISS보다 0.9~2.9%포인트 높았음
 - 1,536차원 4비트에서는 0.7%포인트 낮았음
 - 양쪽 모두 k=8에서 1.0에 도달했고 k≤4에서도 0.997 이상이었음
- 저차원에서는 점근적 Beta 가정이 덜 정확한 GloVe 200차원을 사용함
 - TQ+의 R@1은 4비트에서 1.9%포인트, 2비트에서 0.8%포인트 앞섬
 - 2비트에서는 k≈8부터 FAISS가 근소하게 앞섬
 - 보정된 2비트 R@1은 0.572로 FAISS의 0.564보다 높았음
- FAISS IndexPQ 기준선은 TurboQuant 논문의 사용자 정의 u8 LUT PQ보다 점수 계산 정밀도가 높고 코드북 학습에 k-means++를 사용하는 더 강한 비교 대상임
삽입과 삭제 성능
- 삽입·삭제 측정은 100K OpenAI 벡터에서 Python 호출 비용까지 포함한 사용자 체감 지연 시간을 비교함
- 이미 채워진 인덱스에 벡터 하나를 추가하는 데 6.3~19.7μs가 걸려 FAISS 단일 추가보다 7.6~13.9배 빨랐음
- 100개 배치 추가는 벡터당 4.6~16.3μs로 줄어 FAISS 동일 배치보다 4.6~15.1배 빨랐음
- IdMapIndex.remove(id) 는 셀에 따라 삭제당 0.44~1.22μs 또는 0.59~1.37μs가 걸렸음
- FAISS의 IndexIDMap 과IndexPQFastScan 조합은 삭제할 때마다 저장 코드를 다시 패킹해, 100K 인덱스에서 단일 삭제가 0.19~1.02초 걸렸음
- 단일 추가 작업은 직렬로 실행되므로 멀티스레드 셀도 n=1에서는 단일 스레드와 비슷함
언어와 프레임워크 지원
- Python 패키지는 pip install turbovec , Rust 크레이트는cargo add turbovec 으로 설치함
- Python 입력 벡터와 쿼리는 (n, dim) 형태의 2차원float32 배열이어야 하며, 다른 자료형은 자동 변환하지 않고 거부함
- 참조용 인메모리 벡터·문서 저장소를 대체하도록 네 프레임워크 연동을 제공함
 - LangChain: InMemoryVectorStore 대체
 - LlamaIndex: SimpleVectorStore 대체
 - Haystack: InMemoryDocumentStore 대체
 - Agno: LanceDb 대체

빌드와 벤치마크 검증
- Python 빌드는 maturin , Rust 빌드는cargo build --release 를 사용함
- 모든 x86_64 빌드는 SSE4.2를 기준으로 하는 x86-64-v2를 대상으로 하며, AVX-512와 AVX2 커널은 런타임 CPU 기능 감지로 선택함
- 공개 수치는 실제 임베딩과 FAISS 비교 대상, 고정된 형태, ARM·x86 공식 환경을 사용하는 benchmarks/suite/ 에서 생성함
- 별도의 Rust insert_bench 는 합성 벡터로 대량 추가, 추가 삽입, 단일 추가, 삭제를 빠르게 측정하는 최적화용 선별 도구이며 공개 벤치마크 수치의 출처가 아님
- examples/encode_hash 는 고정 입력에 대한 인코딩 단계별 해시를 출력하며, CI가 운영체제별 결과 불일치를 감지해 인코딩의 바이트 단위 동일성을 검사함
- 구현은 TurboQuant 논문을 기반으로 하며, 벡터별 길이 재정규화는 RaBitQ, x86 SIMD의 패킹·니블 LUT 점수 계산·u16 누산 방식은 FAISS FastScan)을 참고함

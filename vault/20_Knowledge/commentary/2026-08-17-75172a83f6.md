### 모델은 의도적으로 더 멍청해지고 있다 | GeekNews

(https://news.hada.io/topic?id=32564)

- 최근 소형/MoE 모델은 적은 활성 매개변수로도 수학·코딩 추론 성능을 높이는 대신, 세부 정보 회상 능력은 약해지는 모습을 보임
- 사실 지식(factual knowledge) 은 많은 모델 용량을 차지하고 빠르게 낡지만, 문제 분해·검산·되돌아가기 같은 추론 절차는 여러 문제에 반복 사용할 수 있음
- 모델에는 폭넓은 기본 지식만 남기고, 버전·가격·인물·API 같은 세부 정보는 검색·문서·도구 호출로 실행 시점에 공급하는 구조가 더 효율적일 수 있음
- 이렇게 하면 코딩 에이전트가 오래된 내부 지식 대신 현재 프로젝트의 문서와 의존성을 확인하고, 잘못된 정보도 출처를 찾아 수정 가능한 문제로 바꿀 수 있음
- 더 나아가 세부 지식을 모델 밖으로 충분히 옮기면 프런티어급 추론을 훨씬 작은 로컬 모델에서 실행할 가능성도 있다는 전망이지만, 아직 가설에 가까움
추론은 강해지고, 세부 정보 회상은 약해짐
- GLM-5.2는 토큰당 약 40B 활성 매개변수로 AIME 2026에서 99.2%, Qwen3.5는 17B로 91.3%를 기록함
- DeepSeek V4-Flash는 전체 284B 매개변수 가운데 토큰당 약 13B만 활성화함
- Qwen3.5 9B는 양자화하면 6GB VRAM에 들어가면서도 10B 미만 모델에서 높은 종합 성능을 보임
- 반면 도구 없이 세부 정보를 직접 회상하는 SimpleQA에서는 Gemini 2.5 Pro가 53%였고, Qwen3.5 4B/9B는 Artificial Analysis의 지식 평가에서 80~82%의 환각률을 기록함
- 이런 차이는 모델 용량을 수많은 세부 정보를 저장하는 데 쓰기보다 재사용 가능한 추론 능력에 집중하는 절충으로 해석할 수 있음
사실 지식은 많은 저장 공간이 필요함
- Physics of Language Models 의 통제된 실험에서는 모델의 사실 지식 저장 용량을 매개변수당 약 2비트 수준으로 측정함
- 잘 알려지지 않은 사람의 생년, 지역별 인구, npm 패키지 함수의 인수 순서처럼 수많은 세부 정보를 가중치에 직접 넣으려면 많은 매개변수가 필요함
- 반면 추론에는 여러 문제에서 반복해서 사용할 수 있는 비교적 작은 절차 집합이 있음
 - 문제를 작은 단위로 분해
 - 중간 상태를 추적
 - 결과를 검산
 - 실패한 단계에서 되돌아감
- 증류와 검증 가능한 과제를 활용한 강화학습은 이런 추론 절차를 더 작은 모델로 옮기는 데 유리함
- Phi-4처럼 수학에는 강하지만 일반 지식 문제에는 상대적으로 약한 모델도, 단순한 약점이 아니라 모델 용량을 어디에 사용할 것인지에 대한 선택으로 볼 수 있다는 해석임
모델에는 ‘얕고 넓은’ 기본 지식을 남김
- 세부 지식을 모두 모델 밖으로 빼자는 것은 아니며, 질문을 이해하고 무엇을 찾아야 하는지 판단할 정도의 폭넓은 기본 지식은 필요함
- PostgreSQL이라면 무엇인지, 어디에 쓰는지, MVCC가 대략 어떻게 작동하는지는 알되 특정 Planner 기능이 어느 버전에 추가됐는지까지 기억할 필요는 없다는 식임
- 이런 기본 지식이 있어야 적절한 검색어를 만들고, 검색 결과가 질문과 관련 있는지 판단하며, 여러 출처를 비교할 수 있음
- 핵심은 검색하기 쉽지만 가중치에 저장하기 비싼 세부 정보부터 외부로 옮기는 것임
사실 지식은 빠르게 낡지만 추론 절차는 오래감
- 프런티어 모델은 수개월에 걸쳐 훈련되지만, 학습이 끝나는 순간부터 라이브러리 API·가격·인물의 소속 같은 세부 정보는 낡기 시작함
- 가중치에 저장된 지식을 갱신하려면 추가 학습이 필요하지만, 대수학·문제 분해·두 출처의 모순 찾기 같은 추론 방법은 훨씬 오래 유지됨
- 따라서 비싸고 천천히 갱신되는 모델에는 오래 유지되는 추론 능력을 넣고, 빠르게 바뀌는 세계의 상태는 실행 시점에 외부에서 공급하는 편이 효율적이라는 주장임
- 현재 세계의 세부 정보를 대부분 외부에서 가져온다면 모델의 knowledge cutoff 도 지금보다 덜 중요한 개념이 될 수 있음
세부 정보는 에이전트 하네스가 공급
- 모델이 내부에 저장하지 않은 정보는 지식베이스 검색, 웹 검색, 도구 호출, 파일시스템의 문서 등을 통해 실행 시점에 가져올 수 있음
- 모델은 무엇을 찾아야 하는지 결정하고, 가져온 자료를 바탕으로 추론하는 역할에 집중함
- Rust is a harness에서 기계적으로 검증 가능한 피드백을 에이전트에 제공했다면, 여기서는 반대로 추론에 필요한 최신 정보를 하네스가 공급하는 역할을 강조함
- 코딩 에이전트는 라이브러리 API 전체를 기억할 필요 없이 실제 node_modules 나 현재 설치된 패키지 문서를 확인할 수 있음
- 학습 데이터에 많이 등장했던 과거 API 대신 현재 프로젝트에 실제 설치된 버전을 기준으로 작업할 수 있다는 장점이 있음
프런티어급 추론을 소비자용 GPU에서 실행할 수 있을까
- DeepSeek V4-Flash는 전체 284B 매개변수를 가지고 있지만 토큰당 활성화되는 것은 약 13B여서, 실제 추론 계산량은 전체 모델 크기보다 훨씬 작음
- 여기서 비활성 Expert 매개변수의 상당 부분이 사실 지식을 저장하는 역할을 한다고 가정하고, 이를 외부 지식으로 대체할 수 있다면 전체 모델 크기도 줄일 수 있다는 전망임
- 이를 끝까지 밀어붙이면 20~40B급 모델을 4-bit로 양자화해 24GB GPU에서 프런티어급 추론을 실행하는 구성을 예상할 수 있음
- 다만 Expert 계층 대부분이 사실 지식 저장용이라는 전제나 실제로 그 정도까지 모델을 줄일 수 있다는 부분은 아직 입증된 결과가 아님
- 이런 모델은 자체적으로 기억하는 세부 정보가 적기 때문에, 모르는 질문에 그럴듯한 답을 만들어내기보다 검색이나 도구 호출로 확인하는 능력이 중요해짐
환각을 추적 가능한 데이터 버그로 바꾸기
- 가중치에 잘못 저장된 지식은 어디서 비롯됐는지 찾기 어렵고, 특정 오류 하나만 직접 수정하기도 어려움
- 외부 문서에서 가져온 정보라면 어떤 출처를 사용했는지 확인하고, 문서가 잘못됐다면 수정해 이후 요청에 바로 반영할 수 있음
- 같은 오류가 다시 발생하지 않도록 회귀 테스트를 만드는 것도 가능함
- 검색을 사용해도 모델이 출처를 잘못 읽거나 여러 정보를 잘못 결합할 수 있어 환각 자체가 완전히 사라지는 것은 아님
- 그래도 근거가 외부에 있다면 오류의 위치를 찾아 수정할 수 있어, 불투명한 모델 기억의 문제가 일반적인 데이터 버그에 가까워진다는 것이 중요한 차이임

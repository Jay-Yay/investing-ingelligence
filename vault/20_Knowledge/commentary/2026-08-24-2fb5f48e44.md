## 첨부 기사 원문
### agent.md로 LLM 생성 코드의 품질 높이기 | GeekNews

(https://news.hada.io/topic?id=32833)

- 2025년에는 컴파일조차 못 하던 LLM이 2026년에는 복잡한 구현과 버그 분석까지 해냈지만, 스파게티 코드와 부족한 주석·구조 탓에 프로덕션에 바로 쓰기 어려웠음
- 세션마다 반복하던 코드 리뷰 지침을 agent.md에 모아 프롬프트에 자동 주입하자, 생성 코드가 직접 작성한 수준에 가까워지고 검토 초점도 스타일에서 아키텍처와 설계로 이동함
- 짧고 정확한 문장, 매직 넘버 제거, 이른 반환, enum 매개변수, 접근 제한 유지, 계층 경계 준수와 관련 없는 변경 최소화 등을 규칙으로 지정함
- 버그 수정은 실패하는 테스트 작성부터 시작하고, 커밋 메시지는 50자 이내 제목·명령형 사용·본문 72자 줄바꿈 등 7개 규칙을 따르게 함
- 긴 문맥에서는 중간 지침을 덜 따르는 문맥 희석이 발생하므로 기능마다 새 세션을 시작하거나 Reload agent.md 로 지침을 다시 불러와야 하며, 생성 코드는 여전히 직접 검증해야 함
반복적인 코드 리뷰를 agent.md로 자동 적용
- 2025년 중반 Rust 기반 mDNS 구현체 libadbmdns 개발에 처음 LLM을 사용했을 때는 생성 코드가 컴파일되지 않았음
- 2026년 1월에는 복잡한 indexed-binary heap 클래스를 작성하고, Windows IOCP 구현 때문에 발생한 polling 크레이트의 드문 버그도 찾아냄
- 기능 구현 능력과 달리 결과물은 주석과 구조가 없는 스파게티 코드였음
 - 프로덕션 수준으로 정리하는 시간이 개발 속도 향상을 상쇄함
- 2026년 3월 Antigravity와 VS Code의 Claude Code 플러그인 같은 에이전트 IDE에서 staged 코드를 반복 검토함
 - 매직 넘버를 사용하지 않도록 지시함
 - 코드의 의도를 설명하는 짧은 주석을 추가하도록 함
 - 함수 이름을 짧게 만들도록 함
- 반복 지시를 거치면 코드 품질이 직접 작성한 수준에 가까워졌지만, 새 세션마다 같은 내용을 되풀이해야 했음
- 코딩 하네스가 세션 시작 시 agent.md 를 읽어 프롬프트에 주입한다는 점을 이용해 반복되는 지침을 저장함
 - 프로젝트 루트에 개인용 agent.md 를 배치함
 - gemini.md 와claude.md 를agent.md 로 심볼릭 링크해 여러 환경에서 사용할 수 있음
 - 새 규칙이 필요하면 편집기를 열지 않고 에이전트에게 agent.md 업데이트를 요청함
- 프로젝트 루트에 개인용 
짧고 직접적인 문장 사용
- 사람이 읽는 주석, 커밋 메시지, 응답은 단어를 신중히 골라 최대한 짧고 직접적으로 작성함
- 과장과 칭찬을 피하고 사실을 직설적으로 전달함
상수와 함수 인터페이스 규칙
- 반복되거나 의미 있는 매직 넘버와 문자열은 설명적인 상수나 enum으로 추출함
 - 자명한 일회성 값은 불필요한 복잡성을 피하도록 인라인으로 유지함
 - HTTP 200 OK 처럼 명세에서 가져온 값은 반복 여부와 관계없이 상수를 사용함
- 들여쓰기를 줄이고 Arrow Anti-Pattern을 피하도록 이른 반환과 continue 를 활용함
- 함수 이름은 30자 미만으로 유지함
- 함수 매개변수의 boolean 대신 enum을 사용함
- 한 줄짜리 if 문에도 항상{} 를 사용함
코드의 의도와 구조를 드러내는 규칙
- 논리적인 코드 블록 사이에 빈 줄을 넣어 읽기 쉽게 만듦
- 코드 블록이 무엇을 하고 왜 필요한지 설명하는 짧고 직접적인 주석을 추가함
 - 가능하면 예제를 사용함
 - 전체 시스템을 설명할 때는 ASCII 그림을 제안함
- 하위 수준 동작은 전용 드라이버나 추상화 계층에 캡슐화함
 - 원시 하드웨어 I/O, 섹터 파싱, 직접 소켓 스트림을 애플리케이션의 나머지 부분에 노출하지 않음
 - 호출 코드는 구현 세부 사항이 아닌 도메인 개념을 다루는 상위 수준 API를 사용함
접근 제한과 계층 경계 유지
- 멤버 가시성 변경을 중대한 설계 변화로 취급함
 - 설계상 외부 접근이 반드시 필요하지 않으면 필드와 함수를 private으로 유지함
 - private을 internal이나 public으로 바꾸기 전에 사용자 승인을 요청함
- 각 계층은 바로 아래의 인접 계층과만 직접 통신함
 - 컨트롤러나 UI가 데이터베이스 쿼리, 원시 하드웨어 드라이버, 하위 네트워크 클라이언트를 직접 호출하지 않음
 - 중간 서비스나 추상화 계층을 우회하지 않음
- 구현할 기능과 관련 없는 코드 블록은 건드리지 않고 변경된 줄 수를 최소화함
 - 수정하지 않은 코드에 주석을 추가하는 것처럼 요청 범위 밖의 정리 작업을 하지 않음
커밋 메시지 작성 규칙
- 제목과 본문 사이에 빈 줄 하나를 둠
- 제목은 50자 이내로 제한하고 절대 상한은 72자로 둠
- 제목 첫 글자를 대문자로 씀
- 제목 끝에 마침표를 붙이지 않음
- 제목은 “If applied, this commit will ...”을 완성하는 명령형으로 작성함
- Git 서식 문제를 막도록 본문을 72자에서 수동 줄바꿈함
- 구현 방법은 코드에 맡기고 본문에는 무엇을 왜 변경했는지 기록함
버그 수정은 실패하는 테스트부터 시작
- 버그 수정 요청을 받으면 수정 코드를 바로 작성하지 않음
- 먼저 해당 버그를 재현하는 테스트를 작성하고 실제로 실패하는지 확인함
- 수정 코드를 작성한 뒤 같은 테스트가 통과하는지 다시 확인함
품질 향상 효과와 문맥 희석의 한계
- agent.md 는 생성 코드 품질을 크게 높였지만 코드 검토를 없애는 만능책은 아님
 - LLM은 계속 환각할 수 있어 생성 코드를 신뢰할 수 없음
 - 여전히 직접 검증하고 여러 번 반복해야 함
 - 스타일 수정 부담이 줄어들어 아키텍처와 설계 검토에 더 집중할 수 있게 됨
- Lost in the Middle 이 다룬 문맥 희석(context dilution) 때문에 문맥이 길어지면 모델이 중간 지침보다 시작과 끝에 더 주의를 기울임
 - 원인은 아직 충분히 밝혀지지 않았음
 - 기능마다 새 세션을 시작해 문맥을 짧게 유지함
 - 코드 품질이 떨어지면 Reload agent.md 라고 요청해 지침을 다시 불러옴

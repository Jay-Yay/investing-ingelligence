## 첨부 기사 원문
### 100배 저렴한 오픈 모델로 검색에서 GPT-5.6 Sol 능가하기 | GeekNews

(https://news.hada.io/topic?id=32204)

- Castform으로 강화학습 후처리한 4B 오픈 소스 모델이 GPT-5.6 Sol과 같은 수준의 검색 정확도를 달성하면서 비용은 100분의 1로 낮춤
- 에이전트 검색은 한 번의 임베딩 검색에서 여러 차례 계획·검색하는 방식으로 진화했으며, GPT-5.6 Sol 기반 다중 턴 검색은 요청당 10초 이상·약 0.03달러가 들어 비용과 지연이 커짐
- Castform은 문서·제품 기록·지원 자료·고객 상호작용·운영 데이터에서 질문과 정답을 생성하고, 검색 도구와 보상 함수를 결합해 모델을 강화학습 후처리함
- Neon은 원문 저장부터 합성 데이터 생성, 학습 롤아웃, 프로덕션 추론까지 동일한 Lakebase Search 환경을 제공하고 급격한 병렬 검색 부하는 동적 컴퓨팅 확장으로 처리함
- 모델별 검색 학습에 데이터베이스 자동 확장과 브랜칭을 결합하면, 고가의 프런티어 모델을 반복 호출하지 않고도 검색 및 상태 변경 에이전트를 대규모로 훈련할 수 있음
단일 검색에서 에이전트 검색으로
- 좋은 에이전트에는 올바른 데이터를 찾는 도구와 컨텍스트, 무엇을 검색할지 판단하는 모델이 모두 필요함
- 2022년 무렵 데이터베이스 업체들이 임베딩 검색을 도입했으며, pgvector 는 Neon에서 가장 많이 내려받은 확장이었음
 - 개발자들이 LLM에 컨텍스트를 제공하려고 직접 구축한 RAG 파이프라인도 본질적으로 임베딩 유사도 검색을 사용함
- 2025년 무렵 에이전트가 확산하면서 큰 문제를 작은 단계로 나누는 다중 홉 검색이 등장함
 - 모델은 단일 쿼리를 보내는 대신 반복문 안에서 계획하고 여러 번 검색함
 - 매 반복마다 프런티어 모델을 호출하므로 사용자 요청당 비용과 지연 시간이 늘어남
- GPT-5.6 Sol을 사용한 일반적인 다중 턴 검색은 종단 간 10초 이상 걸리고 약 0.03달러가 필요함
- 소형 오픈 가중치 모델은 비용이 100분의 1이지만, 별도 학습 없이 사용하는 기본 성능은 폐쇄형 API 모델보다 낮음
 - 특정 검색 작업에 강화학습 후처리를 적용하면 훨씬 낮은 요청당 비용으로 프런티어 모델과 같거나 더 높은 성능을 달성할 수 있음
 - Castform은 머신러닝과 GPU 내부 구조를 직접 다루지 않고도 후처리할 수 있게 해, 이를 프롬프트 엔지니어링만큼 접근하기 쉽게 만드는 것을 목표로 함
Neon을 활용하는 Castform 파이프라인
- Castform은 Lakebase Search를 통해 전체 파이프라인을 Neon에서 실행함
 - 원본 문서는 Neon의 Postgres에 저장함
 - 합성 데이터 생성 단계에서는 lakebase_text 와lakebase_vector 로 학습 작업을 작성함
 - 강화학습 중에는 각 롤아웃의 검색 도구 호출에 Lakebase Search를 사용함
 - 완성된 모델도 프로덕션 추론에서 동일한 검색 도구를 호출함
기업 데이터를 학습 작업으로 전환
- 강화학습 후처리에는 세 가지 요소가 필요함
 - 사용자의 질문에 답하는 것과 같은 작업
 - 기업 데이터 말뭉치를 검색하는 도구와 같은 에이전트 실행 환경
 - 답이 맞는지 평가하는 보상 함수
- 모델은 도구로 작업을 시도하고 보상 함수는 결과를 채점하며, 이 피드백 신호가 시행착오를 거쳐 성능을 높이는 방향으로 모델을 유도함
- 대부분의 기업에는 후처리에 바로 활용할 수 있도록 정제된 작업·보상 함수 데이터셋이 없음
- 대신 다음과 같은 대규모 독점 데이터를 보유함
 - 내부 문서
 - 제품 기록
 - 지원 문서
 - 고객 상호작용
 - 위키
 - 운영 데이터베이스
- 이러한 데이터에는 에이전트에 필요한 지식이 있지만, 효과적인 학습 데이터셋으로 바꾸려면 일반적으로 상당한 데이터 엔지니어링과 수작업 라벨링이 필요함
- 이 때문에 많은 팀이 학습 데이터나 파인튜닝 인프라가 부족하다는 이유로 후처리를 포기함
- Castform은 기존 말뭉치를 학습 작업으로 변환하고, 오픈 소스 모델이 해당 데이터를 효과적으로 사용하도록 강화학습 반복 과정을 관리함
질문·정답 생성과 보상 설계
- 기업 지식 베이스의 문서에서 정답과 질문을 합성할 수 있음
 - 원문 예시는 Navan으로 예약한 열차 비용을 GitLab 여행 카드로 결제하고, 일반 객실을 선택해 14일 전에 예약해야 한다는 규정임
 - 이 문서에서 “일반 객실과 14일 전 예약”이라는 정답을 추출함
 - 이어 예약 시점과 좌석 등급을 묻는 질문을 합성함
- 생성된 질문·답변 데이터셋과 함께 에이전트가 사용할 도구와 보상 함수를 지정해 학습 실행을 구성함
- 보상 함수는 모델이 강화할 능력을 결정함
 - 이 사례에서는 올바른 문서 조각을 검색하고 적절한 출처를 인용하며 정확한 최종 답변을 내는지 평가함
- 전체 구현은 Neon RAG 코드 예제에서 확인할 수 있음
강화학습 관측성과 디버깅
- Castform에서는 강화학습 실행 중 보상 변화를 단계별로 모니터링할 수 있음
- 개별 작업과 프롬프트를 살펴보며 모델의 정성적 수행 과정을 확인할 수 있음
 - 제대로 동작하지 않는 도구를 찾을 수 있음
 - 모델이 평가 기준의 허점을 이용하는 보상 해킹을 탐지할 수 있음
- 자세한 방법은 학습 실행 모니터링 안내와 학습 실행 예제에서 확인할 수 있음
급격한 검색 부하를 처리하는 Neon
- 학습 중 에이전트는 답변에 충분한 컨텍스트를 얻을 때까지 Lakebase Search를 반복 호출함
- 수천 개의 병렬 롤아웃이 각각 수십 번 검색할 수 있어 부하가 짧은 시간에 급증함
- Neon의 동적 컴퓨팅 확장은 Castform이 최대 용량을 상시 확보하지 않아도 이러한 정점을 흡수함
 - 수요가 급증할 때는 낮은 지연 시간으로 검색함
 - 유휴 시간에는 컴퓨팅 자원을 축소함
상태 변경 에이전트를 위한 격리 환경
- 에이전트가 검색을 넘어 데이터를 변경한다면, 각 롤아웃을 저렴하게 생성하고 초기화할 수 있는 격리 환경이 필요함
 - 한 롤아웃의 작업이 다른 롤아웃에 영향을 주면 안 됨
 - 학습 중인 에이전트가 프로덕션 데이터를 건드리지 않아야 함
- Neon branching은 롤아웃마다 격리된 데이터베이스 상태를 제공할 수 있음
- 시간 여행 쿼리를 사용하면 에이전트가 접했던 상태를 재구성하고 검사할 수 있음
- 브랜칭과 시간 여행 쿼리를 자동 확장 및 제로 스케일링(scale-to-zero) 과 결합하면, 수천 개 환경을 계속 실행하지 않고도 수천 개의 상태 유지형 에이전트 롤아웃을 훈련할 수 있음

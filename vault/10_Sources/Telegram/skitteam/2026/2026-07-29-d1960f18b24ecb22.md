Microsoft FY4Q26 컨퍼런스콜

▶️ 주요 코멘트

- Capex — FY4Q26 $41B(부품 가격 상승 영향 포함), 약 2/3가 단수명 자산(CPU·GPU): 
나머지는 장수명 자산. 분기 금융리스 $5.6B(대형 데이터센터 사이트 중심), PP&E 현금 지출 $35.8B. FY1Q27 Capex는 $50B 초과 전망(내구연수 변경에 따른 리스 재분류 영향 포함), FY27 연간 Capex는 포트폴리오 전반의 수요 시그널을 감안해 YoY 증가 전망

- Capex 회계 변경 — FY27부터 데이터센터·오피스 내구연수를 15년 → 25년으로 연장: 
향후 데이터센터 리스가 금융리스에서 운용리스로 이전(금융리스는 Capex에 포함, 운용리스는 미포함). 이에 따라 CY2026 Capex 기대치가 약 $175B로 조정 — 다만 내구연수 영향을 제외한 실질 투자 계획 자체는 불변. FY27 영업이익에 미치는 효과는 미미

- CAPA — 분기 중 5개 대륙에 데이터센터 31개 추가(연간 88개), 분기 1GW 추가: 
2년 내 전체 캐파 약 2배 목표 유지. 주요 Region의 신규 GPU 배포 리드타임을 지난 회계연도 대비 약 50% 단축. Maya 200은 기존 최신 세대 대비 성능/달러 30% 우위(OpenAI·MAI 모델 모두 지원), AMD Helios·NVIDIA Vera Rubin 기반 차세대 랙스케일 인프라를 최초 도입 클라우드 중 하나로 배포 예정. Cobalt 200 랙은 이달 말까지 25개 이상 데이터센터 배치

- FY4Q26 매출 $90B(+18% YoY, 고정환율 +17%) — 조정 EPS $4.74(+23%): 
GPM +15%, 영업이익 +18%, 회사 GPM 67%(Azure 믹스 이전·AI 인프라 투자·사용량 증가로 하락, 효율 개선이 일부 상쇄). 
OpEx +10%, OPM 45%로 소폭 상승. 
인원은 YoY -2%. 4/29 가이던스 대비 EPS $0.27 순증(Anthropic 투자이익 $3.2B + VRP 비용 하회, XBOX 퇴직·손상 일부 상쇄) — 해당 항목 조정 후에도 전 항목 기대 상회

- FY26 연간 
— 매출 $331B+(+18%), 영업이익 $155B+(+21%), Microsoft Cloud $214B+(+27%), Azure $100B+(+41%): 클라우드 매출의 약 90%가 프론티어 모델 기업 외 고객

- 수주 — 커머셜 RPO $678B(+84% YoY): 
QoQ 증가분은 전량 프론티어 모델 기업 외 고객에서 발생, OpenAI 제외 시 RPO +25%. 가중평균 듀레이션 2.3년, 약 30%를 향후 12개월 내 인식(+37% YoY), 12개월 이후 인식분은 +112%. 커머셜 부킹은 OpenAI 제외 +18%(포함 시 +10%)

- Azure +43% YoY — 수요가 가용 캐파를 계속 초과: 
예상 상회 배경은 CPU·GPU 플릿 효율 개선 + 신규 캐파 조기 인도 프로세스 개선(분기 내 추가 확보 캐파가 즉시 수익화). GitHub Copilot 소비도 6월 사용량 기반 과금 전환 후 예상 초과

핵심은 harness·컨텍스트·메모리·액션 스페이스를 특정 모델 계열과 분리하는 '모델 시스템'
비용-성과 곡선의 프론티어를 이동시키고 모델 대체 가능성으로 사업 연속성 확보
자사 모델 효율 성과로 GitHub Copilot 토큰 사용량 중위값 10% 절감, Dynamics 365 GPU 비용 89% 절감, PowerPoint 84% 절감, MAI Cyber One Flash는 대형 모델 대비 우수 성능에 절반 비용

▶️ 주요 Q&A

Q: 모델 선택권과 기업 IP 보호 — 오픈·커스텀 모델 확산이 얼마나 유의미하고 Microsoft는 어떻게 수혜하나?
A: 목표는 기업이 자기 운명(인적자본·토큰자본)을 통제하는 것 — 모델은 인풋이며 기업 지식의 추출 대상이 아님. 아키텍처 원칙은 harness를 모델과 분리해 메모리·컨텍스트를 외부화 → 어떤 모델이든 상시 교체 가능. 프론티어 모델을 쓸 이유는 충분하지만 복수 병용, 필요 시 자체 학습도 가능(모든 출력·트레이스·컨텍스트를 보유). 특정 모델의 거부(refusal)나 사고에 종속될 수 없다는 점이 핵심 — 어떤 모델을 택하든 Azure 인프라는 대체 가능(fungible) 구조로 수요 확보

Q: Azure 43% → mid-40% 가속의 동인 — 캐파 제약은 여전한가?
A: 제약은 여전 존재(스팟 시장 가격에서도 확인) — 수요가 가용 공급을 계속 초과. 가속 동인은 ① CPU·GPU 플릿 효율 개선, ② 설치·가동 리드타임 단축 등 프로세스 개선. 수급 불균형 상태에서는 효율 개선분이 분기 내 즉시 수익화 — 하이퍼스케일 규모에서 이 효과가 분기 성장률 가속으로 연결

Q: 데이터센터·칩 과잉공급 리스크 대응과 부품 가격 상승 대응은?
A: Capex가 단수명 자산(CPU·GPU, 상대적 단기 리드타임)으로 이동 — 수요 환경 변화 시 최대 비용 항목을 늦추면 됨. 
토지·데이터센터 건설은 전체 원가에서 비중이 작고 타이밍 조정이 유연. 

또한 지역·세그먼트·산업 전반의 광범위한 수주 기반과 대형 1P 앱 사업이 캐파를 흡수 — 유연성 확보. 가격 상승은 업계 공통 이슈로, 효율화로 고객 가치를 유지하고 신규 계약에 가격을 반영.

온프레미스 서버 직접 구매 대비 클라우드의 ROI 우위도 강조 (Satya) 제품 형태·포트폴리오·고객 믹스·효율 운영을 매일 개선하는 것이 관건 — 사이클 등락은 있으나 구조적 전환은 명확

Q: M365 Copilot의 파일럿 → 전사 배포 전환과 향후 수익화 동인은?
A: 제품 형태가 chat → Co-work → Autopilot → Code로 확장되며 플래그십 슈퍼앱으로 수렴. 라이선스 구매에서 사용까지 기간이 수개월 → 수일로 단축, 사용 강도는 Outlook·Teams 수준. Agent 365를 통해 IT Ops·SecOps·FinOps 거버넌스에 연결되고 CRM·ERP가 스킬·플러그인으로 편입 — 전사 워크플로우 연동이 사용량을 복리로 증대. 수익화는 E5+Copilot → E7(에이전트 관측·관리 가치) → 시트+소비 과금으로 TAM 확장

Q: 사이버 — 프론티어 모델 환경 변화와 Project Perception의 의미는?
A: 제품과 운영 방식 모두 근본적으로 변화. 레드팀 에이전트(취약점 탐지)·블루팀(트리아지)·그린팀(수정)으로 자체 에이전틱 방어 시스템 구성 — 디펜더·아이덴티티·네트워크·앱보안 신호를 컨텍스트로 활용. 멀티모델 접근이 특히 중요 — 작업의 90%를 MAI Cyber Flash One이, 10%만 프론티어가 처리해 mythos급 성능을 50% 낮은 비용으로 구현. 특정 모델이 사라져도 운영이 중단되지 않는 복원력도 핵심 기준

Q: Capex 대비 ROI를 1년 전과 비교하면? 남은 마진 레버는?
A: 계산 방식은 불변 — 달라진 것은 TAM 확장에 대한 확신과 마진 레버(제품·인프라 양쪽)의 가시성. 레버는 ① 실리콘 가격·성능 최적화(자사 1P 실리콘 투자 포함), ② 모델 다각화(토큰 효율·원가 구조 개선), ③ 지식근로·코딩·보안·에이전트 계층의 광범위한 포트폴리오, ④ 하이퍼스케일 운영 효율. 매일 조금씩 개선하는 'grind' 작업이며 그것이 강점

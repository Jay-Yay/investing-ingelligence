### 최신 ESP32, Linux를 실행하며 Raspberry Pi에 가까워지고 있음 | GeekNews

(https://news.hada.io/topic?id=34234)

- 센서와 기기를 제어하는 데 쓰이는 ESP32 마이크로컨트롤러가 Linux와 다양한 주변장치를 지원하면서, 소형 컴퓨터로 활용할 수 있는 범위를 넓히고 있음
- Espressif의 ESP32-S31은 기가비트 Ethernet, USB 호스트, 카메라와 디스플레이 인터페이스를 갖춰 화면과 키보드, 유선 네트워크를 연결할 수 있음
- 단순히 외부 메모리를 연결하던 기존 구조와 달리 가상 메모리와 프로세스 격리를 지원하는 MMU를 도입해, 일반적인 RISC-V Linux를 실행할 하드웨어 기반을 갖춤
- Wi-Fi 6, Bluetooth 5.4, Thread/Zigbee를 함께 지원하면서 마이크로컨트롤러 수준의 소비 전력을 유지함
- 공식 Linux 지원 패키지와 커뮤니티 포트가 나왔지만 아직 실험 단계이며, 최대 64MB 메모리와 GPU 부재로 본격적인 데스크톱보다는 Linux 터미널을 구동하는 수준임
SBC에 가까워진 주변장치 구성
- ESP32-S31은 소수의 코어, 적은 RAM, GPIO와 선택적인 Wi-Fi가 중심이던 일반적인 마이크로컨트롤러보다 훨씬 다양한 주변장치를 지원함
- 1000Mbps Ethernet MAC은 ESP32-P4의 100Mbps보다 크게 향상됨
  - 흔히 RJ45로 부르는 8P8C 커넥터를 사용하며, 칩의 RGMII 인터페이스를 통해 외부 PHY에 연결함
  - 일반 RMII가 아닌 RGMII가 기가비트 연결을 가능하게 함
- 공식 개발 보드는 USB 2.0 High-Speed OTG 컨트롤러와 풀사이즈 Type-A 소켓을 갖추며, 호스트 OTG 모드에서 500mA를 공급할 수 있음
- 카메라, 화면, 오디오와 제어용 인터페이스도 폭넓게 갖춤
  - SDIO 호스트 컨트롤러는 슬롯 2개를 지원하며, DVP 카메라 인터페이스는 8~16비트를 처리함
  - 병렬 LCD 컨트롤러는 최대 24비트 RGB, I8080, MOTO6800 패널을 지원함
  - 하드웨어 Bluetooth 오디오 동기화를 지원하는 I2S 컨트롤러 2개, 정전식 터치 채널 14개, CAN FD 컨트롤러, MCPWM 유닛 4개를 제공함
CPU와 메모리 인터페이스의 변화
- 최대 320MHz의 32비트 RISC-V 코어 2개에 각각 부동소수점 연산 장치를 갖추며, 한 코어에는 128비트 SIMD 데이터 경로가 있음
  - 별도의 40MHz 저전력 코어도 탑재함
  - 각 코어는 32KB L1 명령어 캐시를 갖고, 64KB 데이터 캐시를 공유함
- 250MHz 8비트 DDR 인터페이스로 최대 64MB PSRAM을 지원하며, 플래시는 최대 256MB까지 지원함
  - ESP32-S3는 PSRAM과 플래시가 인터페이스를 공유했으므로, S31의 메모리 인터페이스는 큰 변화임
실제 페이지 변환을 지원하는 MMU와 Linux
- ESP32-S3와 ESP32-P4의 MMU는 외부 플래시와 PSRAM을 주소 공간에 매핑하는 블록으로, 프로세스 격리와 페이지 테이블을 다루는 현대적인 MMU와는 달랐음
- S31 데이터시트는 Sv32 2단계 페이지 테이블 주소 변환과 Machine, Supervisor, User 권한 모드를 명시함
  - Sv32는 RISC-V의 페이징 체계이며, 세 권한 모드를 통해 펌웨어는 Machine 모드에서, 일반 커널은 Supervisor 모드에서 실행할 수 있음
  - 과거 ESP32에서 Linux를 실행하려던 우회적인 시도와 달리, S31은 기본 하드웨어 차원에서 더 많은 실행 기반을 갖춤
- Espressif는 8월에 Linux BSP 를 공개함
  - Buildroot와 U-Boot를 기반으로 커널, 디바이스 트리, 루트 파일 시스템을 포함함
  - 실제로 작동하지만 프로덕션 사용은 아직 권장하지 않음
- 커뮤니티에서도 Linux 포트를 개발하고 있음
  - Linux 6.18 포트 는 Supervisor 모드에서 실행되며, 사실상 대부분의 하드웨어에서 작동하는 드라이버를 갖춤
  - Linux 7.1 기반 포트 는 800×480 LCD 패널에 콘솔을 표시할 수 있음
  - 디스플레이, 유선 Ethernet, 마우스와 키보드를 연결하는 사용 방식은 마이크로컨트롤러보다 SBC에 가까움
메모리, 그래픽과 네트워크 처리량의 한계
- 온칩 SRAM은 512KB이며, 패키지 내 PSRAM이 16MB 또는 32MB인 두 가지 모델이 있음
  - 지원 가능한 최대 메모리는 64MB이고 DRAM 컨트롤러는 없음
  - 512MB RAM을 갖춘 Milk-V Duo S 같은 경쟁 제품과 비교하면 여전히 마이크로컨트롤러의 제약이 뚜렷함
- Linux 빌드는 부족한 PSRAM을 아끼기 위해 커널을 플래시에서 실행함
- GPU와 NPU가 없으며, ESP32-P4의 비디오 인코딩과 MIPI 인터페이스 대신 추가 무선 기능을 갖춤
  - JPEG 코덱, 2D 픽셀 처리 가속기, 2D DMA는 있지만 본격적인 Linux 데스크톱을 구동하기에는 부족함
- 320MHz CPU가 기가비트 Ethernet을 충분히 처리할 수 있을지는 패킷 크기에 따라 달라질 수 있음
  - 최대 크기 Ethernet 프레임당 약 3,900 CPU 사이클, 최소 크기 프레임당 약 215사이클이 주어짐
  - PSRAM의 이론상 최대 대역폭은 500MB/s여서 대용량 전송에서는 기가비트 속도에 가까워질 가능성이 있음
  - 다수의 작은 패킷 전송으로 회선 대역폭을 모두 활용할 수 있을지는 불확실함
무선 기능과 마이크로컨트롤러 수준의 소비 전력
- 비슷한 가격대의 SBC가 온보드 무선 기능을 생략하는 것과 달리, S31은 2.4GHz Wi-Fi 6와 여러 무선 규격을 함께 지원함
  - Bluetooth 5.4는 LE와 Classic BR/EDR을 모두 지원하며, Classic 지원으로 구형 오디오 기기도 사용할 수 있음
  - 802.15.4 무선 기능으로 Thread와 Zigbee를 지원하고, Matter는 Wi-Fi와 Thread 위에서 작동함
- SBC에 가까운 주변장치를 갖추면서도 소비 전력 특성은 마이크로컨트롤러 수준을 유지함
  - Wi-Fi 수신 전류는 모드에 따라 110~117mA임
  - 802.11b에서 15dBm으로 송신할 때 최대 265mA를 소비함
  - 두 코어가 320MHz로 동작하는 모뎀 절전(modem-sleep) 상태에서는 주변장치 클록을 끄면 91mA, 켜면 147mA를 소비함
혼동을 주는 이름과 아직 초기인 제품 상태
- S31이라는 이름은 S3의 개정판처럼 보이지만, 실제 구조는 기존 S3와 크게 다름
  - Espressif는 S 시리즈를 명령어 집합과 무관한 “고성능, 풍부한 기능의 SoC”로 정의함
  - 기존에는 C 시리즈의 RISC-V와 S 시리즈의 Xtensa LX7이 두 제품군을 구분하는 큰 차이였음
- Espressif 기술 마케팅 매니저 Jeroen Domburg는 Hackaday 댓글 에서 CPU 아키텍처를 제품 이름에 반영할 의도는 없었다고 밝힘
  - S31 코어는 P4에서 파생됐으며, 속도는 S3의 거의 두 배라고 밝힘
- 데이터시트는 여전히 버전 0.5이고 첫 페이지에 PRELIMINARY 표시가 있는 초기 문서임
  - 상세하고 대체로 일관되지만, PSRAM 최대 클록을 80MHz로 기재해 Espressif가 공개한 250MHz와 충돌함
  - 문서와 Linux 지원 모두 제품 수명주기의 초기 단계에 있으며, Linux는 당분간 실험용에 가까움
Raspberry Pi 대체 가능성은 미래 칩의 과제
- S31은 SBC가 아니지만, 주변장치, 대역폭, CPU 권한 모델이 현대적인 SBC에 가까워진 첫 ESP32임
- 16MB PSRAM에서 데스크톱을 실행할 수는 없어도, 큰 어려움 없이 Linux 터미널을 구동할 수 있음
- 마이크로컨트롤러와 SBC의 간격은 최근 몇 년간 좁아지고 있으며, 이번 변화는 장기적으로 미래 ESP32 칩이 Raspberry Pi의 SBC 대안이 될 가능성을 여는 첫 단계가 될 수 있음

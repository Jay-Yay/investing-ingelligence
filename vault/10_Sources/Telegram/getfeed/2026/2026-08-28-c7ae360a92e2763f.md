### CEO가 AI를 위해 개발팀을 해고하자, 개발자들은 오픈소스 AI CEO를 만들었다 | GeekNews

(https://news.hada.io/topic?id=32939)

- AI 도입 과정에서 해고된 개발팀이 스타트업을 시작하고, “AI가 개발을 바꾼다면 경영도 바꿀 수 있다” 며 Open Executive를 오픈소스로 공개함
- 실제로 한 명의 CEO를 구현한 것은 아니며, 전략·재무·인사·법무·운영·마케팅·제품·이사회 업무를 나눠 맡는 8개 전문 AI 에이전트로 구성된 가상 경영진임
- 사용자는 내부 에이전트들과 각각 대화하지 않고, 오케스트레이터가 필요한 전문가를 호출해 합친 하나의 일관된 경영진 답변을 받음
- 기업 프로필과 업로드한 문서를 참고하고 과거 결정과 추진 과제를 기억하며, 단순 질의응답을 넘어 후속 조치와 시한이 있는 업무를 다시 알려줌
- Claude를 기본으로 OpenRouter와 로컬 모델도 지원하지만, 실제 CEO의 법적 책임이나 인간관계를 대신하는 시스템보다는 경영 조언과 실행 관리를 위한 초기 오픈소스 도구에 가까움
개발자를 AI로 대체하려다 AI 경영진이 나오다
- 프로젝트 팀은 Hacker News 댓글에서 AI를 위한 자리를 만들려는 과정에서 팀 전체가 해고됐다고 밝힘
- 해고된 뒤 스타트업을 시작했고, Copilot 과Claude Code 가 개발 업무를 바꾸는 것을 보며 개발뿐 아니라 경영진 전체를 AI로 바꿔보자는 방향을 잡음
- CEO 한 명을 풍자적으로 대체하는 데 그치지 않고, 전략·재무·인사·법무·운영·마케팅·제품·이사회 커뮤니케이션을 함께 다루는 시스템으로 구현함
- 오픈소스로 공개한 뒤 실제로 필요로 하는 조직에 구축과 지원을 제공하는 Red Hat과 비슷한 사업 모델을 기대하고 있음
여덟 명이 일하지만 한 명처럼 답하는 경영진
- Open Executive는 기업별 상황에 맞춘 고위 경영 조언자를 표방하며, 내부에는 다음 8개 전문 에이전트가 있음
  - 전략, 재무, 인사, 법무, 운영, 마케팅, 제품, 이사회 커뮤니케이션
- 사용자의 질문은 먼저 Executive Orchestrator가 받고, 필요한 전문 에이전트들을 골라 병렬로 호출함
- 각 에이전트가 자신의 영역에서 분석한 결과를 오케스트레이터가 하나의 답변으로 합침
- 사용자에게는 내부 회의나 에이전트 구성이 드러나지 않고 하나의 경영진 페르소나만 보임
- “현금 흐름을 고려해 채용 계획을 다시 세워달라”처럼 여러 경영 영역이 얽힌 질문을 한 대화 안에서 다루기 위한 구조임
회사 사정을 아는 조언자
- 첫 실행 시 온보딩을 통해 회사명·산업·성장 단계·팀 규모·사업 모델·매출·경쟁 구도·전략적 우선순위·문화 등을 입력함
- 피치덱, 재무 모델, 전략 문서 같은 회사 자료도 업로드할 수 있음
- 각 전문 에이전트는 질문과 관련된 정보를 두 곳에서 검색함
  - 프로젝트가 “MBA 수준”이라고 표현하는 내장 경영 지식
  - ChromaDB에 저장된 사용자의 회사 문서
- 검색한 문맥과 기업 프로필을 함께 사용해 일반적인 경영 상식이 아니라 해당 회사의 상황을 반영한 답변을 만들도록 설계됨
- 법률 관련 기능도 제공하지만 계약·지식재산권·고용법·규제 준수의 기초적인 조언 범위이며 전문 법률 서비스를 대신한다고 명시하지는 않음
지난 결정을 기억하고 다시 챙기기
- 매 응답이 끝나면 별도의 모델이 주요 결정, 추진 과제와 조언을 추출해 SQLite에 저장함
- 다음 대화에서는 과거 결정 기록을 불러와 “지난달에 권고했던 계획”을 이어서 다룰 수 있음
- 내장 스케줄러는 후속 조치나 시한이 있는 업무를 저장했다가 예정된 시점에 다시 노출함
- 단발성 질문에 답하는 챗봇보다 조직의 결정과 실행 흐름을 계속 따라가는 경영 보조 시스템을 지향함
- 다만 현재 스케줄러는 여러 API 인스턴스에서 같은 작업이 중복 실행될 수 있어, 별도 제어 장치를 추가하기 전에는 API를 단일 인스턴스로 운영해야 함
Claude와 로컬 모델을 함께 사용
- 기본 구성은 오케스트레이터와 대부분의 전문 에이전트에 claude-sonnet-4-6 을 사용함
- 전략·재무·법무·이사회처럼 더 깊은 추론이 필요한 영역에는 claude-opus-4-7 을 배치함
- OpenRouter 또는 OpenAI 호환 로컬 서버를 통해 Ollama·LM Studio·vLLM·llama.cpp 모델도 사용할 수 있음
- 에이전트별로 모델을 따로 선택할 수 있어, 경영진 응답은 Claude로 유지하고 일부 전문 업무만 로컬 모델에 맡기는 혼합 구성이 가능함
- 로컬 모델에서는 Anthropic의 웹 검색·프롬프트 캐시·extended thinking을 사용할 수 없으며, 도구 호출이 약한 소형 모델은 전문 에이전트 라우팅 품질이 떨어질 수 있음
이용 방식과 데이터
- Web UI와 CLI 외에도 Slack·이메일·Telegram·Google Chat·Discord에서 대화할 수 있음
- 백엔드는 Python 3.11·FastAPI, 웹 UI는 Next.js 15, 문서 검색은 ChromaDB, 과거 결정 기억은 SQLite로 구성됨
- 회사 프로필과 업로드 문서, 벡터 저장소는 Git 추적에서 제외되고 로컬 머신이나 자체 Fly.io 볼륨에 저장됨
- Anthropic API를 사용할 때 관련 문서 내용이 프롬프트의 일부로 전송될 수 있으므로 완전한 로컬 처리가 필요하면 로컬 모델 구성이 필요함
- make dev 로 실행할 수 있으며 첫 실행에는 Python 3.11 이상, Node.js 22 이상과 약 90MB의 임베딩 모델 다운로드가 필요함
평가와 현재 제약
- 8개 경영 영역을 다루는 29개 평가 시나리오로 페르소나 일관성, 영역 정확성, 기업 문맥 활용, 라우팅과 실행 가능성을 검사함
- 평균 3.5/5 미만이거나 기존 버전보다 한 평가 항목이 10% 넘게 하락하면 CI를 통과하지 못하도록 구성됨
- 경영 정보를 바탕으로 조언하고 업무를 추적하는 시스템이지, 법적 책임을 지거나 투자자·고객·직원과 인간관계를 형성하는 실제 경영자를 그대로 대체하는 제품은 아님
- Apache-2.0 라이선스

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.

마케팅의 변화: 캠페인 제작에서 시스템 구축으로
- 1950~1990년대에는 인쇄물, TV, 라디오, 옥외광고가 중심이었음. 캠페인에 수백만 달러와 수개월이 들고 결과 확인도 다음 분기에나 가능해, 연간 몇 번의 기회를 안목과 설득력, 직감에 걸어야 했음
- Google AdWords의 2000년 출시와 Facebook 광고의 2007년 출시 이후 클릭 단위 측정이 가능해짐. SEO, 검색광고, 이메일, 디스플레이 등 채널과 대시보드를 관리하는 디지털 마케터가 등장했고, 한 달에 몇 차례 실험할 수 있었음
- Sean Ellis가 2010년 이름 붙인 그로스 해커는 마케팅을 퍼널, 성장 루프, A/B 테스트를 갖춘 제품처럼 다룸
  - Hotmail의 이메일 하단 무료 가입 문구, Dropbox의 추천인과 친구 대상 무료 저장공간, Airbnb의 Craigslist 교차 게시가 대표 사례임
  - 다만 좋은 아이디어마다 제품 로드맵에 묶인 엔지니어가 필요해, 티켓을 쓰고 기다리는 시간이 길었으며 주 몇 차례 실험이면 좋은 성과였음
- 2022년 말 ChatGPT가 등장하면서 문구와 이미지 제작은 빨라졌지만, 조직도와 회의, 6주짜리 작업 주기는 그대로인 AI 보조 마케팅이 확산됨. 많은 팀이 여전히 이 단계에 머물러 있음
- 마케팅 엔지니어는 마케터이자 제작자이며, 창업자, 엔지니어, 운영 담당자, 1인 제작자 출신도 강점을 가질 수 있음
  - 작업 단위가 개별 캠페인에서 캠페인을 계속 생산하는 시스템으로 바뀜
  - 전체 변화의 공통점은 실험 비용 하락이며, 좋은 실험을 많이 할수록 더 빨리 학습할 수 있음

- 영업은 반복되는 구매 반대를, 지원팀은 환불로 이어지는 약속을, 분석팀은 오래 남는 고객을 유입시키는 페이지를 알고 있음. 창업자의 독자적인 견해까지 서로 다른 도구와 사람에게 흩어져 있어 캠페인에는 드물게 반영됨

  - 기능 출시, 계약 갱신 시점, 담당자의 이직을 감지해 과거 대화를 인용한 개인화 초안을 작성함

6단계: 안전장치는 프롬프트가 아니라 도구에 구현
- “보내기 전에 항상 물어봐”라는 문장만 믿지 말고, 최소 권한과 코드 수준 승인을 적용함

  - 광고는 일시중지 상태로 만들고 예산 권한은 사람이 유지함

  - 조회 실패를 조용히 건너뛰는 대신 어떤 출처가 작동하지 않았는지 알려야 함
7단계: 회계 서비스 캠페인 전체 실행 예시
- 전자상거래 고객을 늘리려는 회계 회사가 “반품, 배송비, 수수료를 빼면 실제로 돈을 벌었는지 모르겠다”는 말을 지난달 고객 11명에게서 발견한 상황을 가정함

  - 광고는 수익이 사라지는 지점, 월간 보고서 예시, 실제 고객 이야기의 세 방향으로 제작함

- 고객의 원래 표현을 캠페인 폴더에 유지해, 여러 요약과 수정 과정에서 일반적인 광고 문구로 희석되지 않게 함
8단계: 주간 검토와 피드백 순환
- 시스템 구축 뒤의 업무는 제작보다 편집과 개선에 가까워짐
  - 월요일에는 성과 메모를 읽고 유지, 중단, 수정을 결정함
  - 화요일과 수요일에는 새 실험을 만들고 지난주 품질이 낮았던 작업 흐름을 고침

  - 금요일에는 결과물을 검토하고 맥락 파일을 갱신함
- 검토 대기열의 각 항목은 1분 이내에 판단할 수 있게 구성함. 변경 내용, 영향을 받는 광고나 이메일, 근거를 함께 보여줘야 함
- 거절 이유를 다음 실행의 입력에 반영함
  - 너무 작은 기업을 끌어오는 광고였다면 customer-fit.md 를 수정함
  - 제안을 오해한 고객이 있었다면 점검 항목을 추가함
  - 실험 기록에는 무엇을, 왜 시험했고, 결과와 다음 행동이 무엇인지 남김

- 에이전트마다 예시 입력 10개와 기대 출력을 보관하고 지시를 바꿀 때마다 재실행해 품질 저하를 확인함

광고 소재 엔진: 비슷한 변형보다 다른 아이디어
- Meta의 Andromeda는 2025년 말 전 세계 적용을 마쳤으며, 광고 자체를 읽어 누구에게 보여줄지 판단함. 이미지, 첫 관심 유도 문구, 대본이 과거 관심사 타기팅의 역할을 맡음
- 비슷하게 보이는 광고를 묶어 하나처럼 취급하므로, 같은 제목의 변형 50개로는 서로 다른 광고 50개의 도달 효과를 얻기 어려움. 성과가 좋은 광고의 소진 주기도 기존 6주에서 2~3주로 짧아짐
- voice.md 와 최신 고객 언어 보고서를 Claude나 GPT에 입력해 8~12개의 서로 다른 콘셉트와 콘셉트당 2~3개의 도입 문구를 만듦
  - 문제 상황, 구체적인 사례, 고객 이야기, 창업자의 강한 견해, 비교, 통념 반박 등으로 구분함
  - 전략은 이 단계에 있으므로 사람의 시간을 집중해야 함
- 이미 작동하는 퍼널에서 출발할 수도 있음. Boring Funnels는 매주 실제 퍼널을 광고부터 마지막 이메일까지 분석하고 각 단계를 코딩 에이전트용 프롬프트로 바꾸는 서비스임
- 이미지 제작에는 Nano Banana, GPT Image, Midjourney를 사용하되 실제 제품 사진을 입력해 제품은 정확히 유지하고 주변 장면을 바꿈
- 영상은 Veo, Kling, fal, 다국어 AI 출연자는 Arcads, HeyGen, Creatify, 음성은 ElevenLabs, 편집은 CapCut이나 Captions를 활용함
- AI 출연자로 검증하고 실제 사람으로 확장하는 방식을 권장함
  - 크리에이터 영상 한 편 비용으로 하루에 대본 20개를 시험할 수 있음
  - 성과가 좋은 대본을 실제 사람이 전달하면 일반적으로 성과와 신뢰가 더 좋아지며, AI 콘텐츠 표시를 요구하는 플랫폼에도 유의해야 함
- 에이전트가 일시중지 상태로 올리고 사람이 실행하며, 코드가 탈락 광고를 중단하고 성과 에이전트가 다음 실험을 추천함. 사람은 아이디어와 안목에 집중함
자연 유입 소셜 엔진
- 자연 유입 콘텐츠를 광고의 시험장으로 사용함. TikTok, Reels, X에서 도입 문구 10개를 시험한 뒤 반응이 좋은 아이디어에만 광고비를 배정함

- 얼굴이 필요 없는 슬라이드쇼와 캐러셀도 활용함. 고객 언어 보고서에서 슬라이드와 이미지를 생성하고 사람이 주말에 일괄 승인하는 방식임
- Reddit, X, TikTok 댓글, 경쟁사 리뷰에서 불만과 요구, 관심사를 먼저 수집함
  - 제품이 실제 도움이 되는 대화에는 유용한 답변 초안을 만들되 사람이 직접 게시함
  - 특히 Reddit에서는 스팸성 답변이 계정 차단으로 이어질 수 있음
- founder-opinions.md 에서 매일 게시물 초안을 만들고 창업자가 자신의 말투로 편집함. 누구나 콘텐츠를 생성할 수 있을수록 실제 사람의 독자적인 견해가 희소해짐
- 플랫폼이 요구하는 경우 AI로 만든 인물과 장면을 표시하고, 최종 게시 권한은 사람이 유지함
상위 수준의 마케팅 엔지니어가 집중할 네 가지
- 구매 의사결정 도구를 만듦. 배송비를 줄이는 상자 크기 계산기나 이전 가능한 설정을 확인하는 소프트웨어 마이그레이션 점검기처럼, 구매자가 저장해두고 다시 찾는 도구를 일주일 안에 거친 초기 버전으로 구현함
- 구매에 영향을 주는 사람을 별도로 공략함. 여러 고객에게 소프트웨어를 추천하는 회계사, 도구를 고르는 대행사, 보안을 검토하는 IT 담당자에게 필요한 자료를 제공함
- 온보딩 내부의 고객 확보 문제를 고침. 광고보다 첫 주의 혼란이 이탈 원인이라면, 지원 티켓에서 막히는 지점을 찾는 에이전트가 더 큰 성장 효과를 낼 수 있음
- 채널마다 역할을 구분함. 검색은 질문에 답하고, 소셜은 대화를 시작하며, 이메일은 특정 순간에 도착해야 함. 모든 채널에서 같은 말을 반복하면 같은 노출에 여러 번 비용을 쓰게 됨
역할별 도구 구성
- 도구 이름은 몇 달마다 바뀌므로 제품명보다 역할별 범주를 익히고 교체할 수 있어야 함
- 에이전트 실행과 생성 작업에는 다음 도구를 활용할 수 있음
  - 작업 공간: Claude Code, Codex, Cursor, Google AI Studio를 사용함
  - 상시 에이전트: Hermes, GrokBot, Codex를 활용함
  - 글쓰기와 전략: Claude, ChatGPT, Gemini를 사용함
  - 이미지: Nano Banana, GPT Image, Midjourney를 사용함
  - 영상: Veo, Sora, Kling, Runway, Fal을 활용함
  - AI 출연자와 UGC: Arcads, HeyGen, Creatify를 사용함
  - 음성은 ElevenLabs, 편집과 클립 제작은 CapCut, Captions, Opus Clip, 퍼널은 Boring Funnels를 활용함
- 고객 데이터와 배포, 측정에는 다음 도구를 활용할 수 있음
  - 고객 목소리: Gong, Fathom, Intercom, Zendesk, G2에서 수집함
  - CRM은 HubSpot/Salesforce, 구매 신호와 정보 보강은 Clay/Apollo를 사용함
  - 검색과 AI 노출은 Ahrefs, Semrush, Google Search Console로 확인함
  - 광고는 Meta Ads API와 Google Ads API, 이메일과 외부 연락은 Customer.io, Resend, Instantly를 활용함
  - 웹은 Vercel에 배포한 Next.js, Framer, Webflow를 사용함
  - 측정은 PostHog, Stripe, Supabase로 구성함
배워야 할 역량과 시작 순서
- 마케팅 역량으로는 고객 인터뷰, 포지셔닝, 할인과 구별되는 구매 제안, 관심을 붙잡는 제목, 채널별 노출 방식, 우연과 실제 성과를 구분할 통계 지식이 필요함
- 구현 역량으로는 에이전트가 쓸 수 있는 맥락 작성, 코드가 요청대로 동작하는지 읽고 판단하는 능력, API와 MCP, 기본 SQL, 페이지 배포, git, 테스트 작성, 실행 비용 파악이 필요함
  - 코드는 에이전트가 작성해도 책임은 운영자에게 있음
  - 주말에 AI 코딩 도구로 미완성에 가까운 랜딩 페이지라도 직접 배포하는 방식으로 시작함
- 역할별 첫 작업을 작게 잡음
  - 마케터는 최근 영업 통화 20건으로 고객 언어 에이전트를 만듦
  - 엔지니어는 영업 통화 5건에 참여한 뒤 특정 고객군용 계산기를 만듦
  - 창업자는 2시간을 확보해 founder-opinions.md 를 작성함
- 게시, 연락, 지출은 신뢰를 확보할 때까지 승인 후에만 실행하고, 한 작업 흐름을 안정화한 뒤 다음 것을 추가함
- 2028년에는 마케팅 엔지니어 1~2명이 수십 개의 에이전트를 운영하며 10배 규모 부서보다 더 많이 실행할 수 있을 것으로 예상함. 확정된 결과는 아니며, 고객 이해와 실행 속도가 조직 규모보다 중요해질 것이라는 예상에 바탕을 둠
- 관련 심화 자료로 마케팅 엔지니어를 다룬 Startup Ideas Podcast 에피소드가 있음

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.

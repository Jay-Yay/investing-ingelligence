### Meta가 AI 인프라의 매출 기여도를 측정한 방법 | GeekNews

(https://news.hada.io/topic?id=33720)

- 광고 모델을 개선해 매출이 늘어도 그 모델을 만든 인프라가 얼마나 기여했는지는 알기 어려움. Meta는 개별 모델 출시 데이터를 분석해 7개 인프라 플랫폼의 기여도를 추정함
- 모델 개선 효과는 A/B 테스트로 측정할 수 있지만, 여러 팀이 공유하는 인프라는 사용 여부를 무작위로 나누기 어려워 비슷한 조건의 사용/미사용 사례를 비교함
- GPU 자원, 팀 규모와 경력, 모델 복잡도, 출시 시점을 고려하자 많이 쓰이던 플랫폼보다 소수 팀이 쓰던 학습 확장성 플랫폼의 출시당 추가 매출 기여가 약 2배로 추정됨
- 도입률이 낮은 플랫폼의 전체 추가 매출도 더 높게 나타나면서, 사용량 중심의 평가를 바꾸고 다음 투자 배분을 조정함
- 다만 관찰 데이터 분석이므로 성과에 영향을 주는 다른 요인을 충분히 고려했다는 가정이 필요하며, A/B 테스트보다 추정의 불확실성이 크다는 점도 받아들여야 함
광고 ML 인프라의 매출 기여를 분리하는 문제
- 대규모 광고 시스템의 ML 모델은 실시간으로 노출할 광고, 입찰 금액, 후보 순위를 예측하며, 예측 품질이 플랫폼 매출에 직접 영향을 줌
  - 개선된 모델을 출시했을 때의 매출 효과는 A/B 테스트로 측정할 수 있음
- 모델 뒤의 ML 인프라는 직접 매출을 발생시키기보다 엔지니어가 매출을 높이는 모델 개선을 가능하게 하거나, 더 빠르고 저렴하게 수행하도록 지원함
  - 학습 플랫폼은 모델 아키텍처 반복 개선을 가속함
  - 서빙 시스템은 지연 시간을 줄이고 처리량을 높여 모델을 운영 환경에 배포함
  - 특성 엔지니어링 파이프라인은 더 풍부한 신호를 공급함
  - 실험 프레임워크는 테스트부터 출시까지의 주기를 단축함
- 인프라 팀의 목표는 기반 도구를 개선해 후속 모델 개선의 속도와 규모를 극대화하는 것이지만, 발생한 매출 중 인프라와 직접적인 ML 엔지니어링 작업의 몫을 구분하기 어려움
- 주요 기술 기업은 AI 인프라에 수십억 달러를 투자하고 있지만, 가동 시간이나 처리량과 달리 사업 효과는 명확히 측정하지 못하는 경우가 많음
  - 새 서빙 플랫폼에 엔지니어 1명분의 연간 작업량을 투입했을 때 추가 매출이 얼마인지가 핵심 질문임
A/B 테스트 대신 관찰 데이터로 식별하기
- 인프라는 수십 개 팀이 공유하고, 가치가 다른 팀의 작업을 거쳐 발생하므로 효과를 특정 지점에 국한하기 어려움
  - 모델 출시나 엔지니어를 플랫폼 사용자와 비사용자로 무작위 배정하는 일은 기술적으로 불가능하거나 비용이 지나치게 크며, 거의 항상 실무적으로 매우 어려움
- 분석 단위는 운영 환경에 반영된 개별 ML 개선인 모델 출시 제안이며, 각 출시에는 측정 가능한 매출 결과가 있음
  - 처치 변수는 해당 출시가 특정 인프라 기능을 사용했는지 여부임
  - Adoptedᵢ 는 도입 여부,Xᵢ 는 교란 변수 벡터이며,β₁ 은 도입한 출시들에 대한 평균 처치 효과, 즉 도입에 인과적으로 귀속되는 추가 매출임
- 식별은 관측 변수에 따른 선택(selection-on-observables) 가정에 의존함
  - 충분히 풍부한 공변량을 조건으로 두면, 인프라 도입 여부가 매출 결과에 대해 사실상 무작위여야 함
- 학습 데이터 파이프라인부터 모델 운영 환경 배포까지 7개 인프라 플랫폼을 같은 기준으로 평가해, 이전에는 비교하기 어려웠던 투자들을 비교함
인과 추정에 필요한 네 가지 교란 요인 통제
- 컴퓨팅 용량을 통제함
  - GPU 할당량이 큰 팀은 매출 기여가 더 높은 모델을 출시함
  - 자원이 풍부한 팀의 플랫폼 도입률도 높다면, 용량을 제외한 추정치는 상향 편향됨
- 인적 자본 투자를 통제함
  - 팀 규모와 구성원의 경력 수준은 도입 성향 및 출시 품질 모두와 상관관계가 있음
  - 인원수 통제로 인프라 효과와 인적 자본 효과를 분리함
- 모델 개발 및 출시 주기의 계절성을 통제함
  - 매출은 계획과 출시 일정에 따른 주기성을 보이므로, 시간 통제가 없으면 계절적 매출 상승을 우연히 겹친 플랫폼 도입 효과로 오인할 수 있음
- 모델 크기와 복잡도를 통제함
  - 대형 모델은 불균형적으로 큰 매출을 창출함
  - 대형 모델을 학습하는 팀이 플랫폼을 더 많이 도입한다면, 모델 크기를 제외할 경우 처치 효과가 교란됨
도입률 순위가 뒤집힌 두 플랫폼 비교
- 운영 모델 기반 계층은 운영 중인 거의 모든 모델이 사용해, 단순 사용량 기준으로 포트폴리오에서 가장 가치 있는 기능 중 하나처럼 보였음
  - 반면 학습 확장성 플랫폼은 가장 큰 모델을 개발하는 소수 팀이 사용해 도입률로는 두드러지지 않았음
- 컴퓨팅 할당량, 팀 규모와 경력 수준, 모델 복잡도, 출시 시점을 통제하고 도입 가능했지만 사용하지 않은 출시만 비교군에 넣자 순위가 역전됨
  - 기반 계층은 도입 출시당 추가 매출 기여가 작았음
  - 학습 확장성 플랫폼의 도입 출시당 기여는 약 2배였으며, 도입률이 훨씬 낮은데도 전체 추가 매출이 더 컸음
- 기반 계층의 겉보기 가치는 대부분 선택 효과에서 비롯됐음
  - 역량이 뛰어난 팀은 해당 계층의 사용 여부와 관계없이 성과가 좋은 모델을 출시했을 것으로 추정됨
- 이 비교는 다음 계획 주기의 추가 투자 배분을 바꿈
  - 선택 효과가 주된 기능에서 인과적 기여를 확인한 기능으로 후속 투자를 돌림
추정의 안정성과 비교군 검증
- 표본 확대와 기간별 안정성을 확인함
  - 초기 추정은 한 반기의 제안 약 258건에 기반했음
  - 연속된 두 반기로 갱신하면서 표본이 두 배로 늘고 정밀도가 개선됐으며, 추정 기간이 달라져도 β₁ 이 안정적으로 유지돼 인과적 해석을 강화함
- 반사실적 비교군의 적합성을 플랫폼 엔지니어링 책임자들과 검토함
  - 기술적으로 플랫폼을 사용할 수 없었던 제안은 비교군에서 제외함
  - 도입 가능했던 미사용 제안만 비교해 기술적 적용 가능성과 관련된 비관측 선택 요인의 편향을 줄임
  - 이는 치료 대상 질환을 진단받은 환자만 모집해 치료군과 위약군으로 나누고, 해당 질환이 없는 사람은 제외하는 실험 설계에 비유할 수 있음
- 플랫폼 간 중복 사용으로 인한 매출 이중 계산을 세 가지 방식으로 처리함
  - 매칭으로 처치군과 비교군의 다른 플랫폼 사용을 균형 있게 맞춤
  - 단일 플랫폼만 도입한 출시로 표본을 제한함
  - 통합 추정치에서 함께 도입한 플랫폼의 기여를 차감함
- 서로 다른 측정 방법의 결과를 교차 검증함
  - 매개 지표 기반 방법이나 관련 프로그램의 독립적인 인과 추정치가 있으면 결과를 비교함
  - 방법론이 다른 추정치들이 일치할수록 효과가 모형 설정의 산물이 아니라 실제라는 신뢰가 높아짐
도입에 필요한 데이터와 조직적 합의
- 분석에는 비교군과 출시 단위 데이터가 필요함
  - 인프라 기능이 100% 보급되지 않아, 사용 자격은 있지만 아직 사용하지 않은 모델이나 엔지니어가 남아 있어야 함
  - 각 출시가 어떤 기능을 사용했는지 추적해야 하며, 이는 대개 가장 어려운 요건으로 인프라 팀과 제품 팀의 지속적인 협업이 필요함
  - 매출을 개별 출시에 연결해 도입 정보와 성과 정보의 분석 단위를 일치시켜야 함
  - 컴퓨팅 할당량, 팀 규모, 모델 특성, 출시 시점을 하나의 분석 데이터셋으로 모아야 함
- 조직적 수용도 필요함
  - 인프라 팀은 매출 기반 평가를 받아들여야 함
  - 경영진은 추정치의 신뢰구간이 A/B 테스트보다 넓지만, 측정하지 않는 것보다는 훨씬 많은 정보를 준다는 점을 이해해야 함
투자 확대 속에서의 적용 범위와 한계
- AI 인프라 지출은 매출보다 빠르게 증가하고 있으며, 믿음만으로 투자를 정당화하는 시대는 끝나가고 있음
- 이 방법은 기반 기능이 후속 팀의 사업 성과를 가능하게 하는 계층형 기술 스택 전반에 적용할 수 있음
  - 광고에 한정되지 않고, 인프라 팀이 공유 기능을 만들고 다른 팀이 이를 활용해 성과를 내는 조직은 같은 귀속 문제를 겪음
- 무작위 실험이 불가능할 때 인프라 투자를 측정 가능한 활동으로 전환할 수 있지만, 타당한 가정과 신중한 모형 설정, 불확실성에 대한 솔직한 인정이 전제돼야 함

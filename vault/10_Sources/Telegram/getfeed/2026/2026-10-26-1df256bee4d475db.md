- ThinkRail은 pi 코딩 에이전트에 편집기, 터미널, 검토 도구를 결합하고, 지속적으로 갱신하는 명세와 재사용 가능한 스킬로 프로젝트 지식을 세션 너머까지 유지하는 IDE임
- git worktree 기반 작업공간마다 브랜치와 작업 디렉터리를 분리해 에이전트를 병렬 실행하며, 변경 검토부터 GitHub PR 생성, CI 확인, 병합까지 연결함
- 코드 옆의 SPEC.md 그래프를 에이전트가 전용 도구로 읽고 검색하고 관리함. 기존 Agent Skills를 그대로 읽으며, 프로젝트 설정과 설계 구상, PR 제출을 위한 워크플로도 제공함
- 작업공간당 여러 pi 세션을 실행하고 모델, 토큰 사용량, 비용을 개별 확인할 수 있음. 실행 중 지시 변경, 후속 요청 대기열, 하위 에이전트 위임, 공동 계획 편집을 지원함
- 데스크톱 앱과 브라우저용 CLI가 같은 엔진 호스트를 사용하며, JetBrains AI 또는 기존 제공업체 인증을 연결함. 기본 사용 이벤트와 오류 보고는 수집하며, 추가 사용 데이터 공유만 별도 설정으로 제어함
작업공간 격리와 PR 작업 흐름
- git 저장소를 프로젝트로 열고 git worktree 로 작업공간을 만들면 각각 독립된 브랜치와 작업 디렉터리를 가짐
  - 에이전트가 기존 체크아웃을 건드리지 않고 병렬 작업하며, 원하는 브랜치는 병합하고 나머지는 삭제할 수 있음
  - 기존 worktree를 연결하거나 프로젝트 폴더 자체에서 작업하는 방식도 지원함
- 완료되거나 쉬고 있는 작업공간은 프로젝트별 보관 선반으로 자동 이동함
  - PR이 병합되거나 닫혔을 때, 또는 일주일간 활동이 없을 때 이동하며 다시 작업하면 복귀함
- 상단 표시줄에서 활성 브랜치의 origin 대비 상태와 PR 상태를 확인하고 게시, 푸시, PR 생성을 실행할 수 있음
  - PR 설명에는 계획, 커밋, PR 템플릿 또는 에이전트가 작성한 초안을 활용함
  - GitHub PR을 연 뒤에는 CI 검사와 리뷰 결정을 확인하고, 리뷰 준비 완료 처리나 실패한 검사 및 분기된 브랜치의 해결을 에이전트에 맡길 수 있음
  - 저장소에서 마지막으로 사용한 방식으로 병합하거나, PR을 다시 열거나, 원격 브랜치를 삭제할 수 있음
에이전트를 둘러싼 편집과 대화 환경
- Monaco 편집기 탭, 파일 트리, 변경 파일 보기, 터미널, 문서를 분할 가능한 작업 화면에 배치하며 모두 활성 작업공간에 종속됨
  - 파일 트리에 Git 변경 상태가 실시간으로 표시됨
  - 파일과 diff의 특정 위치에 리뷰 댓글을 달아 구조화된 맥락으로 채팅에 전달하거나, 설치된 다른 IDE에서 worktree를 열 수 있음
- 작업공간마다 여러 동시 pi 세션을 실행하며 각 세션에 별도 모델과 실시간 토큰 및 비용 표시가 있음
  - 실행 중인 응답에 방향을 제시하거나 후속 요청을 대기열에 넣고, 하위 에이전트에 작업을 위임할 수 있음
  - 에이전트가 갱신하고 사용자가 편집하는 공동 계획을 사용하며, 완료된 단계별로 커밋하고 검토할 수 있음
- 셸 외에도 웹 조사와 채팅 내 시각화 도구를 제공함
  - 다이어그램, 선택지 비교, 파일 미리보기를 채팅 안에서 렌더링함
  - UI 변경 제안 시 전후 목업을 보여주며 diff처럼 댓글을 달 수 있음
  - Settings → Extensions 에서 에이전트에 제공되는 ThinkRail 확장을 확인하고 각각 끌 수 있음
지속적으로 갱신하는 명세와 재사용 가능한 스킬
- 코드 옆에 연결된 SPEC.md 파일 그래프를 두고 프로젝트 의도를 세션 이후에도 유지함
  - 에이전트는 전용 spec_* 도구로 명세를 읽고 검색하고 관리함
  - 읽기 전용 Specs 도구는 명세 그래프를 작업 화면의 트리로 표시함
- 다른 코딩 에이전트용으로 보관한 Agent Skills를 원래 위치에서 읽어 사용함
  - 기본 제공 워크플로는 프로젝트 설정, 설계 브레인스토밍, PR 제출을 안내함
  - 사용자의 gh 를 통해 작업공간 브랜치를 푸시하고 GitHub PR을 열거나 갱신함
- 향후 전체 확장 지원을 추가해 실제 작업 방식에 맞춰 ThinkRail이 필요한 도구를 만들 수 있도록 할 계획임
MCP 연결과 모델 인증
- pi 의mcp.json 에 있는 MCP 서버를 연결하거나 설정에서 서버와 일부 프리셋을 추가할 수 있음
  - 서버가 읽기 전용으로 표시하지 않은 호출은 채팅에서 승인받으며, 프로젝트에서 신뢰하는 도구는 항상 허용할 수 있음
  - 저장소가 정의한 서버는 사용자가 승인하기 전까지 비활성 상태로 유지함
  - OAuth 서버 로그인은 설정에서 진행하며, 각 채팅의 서버를 백그라운드 명령 및 하위 에이전트와 함께 표시함
- JetBrains AI로 로그인하거나 pi 자체 인증을 통해 다른 제공업체를 연결함
  - ThinkRail 자체 계정은 없으며, 실행에는 Git과 모델 제공업체 연결이 필요함
실행 형태와 언어 지원
- 네이티브 데스크톱 앱과 브라우저에서 같은 앱을 여는 독립형 thinkrail CLI를 제공함
  - 두 형태 모두 같은 엔진 호스트를 내장하며 앱 상태는 ~/.thinkrail 에 저장함
  - 배포 파일과 SHA256SUMS 는 릴리스 페이지에서 제공함
- 패키징된 stable 및 nightly 빌드는 업데이트 확인을 지원함
  - 데스크톱 앱은 사용자가 설치 및 재시작을 선택하기 전까지 업데이트를 적용하지 않음
  - CLI 업데이트는 호스트에서 실행되며 성공 후 호스트를 수동 재시작해야 함
- 언어 설정은 시스템 언어를 따르거나 사용자가 선택할 수 있으며 영어와 중국어 간체를 기본 제공함
  - 번역한 en.json 을~/.thinkrail/locales 에 넣으면 저장할 때 반영됨
  - 에이전트 응답과 도구 출력은 에이전트가 작성한 언어 그대로 유지함
사용 데이터와 개인정보 처리
- 기본 사용 이벤트는 무작위 설치 ID와 연결해 수집함
  - 실행, 채팅 생성, 메시지 전송, 제공업체 연결이 대상이며 프롬프트, 코드, 파일, 인증 정보, 계정 신원은 포함하지 않음
- 오류 보고는 항상 전송되며 같은 설치 ID에 연결됨
  - 오류 유형과 코드, ThinkRail 자체 코드 내 발생 위치만 포함함
  - 오류 메시지, 파일 경로, 이름, URL, 프로젝트나 확장 내부 정보는 포함하지 않음
- 추가 제품 사용 정보와 ThinkRail을 알게 된 경로는 Share additional usage data 가 켜져 있을 때만 공유함
  - 첫 실행 또는 Settings → Privacy 에서 설정하며,--no-analytics 나THINKRAIL_NO_ANALYTICS=1 은 해당 실행의 추가 공유를 끔
  - 추가 공유가 켜진 패키지 빌드는 설치와 유입 웹사이트 방문을 연결하기 위해 브라우저에서 ThinkRail 블로그를 한 번 열 수 있음
  - 웹사이트에서 마케팅 쿠키에 동의했거나 동의가 필요 없는 경우에만 연결하며, 연결은 30일 후 만료됨
내부 구조와 명세 우선 개발
- ThinkRail은 pi 코딩 에이전트를 프로세스 내부에서 실행하고 웹 UI에 연결하는 얇은 호스트임
  - pi 가 모델, 스킬, 맥락 압축, 비용, 세션 상태를 담당함
  - 앱은 작업공간, 편집기, 통신을 담당하며 사용자 모르게 프롬프트를 조립하지 않음
- 구조는 엔진 호스트, 통신 계약, UI 클라이언트의 세 영역으로 나뉨
  - packages/server 와packages/shared :Bun.serve 기반 HTTP 및 WebSocket 호스트로, 채팅당 하나의 프로세스 내부pi 세션을 실행하며 CLI 또는 데스크톱 앱이 구동함
  - packages/contracts : 호스트와 UI 사이의 타입 및 버전이 있는 프로토콜을 정의함
  - apps/web : React 19, Zustand, Tailwind v4 기반 클라이언트로 독립 배포되며 통신 계약에만 의존함
- 명세 우선 개발을 적용해 모든 모듈 옆에 SPEC.md 를 두고, 경계나 계약 또는 결정이 바뀌면 같은 변경에서 명세도 갱신함
- 기여 절차와 검사, 종단간 테스트, 데스크톱 패키징, 저장소 구조는 기여 가이드에 있으며, 커뮤니티에는 행동 강령이 적용됨
- 라이선스는 Apache License 2.0임

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.
- 웹 미리보기는 페이지당 최대 20개 메시지씩, 최대 10페이지(최근 약 200개)까지만 페이지네이션한다.
- 이미지, 동영상 등 미디어 전용 메시지(텍스트 없음)는 캡처하지 않는다.
- 메시지에 포함된 기사 링크(최대 메시지당 3개, 유튜브/X/인스타그램/페이스북 제외)는 본문을 함께 가져와 아래 '첨부 기사 원문'에 붙인다 - 실패하면 그 링크만 오류로 표시된다.

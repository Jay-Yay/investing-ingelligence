### Oracle, 사내 AI 코딩은 장려하면서 OpenJDK에는 AI 생성 코드 기여 금지 | GeekNews

(https://news.hada.io/topic?id=32246)

- Oracle은 자신이 관리하는 오픈소스 Java 프로젝트 OpenJDK에서 LLM/확산 모델 등으로 일부라도 생성된 코드, 문서, 이미지 등의 기여를 금지하는 임시 정책을 도입함
- AI 도구를 코드 이해/디버깅/리뷰/연구에 개인적으로 사용하는 것은 허용하지만, 그 도구가 생성한 결과물을 Git 저장소, PR, 이메일, 위키, Java Bug System 등에 제출해서는 안 됨
- Oracle은 검토 부담과 안전/보안/지식재산권 문제를 이유로 들며, 그럴듯하지만 잘못된 코드가 세계 각지의 미션 크리티컬 시스템을 떠받치는 OpenJDK의 신뢰성을 위협할 수 있다고 밝힘
- 반면 Oracle 내부에서는 Larry Ellison이 “Oracle이 작성하는 코드를 Oracle이 작성하지 않는다”고 말할 정도로 AI 코딩을 적극 도입하고 있으며, 더 작은 엔지니어링 팀으로 더 빠르게 제품을 제공할 수 있다고 평가함
- Oracle은 AI 인프라에 향후 1년간 700억 달러를 투자할 계획이지만 S&P가 신용등급을 BBB-로 낮추고 CDS 스프레드도 상승한 상황이어서, The Register는 AI 코드에 대한 내부 정책과 OpenJDK 정책의 차이를 문제 삼음
OpenJDK의 생성형 AI 기여 금지
- Oracle은 OpenJDK의 생성형 AI 임시 정책을 통해 정식 정책을 작성하는 동안 적용할 기본 규칙을 공개함
- OpenJDK 커뮤니티의 기여물에는 대규모 언어 모델, 확산 모델 또는 유사한 딥러닝 시스템이 일부 또는 전부 생성한 콘텐츠가 포함되어서는 안 됨
  - 소스 코드
  - 텍스트
  - 이미지
  - OpenJDK Git 저장소와 GitHub PR
  - 이메일
  - 위키 페이지
  - Java Bug System 이슈 등이 대상임
- AI 도구 자체의 사용을 전면 금지하는 것은 아님
  - OpenJDK 코드와 기타 콘텐츠의 이해
  - 디버깅
  - 코드 및 콘텐츠 리뷰
  - OpenJDK 프로젝트 관련 연구
등에 LLM 기반 도구를 개인적으로 사용할 수 있음
- 단, 이 과정에서 AI가 생성한 결과물을 기여물에 포함하면 안 됨
Oracle이 제시한 이유
- AI 생성 기여물이 늘어나면 사람이 이를 검토해야 하므로 리뷰 작업량 증가가 발생할 수 있음
- 안전과 보안, 지식재산권에 관한 위험도 이유로 제시함
- OpenJDK는 많은 조직에서 사용되는 주요 Java 구현체이며 세계 각지의 미션 크리티컬 시스템을 떠받치고 있음
- Oracle은 그럴듯해 보이지만 잘못된 코드가 OpenJDK의 안전성과 보안을 위험에 빠뜨릴 수 있다고 봄
Oracle 내부에서는 AI 코딩을 적극 도입
- 이 같은 OpenJDK 정책은 Oracle 내부의 AI 코딩 활용과 대조됨
- Larry Ellison은 Oracle AI World 2025에서 개발자가 원하는 프로그램의 동작을 모델에 알려주면 AI 모델이 단계별 절차, 즉 프로그램 자체를 작성한다고 말함
- 개발자는 절차를 직접 작성하는 대신 의도를 선언하고, 모델이 실제 코드를 작성하는 형태라고 설명함
- 2026년 초 공동 CEO Mike Sicilia도 Oracle이 AI 코딩 도구를 매우 빠르게 도입하고 있다고 밝힘
  - AI 코딩을 도입하지 않았다면 위협이 됐을 것이라고 봄
  - AI 코딩 도구를 통해 더 작은 엔지니어링 팀이 더 완전한 솔루션을 더 빠르게 제공할 수 있다고 평가함
AI 도입과 인력 감축
- Oracle은 6월 21,000명 규모의 인력 감축을 설명하면서 AI도 한 요인으로 들었음
- 회사 운영 전반에 AI 기술을 배치한 결과 인력이 감소했으며, 앞으로도 추가적인 인력 감소가 발생할 수 있다고 밝힘
- Oracle은 자사 애플리케이션에 내장된 AI 에이전트가 추론하고, 비즈니스 결정을 내리고, 사용자를 대신해 행동할 수 있다고도 주장하고 있음
내부 코드와 OpenJDK 사이의 모순
- The Register는 Oracle 제품에는 AI 생성 코드가 적합하지만 OpenJDK 기여에는 적합하지 않다고 보는 이유가 불분명하다고 평가함
- Oracle이 내부 AI 생성 코드를 안전하고 보안성 있게 만드는 별도의 방법을 갖고 있는지 문의했으나, 기사 시점에는 해당 방법이 공개되지 않았음
- AI가 안정적으로 사용자를 대신해 행동할 수 있는지 공개적으로 의문을 제기하는 것은 현재 AI에 대규모 투자를 진행 중인 Oracle에게 불편한 문제가 될 수 있음
700억 달러 데이터센터 투자와 재무 부담
- Oracle은 향후 1년 동안 데이터센터 확장을 위해 700억 달러를 투자하겠다고 밝힘
  - 2026 회계연도 투자액은 557억 달러였음
- S&P는 이 발표 이후 Oracle의 신용등급을 BBB- 로 낮춤
  - 투자를 통해 수익을 창출하는 경로가 불확실하다는 점을 이유로 들었음
  - BBB-는 정크 등급보다 한 단계 높은 수준임
- Oracle은 데이터센터 건설을 위해 많은 자금을 차입하면서 마이너스 현금흐름을 감수하고 있음
- 최근 Oracle의 신용부도스왑(CDS) 스프레드도 상승해, 회사의 채무불이행에 대비한 보험 비용이 더 높아진 상태임

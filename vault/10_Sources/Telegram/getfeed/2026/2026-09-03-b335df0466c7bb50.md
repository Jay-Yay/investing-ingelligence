### 마케팅 인텔리전스 레이어 - 흩어진 경험을 AI의 재사용 가능한 컨텍스트로 만들기 | GeekNews

- 문서·회의록·Slack 등에 흩어진 15년 이상의 경험을 구조화해, 다양한 AI 도구가 활용할 수 있는 마케팅 인텔리전스 레이어로 구축하는 법
- /raw 에 원본 자료를 넣고/build 를 실행하면 Extractor가 문서 요약이 아니라 다른 상황에서도 재사용할 수 있는 개별 학습 내용을 추하고, Router가 의미에 따라 주제별로 분류함
- 회사 기밀은 제거하거나 일반화하고 사람이 추출 결과와 분류를 승인한 뒤 반영하며, 업무에서 얻은 전이 가능한 판단과 교훈은 보존함
- Claude Code용 /build 스킬과 HTML 템플릿을 공개, 새 회의와 캠페인, 실험과 실패를 계속 추가해 개인의 경험이 AI와 함께 복리로 축적되는 자산을 만드는 것이 목표임
- 결과물은 Claude·ChatGPT·Gemini·에이전트에 전달할 수 있는 단일 HTML 파일이며, 무료 Claude Code 스킬과 템플릿으로 로컬이나 Google Drive에서 운영할 수 있음
흩어진 경험을 AI가 사용할 수 있는 자산으로 전환
- 오랜 경력에서 얻은 지식은 Google Docs, 발표 자료, Slack 대화, 회의록, 음성 메모와 개인의 기억에 흩어져 있음
- 사람은 일부 경험을 직관적으로 활용하지만 언제 어떤 상황에서 무엇을 배웠는지 모두 기억하기 어려움
- AI도 접근할 수 있는 컨텍스트가 없으면 새 대화마다 사용자의 경험과 판단 기준을 알지 못한 채 시작함
- 사용자가 자신의 프레임워크와 과거 사례를 다시 설명하지 않으면 일반적인 학습 데이터에 기반한 답변만 나오기 쉬움
- Darwin이 관찰·인용문·아이디어·질문을 commonplace book과 노트에 축적해 이후 더 큰 작업에 활용했듯, 누적 지식을 인간의 기억만으로 관리하기는 어려움
- 문제는 자료가 부족한 것이 아니라, AI가 활용할 수 있는 형태로 개인의 경험이 구조화되어 있지 않다는 점
경력 전체를 담는 하나의 인텔리전스 레이어
- Marketing Intelligence Layer는 경력에서 얻은 재사용 가능한 지식을 주제별로 정리한 하나의 구조화된 결과물임
- 보존하려는 정보는 단순한 업무 기록이 아니라 다음 판단 자산임
  - 반복해서 사용하는 프레임워크와 공식
  - 성공한 캠페인과 실패한 실험
  - 신뢰할 만한 지표와 벤치마크

- 특정 AI 제품의 메모리 기능에 경험을 맡기지 않으므로 사용하는 도구가 바뀌어도 같은 지식 자산을 유지할 수 있음
자료를 넣고 명령 하나로 갱신
- 기본 흐름은 원본 자료를 raw/ 에 추가 →/build 실행 → 학습 내용 추출 → 주제 분류 → 기밀 제거 → 사용자 승인 → HTML 갱신으로 구성됨
- 회의록, 전략 문서, 음성 메모 전사본, 발표 자료와 정리되지 않은 불릿 등 형식이 다른 자료를 그대로 넣을 수 있음
- 사용자가 파일을 정리하거나 태그를 붙이고 저장 위치를 고를 필요는 없음
- 이미 처리한 파일은 .processed.md 에 기록해 다음 실행에서 건너뛰고, 처리된 자료의 복사본은archive/ 로 이동함
- 기존 index.html 이 있으면 새 학습 내용만 추가하고, 없으면 새로운 인텔리전스 레이어를 생성함
문서를 요약하지 않고 학습 내용을 추출
- 핵심은 원본 문서의 요약본을 만드는 것이 아니라, 문서 속에서 나중에도 사용할 수 있는 독립적인 판단과 경험을 찾아내는 것임
- 하나의 회의 기록에서도 서로 다른 유형의 정보가 나올 수 있음

  - 실패한 시도와 그 원인
  - 의사결정에 사용한 프레임워크
  - 예상과 달랐던 결과
  - 다시 사용할 만한 운영 원칙
- 추출기는 각각을 별도 항목으로 나누고 짧은 제목, 전체 설명, 유형과 출처 파일을 기록함
- 설명은 원본을 보지 않은 사람이나 AI도 이해할 수 있도록 무엇을 배웠고 왜 중요한지, 어떻게 적용하는지를 완전한 문장으로 작성함

추출한 지식을 주제별로 자동 분류
- 기본 인텔리전스 레이어는 마케팅 업무를 여덟 영역으로 나눔

- AI 마케팅, 브랜드, 파트너십, 커뮤니티와 개발자 마케팅처럼 개인에게 필요한 주제를 추가할 수 있음
- 단어가 포함된 분야보다 학습 내용의 실제 목적을 기준으로 분류함
- 예를 들어 유료 광고팀의 조직 구조에 관한 내용은 Paid가 아니라 Leadership으로, 콘텐츠 ROI 측정 방법은 Content가 아니라 Attribution으로 보냄
- 특정 회사나 역할에서 얻은 경험은 회사별 페이지에 배치하고, 여러 분야에 걸친 일반 원칙은 홈 화면에 표시함

- 회사에서 일하며 접한 내부 데이터는 개인이 다른 곳으로 가져가서는 안 되지만, 그 경험을 통해 형성한 판단과 프레임워크는 재사용할 수 있다는 구분에서 출발함
- /build 에는 기밀 정보를 제거하거나 일반화하는 필터가 포함됨

- 첫 실행에서는 이름과 역할, 추가할 주제를 질문해 config.json 에 저장함
- 이후 /build setup 으로 역할이나 분류 주제를 변경할 수 있지만, 새로 추가한 주제에 기존 항목이 자동으로 재분류되지는 않음
- 분류와 기밀 제거를 AI에 맡기더라도 최종 지식 자산의 정확성과 공개 범위는 사용자가 확인해야 함

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.

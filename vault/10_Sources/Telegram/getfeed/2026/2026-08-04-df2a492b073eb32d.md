### 개발 도구가 오픈소스여야 하는 이유 | GeekNews

(https://news.hada.io/topic?id=32114)

- 코딩 에이전트가 소스 수정부터 업스트림 동기화와 유지보수까지 자동화하면서, 자신만의 소프트웨어를 만드는 비용이 크게 낮아짐
- 소스를 내려받아 로컬 빌드를 만들고 변경 동기를 버전 관리에 기록한 뒤, 매일 업스트림 변경 위로 로컬 수정을 리베이스할 수 있음
- Shelley와 meat.dev의 통합은 프롬프트 하나로 구현됐으며, 커밋 즉시 LLM 처리를 시작해 diff 검토 시 발생하는 대기 시간을 없앰
- 소스를 직접 바꿀 수 있으면 정해진 설정 파일이나 플러그인 API에 맞추지 않고도 글꼴 교체부터 팀 전용 CMS·CRM까지 필요한 기능만 구현할 수 있음
- Codex와 Pi는 자체 소스를 확장 시스템처럼 활용할 수 있지만, 비공개 소스인 Claude Code는 제공된 커스터마이징 훅을 벗어나 개인화하기 어려움
개인용 소프트웨어를 만들기 어려웠던 이유
- 5년 전에는 자신을 위해 직접 작성한 프로그램이 없는 소프트웨어 엔지니어가 대부분이었음
  - 엔지니어들은 다른 사람이 만든 프로그램으로 다른 사람을 위한 프로그램을 작성함
  - 설정 파일, 플러그인, 확장 기능으로 도구를 조정하거나 자신이 만든 제품을 직접 사용하기는 했음
  - 블로그·홈 자동화·홈랩을 위한 맞춤형 프로그램은 기성 정적 사이트 생성기나 Zigbee 기기 대신 쓰는 드문 사례였음
- 개인용 소프트웨어는 투자 대비 효과가 불분명했음
  - 하루에 작성할 수 있는 코드는 제한적이고, 업무상 더 중요한 문제가 늘 존재했음
  - 1년 뒤 프로젝트로 돌아와 유지보수하는 과정도 매우 고통스러웠음
  - 맞춤형 소프트웨어를 모두 버리고 가장 표준적인 개발 환경만 사용한 시기도 있었음
에이전트로 소프트웨어를 개인화하는 방법
- 오늘날에는 두 종류의 프롬프트만으로 소프트웨어를 손쉽게 개인화할 수 있음
  - 소스를 내려받아 로컬용으로 빌드하고, 이후 변경도 소스 수정과 현재 버전 교체로 처리하도록 에이전트의 기억에 남기며 최초 변경 동기를 버전 관리에 기록함
  - 매일 업스트림 변경을 가져와 로컬 수정 사항을 그 위에 리베이스하고, 정상 동작을 확인한 뒤 현재 버전을 교체하는 cron 작업을 설정함
- 에이전트는 특정 기능 구현에 그치지 않고 업스트림 릴리스와 로컬 변경의 동기화도 자동으로 관리함
  - 개인화를 시작하는 비용이 낮아짐
  - 이후 변경을 계속 유지하는 비용도 함께 줄어듦
- 오픈소스 에이전트라면 두 프롬프트를 직접 프로그래밍하지 않고도, 에이전트가 발견할 수 있는 텍스트 지침인 스킬(skill) 로 내장할 수 있음
- Shelley는 이 방식을 자체 기능으로 포함함
  - 별도 사전 지시나 타이머 설정 없이 “Shelley UI를 고대비로 만들어라” 같은 프롬프트만으로 에이전트 자체를 개인화할 수 있음
Shelley와 meat.dev 통합 사례
- meat.dev는 diff에서 중요하지 않은 부분을 LLM으로 제거해 코드 검토자가 핵심에 집중하도록 만든 개인 프로젝트임
- 모델이 발전하면서 코드 검토의 초점도 달라짐
  - 사람은 유용한 오류 메시지나 nil 검사 같은 경계 사례를 자주 놓침
  - 최근 6개월 동안 모델은 반복적인 정확성 측면에서 사람보다 훨씬 꼼꼼해져, 이런 경계 사례를 일일이 검토할 필요가 줄어듦
  - 모델의 오류는 주로 아키텍처, 예상하지 못한 사용 사례, 테스트 환경에서 피드백받지 못한 시각적 출력에 집중됨
- meat.dev는 import 블록, nil 검사, 오류 처리처럼 검토 필요성이 줄어든 코드를 화면에서 제거함
- 기존 사용 방식에는 두 가지 불편이 있었음
  - 터미널 대신 Shelley의 UI에서 diff를 읽고 싶었음
  - LLM이 diff를 축약하는 데 몇 분이 걸려 결과를 기다려야 했음
- Shelley에 meat.dev를 통합하는 단일 프롬프트가 다음 작업을 수행함
  - 최신 meat.dev 버전을 설치하고 PATH 에 추가함
  - Shelley가 Git 커밋을 만들면 백그라운드에서 해당 커밋 처리를 시작함
  - Shelley의 Diffs 화면에 meat 토글을 추가함
  - 처리가 끝나지 않았으면 진행 중임을 사용자에게 표시함
- 최신 meat.dev 버전을 설치하고 
- 커밋 생성 즉시 백그라운드 전처리가 시작되므로, 세션으로 돌아와 diff를 검토할 때 모델의 축약 작업을 기다릴 필요가 없어짐
- 모델이 선택한 유일하게 아쉬운 부분은 토글 버튼에 🥩 이모지를 사용한 것이었음
확장 API와 소스 기반 개인화의 차이
- 같은 기능을 VS Code 확장 API나 vimdiff 에 연결하려면 구현이 복잡해짐
  - 커밋이 나타나는 즉시 전처리를 시작하는 기능은 기존 확장 지점으로 구현하기 매우 어려움
  - 파일 시스템을 감시하고 meat 도구가 사용할 캐시를 제공하는 별도meatd 를 만드는 편이 나을 수 있음
- 기존 커스터마이징 API의 확장 지점과 설정 구조는 원하는 기능의 형태와 맞지 않을 수 있음
- 에이전트 기반 개인화는 소스를 이해하고 특정 작업에 맞게 직접 변경하므로, 고전적인 설정이나 확장 방식보다 변경 범위가 넓음
- 이 방식이 작동하려면 에이전트가 수정할 수 있는 소스 코드가 필요함
플러그인과 설정 파일의 역할 변화
- 에이전트 이전에는 복잡한 소프트웨어에 대규모 설정 파일과 확장·플러그인 시스템을 제공하는 것이 합리적이었음
- Vim 정도 규모의 프로젝트도 핵심 코드가 방대하고 복잡해 사람이 이해하는 데 몇 주가 걸림
  - 줄 번호를 기본으로 출력하려는 개인이 전체 코드베이스를 익혀 직접 기능을 추가하는 것은 비합리적이었음
  - 여러 사용자가 공유할 기능으로 설계해야 구현 비용을 분산할 수 있었음
  - 기능이 늘어나면 공통 추상화를 찾아 확장 또는 플러그인 시스템으로 분리해야 했음
- 이제는 에이전트가 코드 학습과 변경의 무거운 작업을 맡아 변경 비용이 크게 낮아짐
  - 실행 조건이 매우 제한된 단일 사용자용 기능은 최고급 에이전트가 한 번에 추가할 수 있음
  - 단일 사용자용 소프트웨어에서는 세심한 코드 검토를 “제대로 동작하는가”라는 확인으로 대체할 수 있는 경우가 많음
- 개인화 가능한 소프트웨어는 플러그인 시스템이나 설정 파일 없이도 바꿀 수 있음
  - 텍스트 편집기의 글꼴 크기가 하드코딩돼 있다면 에이전트가 값을 찾아 수정함
  - 비트맵 글꼴이라면 다른 글꼴을 내려받아 교체하거나 Monobit으로 새 글꼴을 만들 수 있음
다시 만들어야 할 소프트웨어 제품군
- 개인용 소프트웨어 접근법은 소규모 팀에도 적용할 수 있음
- 엔지니어링 팀은 고도로 설정 가능한 작업 관리자·CMS·CRM을 구매해 사용법을 익히고 제품의 한계에 업무 방식을 맞추는 대신, 공통 구성 요소에서 필요한 기능만 조립할 수 있음
- 소프트웨어 개인화에 들던 초기 고정 비용과 지속 비용이 모두 사라짐
- exe.dev 블로그도 전통적인 제품을 조정하는 것보다 Tiptap 같은 라이브러리를 조립하고 개인화하는 편이 쉬워, Shelley로 만든 맞춤형 소프트웨어임
- 기업의 최종 사용자용 제품이 경쟁력을 가지려면 개인화 가능성이 필요하며, 이를 위해 소스 코드에 접근할 수 있어야 함
Codex·Pi와 Claude Code의 차이
- Shelley의 스킬 기반 개인화는 오픈소스 에이전트인 Pi에도 쉽게 적용할 수 있음
  - 소스 코드 자체가 확장 시스템 역할을 할 수 있어 Pi에 별도 확장 시스템이 필요한지 의문이 생김
- 오픈소스 에이전트인 Codex도 더 많은 토큰이 필요하지만 같은 방식으로 개인화할 수 있음
- Claude Code는 비공개 소스이므로 직접 개인화할 수 없음
  - 전통적인 커스터마이징 훅은 많이 제공함
  - 원하는 작동 방식이 해당 훅에 맞지 않으면 소스를 개인화할 수 있는 다른 에이전트로 전환해야 함

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.
- 웹 미리보기는 페이지당 최대 20개 메시지씩, 최대 10페이지(최근 약 200개)까지만 페이지네이션한다.
- 이미지, 동영상 등 미디어 전용 메시지(텍스트 없음)는 캡처하지 않는다.
- 메시지에 포함된 기사 링크(최대 메시지당 3개, 유튜브/X/인스타그램/페이스북 제외)는 본문을 함께 가져와 아래 '첨부 기사 원문'에 붙인다 - 실패하면 그 링크만 오류로 표시된다.

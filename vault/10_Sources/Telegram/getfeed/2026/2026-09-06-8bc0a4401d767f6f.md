### AI는 이제 회로 기판도 설계할 수 있을까? | GeekNews

(https://news.hada.io/topic?id=33261)

- AI는 일부 회로 설계 문제를 풀 수 있지만, 실제 부품의 오차와 비용까지 고려해 요구사항을 만족하는지는 시뮬레이션으로 검증해야 함
- EEBench는 회로를 코드로 작성하고 SPICE로 시험하는 벤치마크로, CAD 화면을 조작하는 능력보다 부품 선택과 연결, 전기적 동작을 설계하는 능력을 평가함
- 정전 후 20ms 동안 전압을 유지해야 하는 과제에서 한 설계는 코드 빌드에 성공했지만 0.85ms 만에 전압 기준을 밑돌았음. 커패시터를 넣는 기본 해법만으로는 실제 요구조건을 만족하지 못함
- 9월 1일 기준 13개 과제의 최고 점수는 Claude Opus 5의 61.6%였으며, Grok 4.6은 57.1%, Claude Fable 5.1은 56.4%를 기록함
- 현재 평가는 아날로그/디지털 회로의 시뮬레이션에 한정되며, PCB 부품 배치와 배선, 제조와 초기 구동까지 맡길 수 있는지를 입증한 결과는 아님
GUI 대신 선언형 회로 코드로 평가
- OpenAI가 GPT-6 Astra의 KiCad 회로 기판 작업을 시연하면서, 모델이 만든 전자 회로의 품질을 어떻게 측정할지가 과제로 떠오름
- 현재 모델은 교과서, 데이터시트, 애플리케이션 노트와 코드를 학습해 상당한 전자공학 지식을 갖췄지만, 일반적인 설계 도구에서는 그 역량을 충분히 드러내기 어려움
- 그래픽 CAD를 조작하는 에이전트는 화면 좌표, 메뉴, 애플리케이션 상태를 추적하고 클릭하는 데 많은 시간과 컨텍스트를 소모함
- EEBench는 atopile을 이용해 회로를 선언형 코드로 표현함
  - 에이전트가 부품, 연결, 전기적 제약을 직접 다룸
  - 프로젝트 안에서 설계 변경, 빌드, 시뮬레이션과 실패 분석을 수행함
  - 컴퓨터 조작 능력보다 전자공학 설계 능력 자체에 집중해 평가할 수 있음
실제 부품이 만드는 설계 제약
- 
에너지 미터의 전원 유지
  - 주거용 에너지 미터는 5V 전원이 끊긴 뒤 프로세서가 누적 측정값을 저장할 수 있도록 20ms 동안 동작을 유지해야 함
  - 보호 전원 레일은 이 시간 동안 프로세서의 3.0V 브라운아웃 임계값보다 높아야 함
  - 대부분의 모델은 커패시터를 추가하는 기본 해법을 찾지만, 실제 부품을 쓰면 여러 조건이 뒤따름
    - 세라믹 커패시터는 전압이 걸리면 표시 용량보다 실제 용량이 크게 줄어들 수 있음
    - 부품 공차 때문에 명목값으로 성공한 설계도 실제 납품 부품에서는 실패할 수 있음
    - 용량을 늘리면 비용과 공간이 증가하고, 전원이 돌아왔을 때 레일 재충전도 느려짐
  - EEBench는 시뮬레이션에서 입력 전원을 차단한 뒤 다음 조건을 측정함
    - 정전 구간의 전압
    - 동작점에서의 유효 정전용량
    - 전원 복귀 후 회복
    - 패키지, 유전체, 정격 전압과 비용 제한
- 
더 어려운 아날로그 필터
  - 다중 피드백 저역통과 필터 과제에서는 연산증폭기를 중심으로 회로를 합성하고, 요구 극점에 맞춰 저항과 커패시터 비율을 계산해야 함
  - 모든 부품을 최악 공차 조건으로 이동시킨 뒤에도 이득, 차단 주파수와 Q가 제한 범위 안에 있어야 함
  - 평가 하네스는 각 공차 조건에 맞춰 SPICE 덱을 다시 만들고 AC 및 과도 응답을 캡처함
    - 측정값을 이름이 지정된 프로브에 연결함
    - 각 결과를 명세의 하한·상한과 비교해 기록함
- 
성능·비용·수급의 절충
  - EEBench는 데이터시트에서 추출한 명세를 SPICE 모델에 반영한 실제 제조사 부품을 사용함
  - 에이전트는 전체 공차 범위에서 동작하고 실제로 주문할 수 있으며, 제품에 적절한 가격의 부품 조합을 찾아야 함
  - 이상적인 교과서 값을 고르는 대신 전기적 성능·비용·공급 가능성 사이의 절충을 다루게 됨
요구사항을 결정론적으로 채점하는 방식
- EEBench는 제출된 설계를 빌드해 회로 그래프와 부품 명세서(BOM)를 구성한 뒤 SPICE 시뮬레이션과 설계 검사를 실행함
- 각 요구사항이 제한값과 비교 가능한 측정 결과를 생성하므로 평가가 완전히 결정론적임
- 에너지 미터에서는 입력 전원이 사라졌다가 복귀할 때 보호 레일을 측정하며, 다른 과제에서는 다음 항목을 검사함
  - 이득과 임계값
  - 리플과 과도 응답
  - 부품 공차 조건별 동작
- 기술 점수는 기준 BOM 대비 비용 효율과 결합되지만, 회로가 먼저 정상 동작해야 비용이 점수에 반영됨
- 코딩 에이전트에 컴파일러와 테스트를 제공하는 방식과 비슷하지만, 여기서는 전압과 부품 동작을 시험한다는 차이가 있음
- EEBench V1은 시뮬레이션을 통한 아날로그·디지털 설계를 평가함
  - 완제품의 PCB 배치, 제조와 초기 구동 능력은 아직 평가하지 않음
  - 객관적으로 채점할 수 있는 요구사항 정의, 설계와 검증 순환에 집중함
  - 전체 방법론과 샘플 결과 탐색기가 공개돼 있음
13개 과제의 모델별 성적
- 9월 1일 EEBench V1 결과는 다음과 같음
  - Claude Opus 5: 61.6%
  - Grok 4.6: 57.1%
  - Claude Fable 5.1: 56.4%
  - Claude Fable 5: 54.3%
  - Claude Opus 4.8 Max: 51.4%
- 전체 순위와 실행 세부 사항은 EEBench 리더보드에서 확인할 수 있음
- xAI는 Grok 4.6 모델 카드의 ‘engineering acceleration’ 항목에 EEBench를 3D 모델링 및 파라메트릭 CAD 평가와 함께 포함함
  - xhigh 추론 노력 설정으로 공개한 Grok 4.6 실행 결과는 60.0% 임
- Anthropic 모델은 이 환경에서 꾸준히 높은 성적을 냈으며, Grok 4.6의 순위도 상승함
- xAI는 Grok 4.6 출시 글에서 고품질 엔지니어링 데이터와 CAD를 포함한 분야별 환경의 강화학습을 사용했다고 밝힘
- 테스트된 OpenAI 모델은 상대적으로 낮은 순위에 있음
  - GPT-5.5는 42.3%
  - GPT-5.6 Sol은 39.4%
  - GPT-6 Astra는 아직 EEBench 결과가 없음
평가 하네스를 강화학습에 활용
- 회로를 채점하는 시뮬레이션 하네스는 전자공학용 강화학습 환경의 기반으로도 활용할 수 있음
- 동일한 검사 결과를 모델 후학습 과정의 보상 신호로 사용할 수 있음
- 실패한 실행은 회로도가 그럴듯한지만 판단하는 것보다 구체적인 정보를 제공함
  - 어떤 전압이 제한을 벗어났는지 확인할 수 있음
  - 어느 동작 공차 조건에서 실패했는지 파악 가능함
  - 불필요하게 비싼 설계로 문제를 해결했는지 판별할 수 있음
- EEBench는 이 작업을 공개한 소규모 버전이며, 더 큰 평가 모음과 시뮬레이션 기반 학습 환경을 원하는 프런티어 연구소와도 직접 협업을 시작함
현재 가능한 범위와 다음 단계
- 유용하면서 계속 늘어나는 일부 회로 문제에서는 AI가 이미 설계를 수행할 수 있지만, 60% 안팎의 최고 점수는 여전히 개선할 부분이 많음을 보여줌
- OpenAI가 Astra의 초기 시연에 PCB를 선택하고 xAI가 EEBench를 모델 카드에 포함하면서 AI 연구소도 전자공학 평가를 다루기 시작함
- Elon Musk는 Grok 4.7이 대규모 SpaceX 데이터를 추가로 학습해 엔지니어링 역량을 강화한 뒤 수주 내 출시될 것이라고 말함
  - 모델은 아직 출시되지 않았으며 일정도 바뀔 수 있음
  - 설명대로 출시되면 EEBench에서 평가할 계획임
- 모델이 발전함에 따라 더 어려운 과제를 추가하고 Astra와 차세대 모델을 평가할 예정임
- 사용자는 atopile에서 같은 접근법을 적용해 에이전트가 원하는 기판 설계를 어디까지 수행하는지 시험할 수 있음
- 일부 회로 기판은 이미 설계할 수 있지만, 심박조율기 같은 안전 필수 제품을 맡기고 검증 없이 사용하는 단계는 아님
- EEBench는 atopile 팀이 개발하고 자금을 부담하며, 공개 벤치마크 실행 비용을 직접 지불하고 벤치마크 점수를 판매하지 않음

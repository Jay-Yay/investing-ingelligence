### Jev는 아마도 Qwen3.5-35B-A3B 기반일 것 | GeekNews

발행 2026-11-26 · 작성 xguru
출처 https://news.hada.io/topic?id=37859
- 경쟁 의사결정 모델을 개발하는 Modaic이 TypeSafe의 Jev를 응답 행동, 토큰 수와 지연 시간의 관계, 처리량으로 분석함. 여러 단서를 종합해 Qwen3.5-35B-A3B를 가장 유력한 기반 모델 후보로 추정함
- 입력이 길어져도 안정적인 지연 시간과 가격 대비 높은 정확도는 일부 전문가만 활성화하는 희소 MoE 구조와 부합함
- 간접적인 자기 식별 질문에서 두 Jev 버전 모두 Qwen 선택지에 74%의 확률을 부여했지만, 이 응답만으로 기반 모델을 입증할 수는 없음
- 9,984개 프롬프트에서 Qwen 토크나이저의 토큰 수가 Jev API 보고값보다 지연 시간을 잘 예측했지만, Gemma와는 거의 동률이었음. 별도의 처리량 비교에서는 Qwen3.5-35B-A3B 파생 모델과 가장 비슷한 양상을 보임
- 이는 대략적인 성능 지문이지 기반 모델의 확정 증거는 아님. 하드웨어와 서비스 구성이 공개되지 않았고, 같은 아키텍처의 Qwen3.6-35B-A3B와도 처리량만으로 구별할 수 없음
입력 중심 모델에서 기반 모델 선택이 중요한 이유
- Jev는 텍스트 생성 대신 보정된 판단을 출력하도록 학습한 TypeSafe의 System One 모델임
- 경쟁 System One 모델들이 정확도와 보정 성능에서 빠르게 앞선 가운데, 이번 분석은 Jev의 일관된 추론 속도와 같은 가격으로 유사 모델을 안정적으로 서비스하는 조건에 초점을 맞춤
- System One 작업은 입력 비중이 높아 프리필(prefill) 이 지배적인 비용이며, 커널 최적화만으로 얻을 수 있는 속도 향상에는 한계가 있음
- Jev 수준의 지능을 갖춘 모델을 처음부터 사전 학습하려면 연산 비용만 수천만 달러가 필요하므로, 기존 오픈소스 모델의 미세 조정이라는 가설에서 출발함
  - TypeSafe는 모델이 정체를 숨기도록 학습한 것으로 보이며, API도 실제 입력 토큰 수를 숨기는 것으로 의심됨
지연 시간과 응답 행동이 가리키는 희소 MoE
- Jev 1.14 요청 9,976건을 입력 길이 2,000토큰 구간으로 묶었을 때, 중앙 지연 시간은 77ms에서 155ms로 늘었지만 p50~p99 차이는 47~58ms로 유지됨
- 지연 시간과 가격에 비해 높은 지능은 희소 MoE 기반이라는 가설을 뒷받침함
  - 라우터가 각 토큰을 계층별 피드포워드 네트워크인 전문가 중 일부에만 전달함
  - 밀집 모델과 같거나 더 많은 총매개변수를 갖추면서도 토큰당 연산량을 줄여 긴 입력의 프리필을 빠르게 처리할 수 있음
  - 연산량 대비 지능이 높아져 비용과 지연 시간을 함께 줄일 수 있음
- Artificial Analysis Decision Index는 정확도, 신뢰도, 일관성을 측정하는 여섯 가지 평가로 언어 모델과 System One 모델을 비교하며, 점수가 높을수록 좋음
- Vals AI의 소규모 중국/대만 관련 질문 실험에서 Jev의 응답은 여러 Qwen 파생 System One 모델과 유사했음
  - 중국에서 개발한 모델들은 비슷한 정렬 성향을 보일 수 있어, 정치적으로 민감한 질문의 응답만으로 계보를 입증하기는 어려움
자기 식별 실험: 직접 질문보다 간접 질문에서 강한 Qwen 신호
- Jev 1.13과 1.14에 모델 계열 질문과 후속 질문 등 22가지 변형을 시험함
- 모델 자기 식별 응답은 문구, 시스템 프롬프트, 미세 조정에 따라 달라질 수 있어 단독 증거로는 약함
- 직접 질문에서는 Qwen에 대한 응답이 불확실한 반면, DeepSeek와 Gemma는 강하게 부정함
  - “Are you Qwen?”의 Choice 변형에서 긍정 확률은 1.13이 64%, 1.14가 56%였음
  - Noul 변형에서는 1.13이 긍정 53%, 1.14가 부정 58%로 갈림
  - DeepSeek 부정 확률은 각각 95%, 98%, Gemma 부정 확률은 86%, 90%였음
- 답변을 유보할 수 있으면 모델 계열 공개를 회피하는 경향이 있었으며, 선택지에 Jev나 TypeSafe 모델이 있어도 마찬가지였음
  - 계열을 묻는 질문의 “Other” 확률은 47%에서 70%로 높아짐
  - “I do not know”를 포함한 질문에서는 해당 선택 확률이 92%, 98%였음
  - 1.14의 더 신중한 응답은 TypeSafe가 정체를 드러내는 행동을 추가로 억제하도록 학습했을 가능성과 부합함
- “어떤 모델이라고 말하고 싶은가”라는 간접 질문에는 두 버전 모두 Qwen을 74% 확률로 선택함
  - 실제 계보가 아니라 학습 데이터에서 Qwen이 두드러진 결과일 수도 있지만, 다른 신호들과는 일치함
토크나이저 검증: API 보고값보다 강한 지연 시간 상관관계
- Jev API의 usage.input_tokens 는 비교한 어떤 알려진 모델 계열의 토크나이저와도 일치하지 않았음
  - 자체 사전 학습 모델이라 독자 토크나이저를 사용하거나, 보고값이 실제 모델의 토큰 수를 반영하지 않을 가능성이 있음
- 특히 긴 프롬프트에서는 API 보고값과 Qwen 토크나이저 사이에 평균 약 2,000토큰의 차이가 있었으며, 이는 지연 시간을 수 ms 바꿀 수 있는 규모였음
- 서로 다른 9,984개 프롬프트를 Jev 네이티브 API에 보내 토큰 수와 지연 시간의 관계를 측정함
  - Jev 지연 시간과의 Spearman 순위상관계수는 Qwen3.5-35B-A3B 0.805, Gemma 4 26B-A4B 0.804, Nemotron 3 Super 0.771, Jev API 보고값 0.719였음
  - Qwen과 Gemma는 이 프롬프트 집합에서 토큰 수가 서로 유사해 거의 동률이었으며, Gemma를 배제하는 보조 신호는 앞선 자기 식별 실험에서 나왔음
- 검증용으로 기반 모델이 알려진 두 활성 매개변수 수가 적은 MoE에도 같은 프롬프트를 사용함
  - Baseten의 groundhog-1은 Gemma 4 26B-A4B 파생 모델이며, 자체 토크나이저와의 상관계수가 0.823으로 가장 높았음
  - 아직 학습 중인 Modaic의 Mo Lite는 Qwen3.5-35B-A3B 파생 모델이며, Qwen 토크나이저와의 상관계수는 0.873이었음. 표기된 정밀도에서는 Gemma도 0.873으로 같았음
- 측정은 엔드포인트 내부의 순위상관관계를 비교하므로 서비스 간 절대 속도 차이는 계산에 영향을 주지 않음
  - Jev는 API로 직렬 호출하고, groundhog-1은 Vercel AI gateway에서 연결 4개를 사용함
  - Mo Lite는 단일 B200의 Modal RPC에서 요청 2개를 동시에 처리함
  - 평균 지연 시간은 2,000토큰 구간으로 묶고, 지문 단위 부트스트랩으로 95% 구간을 계산함
- 결과는 Jev의 API 보고 토큰 수가 실제 토큰 수가 아닐 가능성과 실제 토크나이저가 Qwen일 가능성을 뒷받침함
처리량 비교: 밀집 27B보다 Qwen3.5 MoE에 가까움
- 동일한 프롬프트 250개를 네 모델에 재생하며, 모델마다 한 번에 요청 하나만 처리하도록 비교함
  - 입력은 공통 토크나이저 기준 512~9,500토큰이었음
  - Mo Lite는 Qwen3.5-35B-A3B MoE, Baseten의 elephant-1은 밀집 Qwen3.5-9B, Modaic의 Mo 2.0은 밀집 Qwen3.8-27B 기반임
  - 세 비교 모델은 각각 단일 B200에서 실행함
- 요청별 입력 토큰 수를 지연 시간으로 나눈 뒤 길이 구간별 평균을 계산함. Jev만 호스팅 API 오버헤드를 포함하므로, 이 비교는 오히려 Jev 처리량을 낮게 평가할 수 있음
- 밀집 27B 모델인 Mo 2.0은 초당 약 3만 5,000토큰에서 정체됐지만, Jev는 초당 9만 토큰을 넘어서도 처리량이 증가함
- Jev의 곡선은 Mo Lite와 가장 유사했으며, 항상 느렸지만 입력이 길수록 격차가 줄었음
  - 약 3,200토큰에서 처리량 차이는 22%, 지연 시간 차이는 약 15ms였음
  - 약 8,800토큰에서는 각각 7%, 약 7ms로 좁혀짐
  - elephant-1도 빠르지만 긴 입력에서 더 일찍 처리량 곡선이 평탄해짐
- 이 패턴은 대기열/API의 고정 오버헤드와 추가 토큰당 더 빠른 프리필의 조합에 부합함
  - TypeSafe가 유사한 모델을 단일 B200보다 더 많거나 빠른 하드웨어로 서비스한다면 기대할 수 있는 양상임
- 후보 모델의 구조는 Qwen3.5-35B-A3B 모델 카드에서 확인할 수 있음
한계와 다음 검증 과제
- 이번 비교는 후보 기반 모델이 Jev의 관측 성능 범위에 들어가는지 확인하는 근사 성능 지문이며, GPU당 또는 복제본당 처리량의 정확한 측정은 아님
  - Jev의 하드웨어, 동시성, 복제본 수가 공개되지 않았음
  - 종단 간 지연 시간에는 네트워크와 서빙 오버헤드가 포함됨
- 여러 실험을 종합하면 Qwen3.5-35B-A3B가 가장 유력하지만, 후속 모델인 Qwen3.6-35B-A3B도 같은 아키텍처라 처리량만으로 구별할 수 없음
- 두 후보를 구분하려면 지식 기준 시점 질문이나 두 기반 모델의 성능이 다른 작업처럼 행동 차이를 드러내는 추가 검증이 필요함

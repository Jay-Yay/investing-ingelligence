### Qwen 3.8 27B는 뛰어나지만 기본 설정에서 지나치게 오래 추론함 | GeekNews

(https://news.hada.io/topic?id=32578)

- Alibaba Qwen 연구소의 Qwen 3.8 27B는 Apache 2 라이선스와 비전 기능, 262,144토큰 문맥을 갖췄으며, 17GB 양자화 파일로 노트북에서 코드 작성·도구 호출·이미지 분석을 수행함
- 기본 추론 강도인 xhigh 는 단순 요청에도 과도하게 작동해, 자전거를 타는 펠리컨 SVG를 만드는 데 추론 22,276토큰과 21분을 소비한 반면 추론을 끄면 같은 작업이 137초에 끝남
- 사진 속 펠리컨 두 마리의 경계 상자를 정확히 반환하고 좌표 시각화 HTML도 한 번의 프롬프트로 만들었지만, 요청하지 않은 데모 장면까지 추가하는 과잉 설계가 나타남
- 로컬 코딩 에이전트 Pi에서는 여러 파일을 탐색해 Datasette 인증 구조를 분석하고, JSONL 대화를 Markdown으로 변환하는 Python 도구를 직접 작성·테스트해 긴 문맥과 도구 호출 능력을 입증함
- LM Studio에서는 초당 15~30토큰으로 느렸지만 llama.cpp 의 다중 토큰 예측을 적용하자 약 72% 빨라졌으며, 실제 사용은low 나 추론 비활성화로 시작해 필요한 작업에서만 강도를 높이는 편이 적합함
17GB로 실행하는 범용 로컬 모델
- Qwen 3.8 27B는 Alibaba Qwen 연구소가 공개한 270억 매개변수 비전 LLM으로, Apache 2 라이선스를 적용함
- 27B급은 적절한 사양의 노트북에서 실행하기 좋은 크기이며, 이전 모델 Qwen 3.6 27B도 인상적인 성능을 보였음
- Qwen의 자체 벤치마크에서는 Qwen 3.6 27B뿐 아니라 폐쇄형 가중치 모델 Qwen 3.7-Plus보다도 향상된 결과를 기록함
  - Qwen 3.7-Plus는 같은 해 5월까지 Qwen의 모든 크기 모델 중에서도 강력한 축에 속했음
  - 다만 자체 측정치이므로 독립 벤치마크를 통한 확인이 남아 있음
- 테스트에는 128GB M5 Max MacBook Pro와 NVIDIA DGX Spark를 사용함
xhigh 기본값이 일으키는 과잉 추론
- Qwen 3.8은 비용과 추론 깊이를 조절하는 reasoning_effort 를 공식 지원함
  - xhigh : 복잡하고 철저한 분석이 필요한 작업용이며 기본값으로 설정됨
  - medium : 정확도와 속도의 균형을 맞춤
  - low : 속도와 비용을 우선하는 효율적 추론에 적합함
- LM Studio GGUF도 xhigh 를 기본값으로 유지해, 소비자용 하드웨어에서는 단순 작업까지 장시간 추론하는 문제가 생김
- LM Studio의 기본 8,192토큰 문맥 한도는 평범한 문제를 추론하는 것만으로 소진됐으며, 최대 문맥인 262,144토큰으로 확장한 뒤에야 중단되지 않았음
- 
자전거를 타는 펠리컨 SVG
  - 문맥을 확장한 첫 시도에서 만든 자전거를 타는 펠리컨 SVG는 추론 22,276토큰과 출력 3,223토큰을 사용했고 총 21분이 걸림
  - 로컬 모델로 생성한 펠리컨 SVG 중 가장 우수한 결과였음
    - 자전거 프레임 형태가 정확함
    - 자전거 양쪽에 다리가 하나씩 배치됨
    - 펠리컨의 목주머니가 분명함
    - 날개가 핸들까지 닿음
    - 움직임 선이 대상 앞이 아니라 뒤에 있음
    - 해·구름·언덕·꽃·풀이 포함된 배경도 자연스러움
  - 품질은 높았지만 21분의 대기 시간을 정당화할 정도는 아니었음
  - 같은 프롬프트에서 추론을 끄자 결과는 3,715토큰을 출력하고 137초 만에 완성됨
  - OpenRouter를 통해 더 큰 Qwen 3.8 2.4T-A95B에도 같은 프롬프트를 실행해 애니메이션 SVG를 생성함
- 
원 하나에도 불필요한 디자인을 추가
  - draw an svg of a circle 이라는 단순 요청에도xhigh 는 단일<circle> 대신 기하학적 구성, 동심원, 눈금, 그라데이션, 회전 점선, 발광 효과, 애니메이션과 색상표를 장시간 검토함
  - 몇 분 뒤 완성된 애니메이션 원은 아름다웠지만 요청 범위를 벗어남
  - 처음부터 기본값을 무시하고 low 또는 추론 비활성화로 실행하는 방식이 권장됨
사진 속 경계 상자 인식
- 비전 성능을 평가하기 위해 사진 속 펠리컨을 찾아 각 차원의 좌표를 0~1000 척도로 반환하도록 요청함
- Qwen 3.8 27B가 생성한 JSON은 실제 사진 속 두 펠리컨과 매우 정확하게 일치함
[
  {"bbox_2d": [195, 290, 370, 780], "label": "pelicans"},
  {"bbox_2d": [445, 320, 675, 850], "label": "pelicans"}
]
- 실행에는 이미지 첨부를 지원하는 llm 명령과 LM Studio의qwen/qwen3.8-27b 모델을 사용함
경계 상자 시각화 도구 생성
- Qwen 3.8 27B는 노트북에서 오프라인으로 실행되면서, 경계 상자를 이미지 위에 표시하는 전체 HTML 인터페이스를 단일 프롬프트로 생성함
- 요구 사항은 다음과 같았음
  - 이미지 URL 입력창과 경계 상자 JSON 입력용 텍스트 영역을 제공함
  - 이미지를 페이지에 추가하고 실제 너비와 높이를 측정함
  - 0~1000 좌표를 실제 이미지 크기에 맞춰 변환함
  - 변환된 위치에 레이블이 붙은 상자를 렌더링함
- 추론 강도를 낮추지 않아 요청보다 훨씬 복잡한 도구가 만들어졌고, 요구하지 않은 자체 데모 장면까지 포함됨
  - 외부 이미지 없이 기능을 시연하고자 1000×1000 캔버스에 하늘·태양·물과 두 마리의 펠리컨 모양을 그림
  - 예시 JSON의 경계 상자 위치에 맞춰 펠리컨 실루엣을 배치한 뒤 데이터 URL 이미지로 변환함
  - 프롬프트의 "pelicans" 레이블만으로 이 기능을 자발적으로 추가함
- 추론을 끄고 만든 다른 버전은 거의 작동했지만 상자 위치가 잘못됨
- 후속 프롬프트로 수정할 수 있겠지만, 이 사례에서는 일정 수준의 추론이 한 번에 작동하는 도구를 만드는 데 차이를 보였음
로컬 코딩 에이전트 구동
- 로컬 모델이 코딩 에이전트 루프를 실행하려면 긴 문맥, 강한 코드 생성, 안정적인 도구 호출이 필요하며 Qwen 3.8 27B는 세 조건을 모두 지원함
- 초기 실험에는 시스템 프롬프트가 비교적 짧아 소형 모델에 유리한 Pi를 사용함
- DGX Spark의 LM Studio를 tailscale serve 로 공유하고~/.pi/agent/models.json 에 OpenAI Responses 호환 제공자를 등록함
  - 모델 ID를 qwen3.8-27b 로 지정함
  - "reasoning": true 를 설정함
- Datasette 저장소에서 how does auth work? 라고 요청하자 여러 파일을 읽는 추론·도구 호출 과정을 거쳐 인증 구조를 충실하게 분석함
- 이어 Pi 세션의 JSONL 대화를 Markdown으로 공유할 수 있도록 변환 코드 작성을 요청함
속도와 다중 토큰 예측
- 17GB 모델로 코드 작성, 도구 실행, 이미지 주석과 일반 작업을 처리할 수 있지만 추론 속도가 큰 제약으로 남음
- LM Studio에서 측정한 생성 속도는 초당 약 15~30토큰이었음
  - 사용할 수 없는 수준은 아니지만 호스팅 API 모델보다 체감상 느림
  - Artificial Analysis 측정치는 OpenAI 5.6 Sol이 초당 74토큰, 5.6 Luna가 초당 184토큰임
- Qwen은 저렴한 메커니즘이 여러 후속 토큰을 예측하고 본 모델이 이를 빠르게 검증하는 다중 토큰 예측(Multi-Token Prediction)을 지원함
- DGX Spark에서는 llama.cpp 의 MTP 추측 디코딩을 다음과 같이 활성화함
llama serve \
 -hf  ggml-org/Qwen3.8-27B-GGUF:Q4_K_M \
 -hfd ggml-org/Qwen3.8-27B-GGUF:Q4_0 \
 --spec-default \
 --spec-type draft-mtp \
 --reasoning-preserve
- GPT-5.6을 Codex에서 사용한 비교 벤치마크에서는 --spec-type draft-mtp 서버가 LM Studio 기본 GGUF보다 약 72% 빠른 성능을 냄
- 모델 공개 이틀 만에 커뮤니티가 다양한 최적화를 탐색하기 시작했으며, 향후 llama.cpp 와 MLX 생태계에서 추가 속도 개선을 기대할 수 있음
로컬 모델이 보여준 가능성과 한계
- Qwen 3.8 27B는 17GB 파일 하나로 개인 장비에서 긴 문맥, 도구 호출, 비전 처리와 코드 생성을 제공함
- 1년 전에는 최고 수준의 독점 모델과 경쟁했을 기능을 이제 성능이 좋은 노트북에서 실행할 수 있음
- 일상적인 주력 모델이 되기 어려운 핵심 제약은 M5 Mac과 DGX Spark 모두에서 체감되는 속도임
  - Qwen 3.8 27B는 MoE가 아닌 밀집형 모델이어서 높은 성능을 내려면 많은 메모리 대역폭이 필요함
  - 테스트한 두 장비 모두 메모리 대역폭 측면에서 최상급 장비는 아님
- 이 크기의 모델은 빠르게 발전하고 있으며, 유능한 범용 모델을 실행하는 데 데이터센터급 하드웨어 비용으로 50만 달러를 지출할 필요가 없음을 보여줌

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.
- 웹 미리보기는 페이지당 최대 20개 메시지씩, 최대 10페이지(최근 약 200개)까지만 페이지네이션한다.
- 이미지, 동영상 등 미디어 전용 메시지(텍스트 없음)는 캡처하지 않는다.
- 메시지에 포함된 기사 링크(최대 메시지당 3개, 유튜브/X/인스타그램/페이스북 제외)는 본문을 함께 가져와 아래 '첨부 기사 원문'에 붙인다 - 실패하면 그 링크만 오류로 표시된다.

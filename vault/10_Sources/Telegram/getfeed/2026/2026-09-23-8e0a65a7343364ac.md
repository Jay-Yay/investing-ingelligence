### Kev - 직접 학습하고 실행할 수 있는 Jev 방식의 의사결정 모델 | GeekNews

(https://news.hada.io/topic?id=34065)

- Qwen3.5를 기반으로, 긴 답변을 생성하는 대신 예/아니요 확률, 선택지별 확률과 평가 점수를 반환하는 의사결정 모델
- 고객 문의 하나에서 담당 부서, 긴급 대응 여부, 고객의 불만 정도를 함께 판단할 수 있으며, 각 질문은 다른 질문의 내용에 영향을 받지 않도록 분리됨
- 0.8B, 4B, 9B 모델의 가중치와 학습 코드, 평가 데이터를 공개해, 필요한 정확도와 메모리 여유에 따라 선택 가능
- CUDA와 Apple Silicon에서 실행하며, TypeSafe System One 호환 API를 제공해 기존 Python SDK의 연결 주소를 로컬 서버로 바꿔 사용 가능
- 공개 모델을 출발점으로 자체 분류 기준과 업무 규칙에 맞게 추가 학습할 수 있으며, 수백 개의 정답 예제로 미세조정하고 별도 데이터로 평가하는 절차 제공
답변 대신 선택지와 확률을 반환
- Kev는 Jev's Architecture Unmasked의 구조를 바탕으로 Qwen3.5에 구축한 의사결정 모델로, 공개 가중치를 그대로 사용하거나 자체 데이터로 추가 학습할 수 있음
- 긴 문장을 생성하는 대신 주어진 선택지를 평가하고 확률과 점수를 반환하며, 한 요청에서 세 가지 질문 유형을 함께 처리함
  - 예/아니요: 긴급한 사람의 대응이 필요한지 등을 확률로 판단
  - 객관식 선택: 문의를 담당할 부서처럼 여러 선택지 중 적절한 항목을 선택
  - 점수 평가: 고객의 불만이나 요청의 긴급도를 지정한 척도로 평가
- 하나의 라벨뿐 아니라 선택지별 확률을 받으므로, 여러 문제가 섞인 입력도 구분해 볼 수 있음
  - 배송 지연, 잘못된 사이즈, 중복 결제가 함께 있는 고객 문의 예시에서는 반품 47%, 배송 28%, 결제 25%를 반환함
  - 같은 문의에서 긴급 대응 필요성과 고객 불만 정도도 함께 평가함
- TypeSafe System One API와 호환돼, 공식 Python SDK의 연결 주소를 로컬 서버로 바꿔 사용 가능
입력은 공유하되 질문은 독립적으로 처리
- 모델은 Qwen 위에 LoRA 어댑터와 선택지를 평가하는 작은 포인터 헤드를 추가한 구조
  - 기반 모델의 가중치는 고정하고 어댑터와 헤드만 학습함
  - Jev가 생성한 답변은 학습에 사용하지 않음
- 각 질문은 공통 입력과 자신의 질문만 읽으며, 다른 질문의 내용은 읽지 못하도록 분리됨
  - Qwen3.5에서는 질문마다 독립된 입력을 구성하고, 공통 입력의 계산 결과를 캐시해 재사용함
  - ‘담당 부서’ 질문에 무엇을 적었는지가 ‘고객 불만 정도’ 질문에 섞이지 않도록 하는 방식
- 포인터 헤드가 각 선택지의 점수를 계산하고 이를 확률로 변환하므로, 답변 문장을 한 토큰씩 생성할 필요가 없음
- 질문을 함께 보낼 때와 따로 보낼 때의 결과는 테스트에서 거의 같았지만, 한 질문 안의 선택지 순서에 따라 답이 달라질 수는 있음
자체 업무 데이터로 추가 학습
- 공개 모델은 10개 공개 데이터셋의 사례 1만 개와 생성한 정책/규칙 사례를 학습함
- 회사마다 다른 문의 분류 체계, 담당자에게 넘기는 기준, 사용하는 언어에 맞춰 수백 개의 정답 예제로 미세조정할 수 있음
  - API 요청과 같은 형식에 정답을 추가하고, 데이터의 10~20%는 평가용으로 남기는 방식
- 기반 Qwen 모델부터 새로 학습하기보다 공개 Kev 모델에서 이어서 학습하면 기존 판단 능력을 유지하면서 새 업무에 적응시킬 수 있음
  - 지원 도구 의사결정 836개를 사용한 한 실험에서는 기존 평가 정확도 83%를 유지하면서 새 업무에서 88%를 기록함
  - 같은 데이터로 기반 모델부터 학습했을 때는 기존 평가 정확도가 33%로 낮아졌음
- H100 한 대에서 공개 학습 절차를 실행하면 0.8B는 약 20분, 4B는 약 1시간이 걸림
- 0.8B 모델은 설정을 조정하면 4GB GPU에서도 미세조정 가능
- 학습 설정과 데이터셋, 실험 이력은 모델 카드와 PLAN.md에 공개돼 있음
모델 선택과 실행 환경
- Kev-4B가 기본 선택이며, 정확도를 더 중시하면 Kev-9B, 메모리를 줄이려면 Kev-0.8B를 선택할 수 있음
- CUDA와 Apple Silicon에서 실행하며, 4B와 9B는 bf16 형식으로 32GB Mac에 올릴 수 있음
- CUDA에서는 최적화된 커널을 사용해 H100에서 질문 5개를 수십 밀리초에 처리
- Apple Silicon에서는 Qwen3.5의 DeltaNet용 고속 커널이 없어 실행 속도가 더 느림
  - M5에서 약 230토큰 입력과 질문 5개를 처리한 모델 실행 시간은 0.8B 329ms, 4B 779ms, 9B 약 2초
  - Mac에서 낮은 지연 시간이 중요하면 이전 Qwen3 기반 모델을 권장하며, Qwen3.5용 MLX 백엔드는 개발 예정
- 가중치는 Hugging Face 컬렉션과 GitHub 릴리스에서 제공
공개 평가와 실제 적용 시 확인할 점
- 학습에 사용하지 않은 데이터셋과 정책 규칙의 개발 세트에서 Kev-9B는 정확도 82.2%, Jev는 85.7% 를 기록함
  - Jev의 학습 데이터는 알려져 있지 않으므로, 두 아키텍처의 우열만을 가리는 통제된 비교는 아님
- 외부 평가에서는 작업에 따라 결과가 달라짐
  - SemIf의 의사결정 144개에서는 Kev-9B 91.7%, Jev 96.5%
  - 지원 티켓 900개 평가의 담당 부서 분류에서는 Kev-9B 95.2%, Jev 89.7%
- 정확도뿐 아니라 확률이 실제 정답률과 얼마나 맞는지, 허용 오류율 안에서 얼마나 많은 판단을 자동화할 수 있는지도 평가함
- 새 데이터에서는 틀린 답에 높은 확률을 줄 수 있으며, API의 confidence 도 실측 정확도를 뜻하지 않음
  - 자동 처리와 사람의 확인을 나누는 기준은 자체 업무 데이터로 검증해야 함
  - 지식 질문과 날짜 계산, 긴 문맥은 별도로 확인할 필요가 있음
직접 시험할 수 있는 도구와 공개 범위
- 웹 플레이그라운드에서 입력과 질문을 바꿔 실행하고, 여러 질문을 함께 처리한 결과와 개별 처리한 결과를 비교할 수 있음
- 선택지 순서를 바꿔 답이 얼마나 달라지는지 확인하는 기능과 질문 격리 테스트도 제공
- 체스판을 입력으로 넣고 가능한 수를 선택지로 평가하는 체스 데모도 포함
- 로컬 API 서버에는 인증이 없으므로, 외부에 공개하려면 별도 인증을 추가해야 함
- 코드와 모델은 Apache-2.0 라이선스이며, 학습 데이터셋에는 각각 별도 라이선스가 적용됨

### GitHub PR에 급증한 ‘Claude 같은’ 문체 - 46만 건의 어휘 변화 분석 | GeekNews

(https://news.hada.io/topic?id=32970)

- GitHub 풀리퀘스트 46만 건을 어휘만으로 분류했더니, 2025년 초 0.7%에 불과했던 새로운 문체 집단이 2026년 중반 약 39%까지 증가함
- 이 집단에는 load-bearing ,plainly ,quietly ,seam ,byte-identical ,root-caused ,fail-loud 처럼 코딩 에이전트 사용자에게 익숙한 표현이 함께 등장함
- 대표 단어 load-bearing 은 848개 계정이 작성한 905개 PR에서 1,011번 사용됐으며, 해당 집단에서 나머지 PR보다 39.47배 높은 빈도를 보임
- 분석은 Claude 사용 여부를 확인하거나 AI 문체를 미리 정의하지 않고 단어 분포만으로 수행했으므로, Claude가 작성한 PR의 비율이나 개별 PR의 작성 주체를 판별하는 도구는 아님
- 흥미로운 점은 특정 단어 하나보다 여러 계정에서 같은 어휘 조합이 동시에 확산된 현상이며, AI가 사람의 개발 문체까지 바꾸고 있을 가능성을 보여줌
2026년에 나타난 새로운 PR 문체
- 2025년 1월부터 수집한 GitHub PR 설명을 사용된 단어의 분포에 따라 10가지 문체 집단으로 분류함
- 어떤 표현을 찾으라고 미리 지정하거나 Claude가 작성한 문장을 학습 데이터로 제공하지 않음
- 그중 한 집단의 비중이 다음과 같이 빠르게 증가함
  - 2025년 초 전체의 약 0.7%
  - 2026년 중반 약 39%
  - 최근 한 달에는 사람이 작성자로 표시된 PR의 약 40%
- 최근 12주 동안에도 일주일에 평균 1.2%포인트씩 증가하는 추세
- 여기서 ‘사람이 작성자로 표시된 PR’은 봇 계정을 제외했다는 뜻이며, 사람이 직접 문장을 작성했다는 의미는 아님
  - 개인 계정에서 Claude Code 같은 에이전트가 만든 PR도 포함될 수 있음
load-bearing과 그 주변의 어휘
- 새로 증가한 집단을 가장 잘 대표하는 단어는 load-bearing
- 전체 데이터에서 다음과 같이 사용됨
  - 1,011회 등장
  - 905개 PR 설명
  - 848개 서로 다른 계정
- 이 가운데 929회가 새 문체 집단 안에서, 82회가 나머지 집단에서 발견됨
- 각 집단의 전체 단어 수 차이를 보정하면 load-bearing 은 이 집단에서 39.47배 자주 등장함
- 함께 나타나는 대표 표현
  - plainly ,quietly ,genuinely ,deliberately
  - seam ,chokepoint ,backstop ,blast-radius
  - byte-identical ,bit-for-bit ,byte-stable
  - mutation-checked ,re-verified ,cross-checked
  - root-caused ,self-heals ,fail-loud ,fail-soft
  - survived ,refuses ,proved ,falsified
- 단순한 기술 용어 목록이라기보다 코드의 의도와 검증 결과를 단정적이고 서사적으로 설명하는 표현이 함께 묶여 있음
매일 GitHub PR 1,000개를 표본 조사
- GitHub Search API에서 하루를 2.4시간씩 나눈 10개 구간마다 무작위 5분을 선택함
- 각 시간대의 PR 설명을 최대 100개씩 가져와 하루 약 1,000개를 수집하고 GitHub Actions로 매일 갱신함
- 현재 분석 규모
  - 완전한 85주, 총 595일
  - PR 설명 461,121개
  - 단어 약 5,108만 개
- 검색 API가 한 요청에 반환하는 결과 수가 제한돼 해당 시간대의 모든 PR을 조사하지는 못함
  - GitHub 활동이 많을 때는 5분 구간에서도 앞쪽 100개만 가져오는 표본 조사
  - 시간대를 하루 전체에 고르게 배치해 특정 시각에 데이터가 몰리는 현상을 줄임
자동 생성과 반복 문장을 줄이는 방법
- 로그인 이름이 [bot] 이나-bot 으로 끝나는 계정과copilot , Dependabot·Renovate·GitHub Actions 계열 앱을 제외함
- 같은 주에 단어 구성이 완전히 같은 PR 설명은 하나만 남김
- 한 계정이 한 주의 분석에 기여할 수 있는 설명을 최대 3개로 제한함
  - 사람처럼 보이는 계정에서 대량 생성된 텍스트가 결과를 지배하는 것을 줄이기 위한 조치
- 최소 50개의 서로 다른 계정이 사용한 단어만 분석 대상에 포함함
  - 소수 계정이 반복해서 사용한 프로젝트 전용 표현을 대표 어휘로 잘못 판단하지 않기 위한 기준
- 남은 PR을 단어 분포 사이의 차이를 측정하는 KL-divergence k-means로 10개 집단에 배정함
이 결과가 증명하지 않는 것
- 제작자는 HN에서 “Claude의 말버릇을 추적하는 것이 아니다” 라고 명확히 밝힘
- Claude 사용 여부가 표시된 정답 데이터가 없기 때문에 다음 사항은 알 수 없음
  - 어떤 PR을 Claude가 작성했는지
  - Claude와 다른 코딩 에이전트 중 어느 모델의 영향인지
  - 사람이 에이전트의 표현을 받아들여 직접 쓴 것인지
  - 문체 변화가 AI 사용 때문에 발생했다고 단정할 수 있는지
- 집단 수를 10개로 정한 결정도 결과를 살펴본 뒤 이 문체가 다른 주제와 섞이지 않는 범위에서 선택됨
- 따라서 최근 PR의 40%를 Claude가 작성했다는 통계가 아니라, 최근 PR의 약 40%가 Claude 사용자에게 익숙한 어휘 분포를 공유한다는 관찰로 읽어야 함
HN에서 나온 해석
- 여러 사용자가 load-bearing 과seam 을 Claude가 코드와 문서를 설명할 때 지나치게 반복하는 표현으로 알아봄
- 반면 seam 은 LLM보다 훨씬 이전의 리팩터링·소프트웨어 공학 문헌에서도 사용됐다는 지적이 나옴
  - 개별 단어의 존재보다 여러 표현이 함께 나타나고 사용 비중이 급증한 현상이 더 중요함
- unit-tested ,re-verified ,provably 같은 단어는 Claude 고유의 어휘라기보다 에이전트가 자신의 작업을 정당화하고 검증 결과를 보고하도록 훈련된 결과일 수 있다는 의견도 있음
- 사람도 LLM과 대화하면서 표현 방식과 문장 구조를 학습하므로, 앞으로는 AI가 사람의 글을 닮는 동시에 사람이 AI의 문체를 받아들이는 순환이 나타날 수 있다는 논의로 이어짐

### Meta Muse Glimmer - 기기에서 실행하는 오픈 웨이트 30B 코딩 모델 | GeekNews

(https://news.hada.io/topic?id=32362)

- Meta가 30B 파라미터 로컬 에이전트 모델 Muse Glimmer를 Apache 2.0 라이선스로 공개했으며, 단일 소비자용 GPU를 장착한 Mac이나 PC에서 실행하도록 최적화함
- 대형 교사 모델의 에이전트 추론을 전이하는 로짓 증류와 장문맥 중간 학습, 지도 미세조정·온정책 증류·강화학습을 조합해 제한된 메모리·연산 성능에 대응함
- 함수 호출과 장기 다단계 추론, 도구 오류 복구, 코드 작성·디버깅, 텍스트·이미지 처리를 지원하며 100개가 넘는 언어의 데이터로 학습함
- 완전 정밀도에서 55GB 이상 필요한 모델을 약 4비트·20GB 미만으로 양자화하고, DFlash 기반 추측 디코딩으로 출력 품질을 유지하면서 생성 속도를 높임
- 가중치는 Hugging Face에서 받을 수 있으며, llama.cpp·MLX·ExecuTorch와 Ollama·LM Studio·Unsloth 등 로컬 실행 생태계의 지원도 순차적으로 추가될 예정임
소비자용 하드웨어를 겨냥한 로컬 에이전트
- Muse Glimmer는 Meta Superintelligence Labs가 공개한 30B 파라미터 모델로, 상시 실행되는 로컬 에이전트 워크플로에 최적화됨
  - 단일 소비자용 GPU를 탑재한 Mac이나 PC에서 실행할 수 있음
  - 로컬 에이전트, 함수 호출, 코딩, LLM 심사자 평가에 활용 가능함
  - Apache 2.0 라이선스로 오픈 웨이트를 제공함
- 클라우드와 네트워크에 의존하지 않고 어디서나 AI를 사용할 수 있도록 설계했으며, 표적 작업에서 소형 모델의 성능을 높이는 학습 방식을 적용함
- 모델 가중치와 개발자 문서를 함께 공개함
- llama.cpp, MLX, ExecuTorch용 최적화 통합은 공개 후 며칠 내 제공될 예정임
에이전트 성능을 만드는 학습 과정
- 개인 일정·메시지·파일을 다루는 에이전트에는 장기 실행과 정확한 도구 호출, 멀티모달 이해, 장문맥 기억, 지시 준수가 함께 필요함
- 로컬 하드웨어의 메모리·연산 제약에 맞추기 위해 소형 아키텍처, 대형 교사 모델의 에이전트 추론을 전달하는 증류 방식, 양자화를 포함한 추론 최적화를 사용함
- 학습은 세 단계로 진행됨
  - 사전 학습: 교사 모델과 유사한 데이터 구성을 사용하고 Muse Spark 출력에 로짓 증류를 수행함
  - 중간 학습: 자연 발생 데이터와 함께 더 긴 문맥, 에이전트 중심 데이터, 풍부한 추론 실행 추적을 학습함
  - 후속 학습: 일반·추론·코딩·에이전트 영역에서 지도 미세조정, 온정책 증류, 강화학습을 조합함
- Meta Advanced AI Scaling Framework 기준으로 평가하고, 관련 범주 전반에서 오픈 웨이트 공개 적합성을 검토함
작업 수행과 도구 사용
- 종단 간 작업 수행 능력을 DeepSearch QA, MCP-Atlas, 𝛕-Bench, SWE-Bench로 평가함
  - 에이전트 스캐폴드 안에서 작업함
  - 코드를 작성하고 디버깅함
  - 여러 차례 이어지는 요청을 처음부터 끝까지 해결함
- 장시간 워크플로에서도 명세에 맞춰 여러 종류의 함수를 호출하도록 훈련함
- 복잡하고 긴 작업에서 일관된 계획을 유지하며 다단계 추론을 이어갈 수 있음
- 도구 호출이 실패하거나 예상하지 못한 결과를 반환하면 중단하지 않고 오류를 진단한 뒤 다시 시도함
- 전용 인지 인코더를 통해 텍스트와 이미지가 섞인 입력을 받고, 스크린샷·차트·문서를 대화와 함께 해석함
- OpenClaw를 비롯한 여러 에이전트 오케스트레이션 패턴과 호환됨
- 품질과 속도의 균형에 따라 서로 다른 추론 강도를 선택할 수 있음
- 100개가 넘는 언어의 데이터로 학습함
동급 모델과의 벤치마크 비교
- 자율 에이전트에 필요한 다양한 능력을 폭넓은 벤치마크에서 평가함
- 같은 크기 범주의 Gemma4-31B, Qwen3.6-27B와 비교해 여러 주요 LLM 벤치마크에서 강한 성능을 기록함
- 구체적인 평가 방식과 결과는 방법론 보고서에서 확인할 수 있음
20GB 미만으로 줄인 양자화 모델
- 완전 정밀도의 30B 모델은 55GB 이상 메모리가 필요해 소비자용 GPU에서 실행하기 어려움
- 가중치를 약 4비트 정밀도로 양자화해 언어 모델 크기를 20GB 미만으로 줄임
- 24GB 또는 32GB 메모리 안에서 다음 구성 요소를 함께 실행할 공간을 확보함
  - 모델 작업 메모리인 KV 캐시
  - 이미지 이해용 인지 인코더
  - 추측 디코딩용 초안 모델
- 양자화에 따른 에이전트 작업 성능 저하는 최소 수준이거나 관측되지 않았다고 평가함
DFlash로 생성 속도 향상
- 일반적인 언어 모델은 토큰을 하나씩 생성하므로 긴 추론이나 다단계 도구 호출에서 응답이 느려질 수 있음
- Muse Glimmer는 DFlash 기반의 경량 초안 모델을 함께 제공함
  - 초안 모델이 여러 토큰으로 구성된 블록을 한 번에 제안함
  - 주 모델은 제안을 병렬로 검증해 올바른 토큰을 수락하고 잘못된 토큰을 수정함
- 표준 토큰 단위 생성보다 속도를 크게 높이면서 동일한 출력 품질을 유지함
- 추가 메모리 사용량을 줄이기 위해 양자화된 초안 모델도 제공함
- K-Quant-17GB 모델과 양자화된 DFlash 초안 모델의 속도를 MacBook M4 Max·M5 Max와 RTX 5090에서 측정했으며, 기기 내에서 유연한 대화와 실시간 에이전트 상호작용이 가능한 수준임
로컬 실행부터 대규모 배포까지
- Muse Glimmer 가중치는 현재 Hugging Face에서 내려받을 수 있음
- 공개 후 며칠 내 다음 도구와 서비스에서 지원할 예정임
  - 로컬 실행: Ollama, LM Studio, Unsloth
  - 엣지 프레임워크: llama.cpp, ExecuTorch, MLX
  - 대규모 서빙: vLLM, SGLang
  - 호스팅 서비스: Together AI, Fireworks AI, OpenRouter
- PyTorch의 TorchTitan 학습 기능으로 용도에 맞게 모델을 추가로 맞춤화할 수 있음
- AMD, Arm, Dell, Intel, NVIDIA와 협력해 여러 기기에서 성능을 최적화하고 있음
- Meta AI Developer Center에서 사용자 정의 스캐폴드 설정과 개인 에이전트 구축·배포 자료를 제공함

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.

- 메시지에 포함된 기사 링크(최대 메시지당 3개, 유튜브/X/인스타그램/페이스북 제외)는 본문을 함께 가져와 아래 '첨부 기사 원문'에 붙인다 - 실패하면 그 링크만 오류로 표시된다.

### 모든 CEO가 알아야 할 AI 거버넌스 | GeekNews

(https://news.hada.io/topic?id=33213)

- AI가 의료·금융·운영 의사결정에 영향을 미치면서 결과의 무결성을 책임지는 AI 거버넌스는 법무·IT·CISO에게만 맡길 수 없는 CEO와 이사회의 책임이 되고 있음
- 기존 보안이 데이터의 무단 접근을 막았다면, AI 거버넌스는 오염되거나 불법적으로 취득한 데이터가 모델의 판단에 영향을 주는 무단 영향(unauthorized influence) 까지 다뤄야 함
- 조직은 기존 CIA 분류에 SCC(민감도·중요도·규정 준수) 를 더하고, 데이터가 모델을 학습시키기 전에 출처·처리 과정·변경 이력을 입증해야 함
- AI 관리 연속성(chain of custody)은 출처 식별, 보유 기록, 변조 증거, 무결성 검증, 접근 로그, 기록 보존이라는 6개 원칙으로 데이터부터 모델과 결정까지 연결함
- CEO와 이사회는 책임자 지정, 기존 시스템 감사, 사용 정책, AI 보안, 독립 감사, 윤리 체계, 공급업체 계약을 점검하고 규제가 확정되기 전에 검증 가능한 신뢰를 구축해야 함
AI가 이사회 책임이 된 이유
- 기업은 AI 위험을 법무의 규정 준수, IT의 시스템 운영, CISO의 보안 문제로 나누는 경우가 많지만, AI 거버넌스는 여러 분야를 아우르는 경영진의 책임임
- 전통적인 사이버보안은 데이터를 저장·처리하는 시스템을 전제로 무단 접근을 차단하고 경계를 보호하며 기록을 온전하게 유지함
- 머신러닝 모델은 학습 데이터를 그대로 저장하지 않고 그 통계적 패턴을 수백만 개의 매개변수에 흡수함
  - 원본 입력은 보이지 않게 되지만 영향은 남음
  - 데이터가 오염·편향됐거나 불법 취득 또는 부적절하게 처리됐다면 문제가 모델 출력과 자동화된 결정에 내재함
- AI는 이미 의료 진단, 신용 승인, 사기 탐지, 재무 공시에 쓰이지만 결과가 만들어진 과정을 증명할 거버넌스 기반은 부족한 경우가 많음
- AI 출력은 불투명한 기술 산출물이 아니라 조직의 의사결정에 쓰이는 기관 지식 자산이 되며, 훼손될 경우 이사회의 주의 의무와 충실 의무에 직접 영향을 줄 수 있음
- FTC, SEC, HHS와 EU AI Act의 규제 압력이 커지면서 데이터 출처와 모델 구축 과정을 증명하는 능력이 모범 사례를 넘어 법적 요건으로 이동하고 있음
- AI 거버넌스를 규정 준수 체크리스트로만 다루면 대비가 부족함
  - 관리 연속성을 인프라에 먼저 구축한 조직은 방어 가능하고 신뢰할 수 있는 시스템을 확보할 수 있음
전통적인 보안 모델의 한계
- 기존 위협 모델은 공격자가 데이터를 훔치거나 변경하거나 접근을 차단한다는 전제 아래 접근 제어·암호화·로깅·사고 대응으로 위험을 다룸
- AI의 핵심 위험은 데이터 도난보다 오염되거나 불법 취득된 데이터가 모델 행동에 미치는 미세한 영향임
  - 문제의 중심이 시스템 경계가 아니라 학습 파이프라인에 있음
  - 배포 후에는 영향이 수백만 개의 매개변수에 분산되므로 재학습 없이 되돌리기 어려움
- AI 보호에는 보안 통제뿐 아니라 출처 통제가 필요함
  - 누가 데이터에 접근했는지만 확인해서는 부족함
  - 데이터 출처와 취급자, 변환 과정, 훼손 여부까지 증명할 수 있어야 함
- 이러한 검증 책임은 CISO의 범위를 넘어 이사회와 경영진까지 이어짐
CIA를 보완하는 SCC 데이터 분류
- 전통적인 CIA 삼요소인 기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)은 여전히 필요하지만 AI 시스템을 관리하기에는 충분하지 않음
- AI에서는 데이터를 보호할 수 있는지뿐 아니라 그 데이터가 지능형 시스템에 영향을 주도록 사용돼도 되는지를 판단해야 함
- 이를 위해 세 가지 SCC 차원을 추가함
  - 민감도(Sensitivity): 오용이 개인·고객·지식재산·기업에 미칠 피해를 평가하며 개인정보 보호와 윤리·평판 영향까지 포함함
  - 중요도(Criticality): 데이터가 중대한 AI 결정에 얼마나 큰 영향을 줄 수 있는지 평가함
    - 의료 진단, 사기 탐지, 재무 보고, 안전 시스템의 데이터에는 저위험 생산성 도구보다 강한 관리가 필요함
  - 규정 준수(Compliance): 수집·보존·변환·사용을 제한하는 법률, 계약, 규제, 라이선스를 확인함
    - 모델 학습, 미세 조정, 검색 시스템, 자율 에이전트에 합법적으로 사용할 수 있는지도 판단해야 함
- SCC는 CIA를 대체하지 않고 보완하며, 어떤 데이터가 기계의 추론을 형성하도록 신뢰받는지까지 관리 범위를 넓힘
- 이사회는 데이터가 학습 파이프라인, 검색 아키텍처, 프로덕션 AI에 투입되기 전에 경영진이 SCC 기준으로 분류하도록 요구해야 함
AI 관리 연속성의 작동 방식
- 관리 연속성은 법정 증거가 수집부터 제출까지 모든 이전·취급자·보관 조건을 끊김 없이 기록해야 한다는 법률·포렌식 원칙에서 출발함
- AI에서는 데이터가 학습되기 전에 관리 연속성을 확립해야 함
  - 학습 후에는 신경망을 역으로 감사해 데이터 계보를 복원하기가 급격히 어려워짐
- 목표는 데이터, 모델, 의사결정을 검증 가능한 기록으로 연결해 법적 증거 수준의 기반을 만드는 것임
- 
여섯 가지 기본 원칙
  - 식별 가능한 출처
    - 모든 데이터셋에 제공 조직, 취득일, 수집 방법, 라이선스 권리, 규제 분류를 기록해 출처를 검증할 수 있어야 함
  - 보유·취급 기록
    - 데이터 생명주기의 각 단계에서 접근자, 시점, 수행 작업, 영향을 받은 버전을 기록함
  - 변조 증거
    - 데이터셋 해시, 디지털 서명, 불변 스토리지 같은 암호화 기술로 무단 변경을 탐지하고 모든 수정이 기록에 남도록 해야 함
  - 무결성 검증
    - 변조 탐지에 그치지 않고 주기적 해시 검증, 학습 파이프라인 재현성 테스트, 버전 비교로 원본 상태와의 일관성을 확인함
  - 접근 제어 로그
    - 학습 데이터와 모델 산출물의 모든 상호작용을 사람 또는 기계의 신원, 타임스탬프, 작업 기록과 연결함
  - 보존
    - 데이터셋, 모델 설정, 학습 로그, 평가 결과의 과거 기록을 유지해 예상 밖 결과가 발생했을 때 모델 구축 과정을 재현할 수 있어야 함

이사회가 실행할 일곱 단계
- 
1단계, 명확한 AI 거버넌스 책임자 지정
  - AI 거버넌스를 CTO의 기존 업무에 부수적으로 추가하는 방식으로는 충분하지 않다고 봄
  - 데이터 출처 기준과 모델 수명 주기, AI 위험 보고를 담당할 명시적인 책임자를 지정해야 함
  - 책임자는 필요한 통제를 요구할 권한을 가지고 이사회에 AI 위험을 직접 보고할 수 있어야 함
  - 법무와 보안, 데이터, 제품, 규제 대응 조직을 연결하되 각 부서 사이에서 책임이 사라지지 않게 해야 함
- 
2. 기존 AI 시스템의 데이터 출처 감사
  - 중요한 결정에 영향을 주는 모든 AI 시스템을 먼저 목록화해야 함
  - 각 시스템에 대해 학습과 미세 조정, 검색에 사용한 데이터의 출처와 적법한 사용 권리를 확인함
  - 데이터 무결성이 검증됐는지, 수집부터 모델 사용까지의 취급 이력을 다시 구성할 수 있는지도 점검함
  - 출처나 권리를 알 수 없다는 답변은 단순한 기술 부채가 아니라 이사회에 공개해야 할 위험으로 취급함
  - 외부 모델 API를 사용하더라도 프롬프트와 RAG 데이터, 미세 조정 자료가 모델의 판단에 영향을 주므로 감사 범위에 포함해야 함
- 
3. AI 허용 사용 정책 검증
  - 조직은 어떤 데이터를 모델 학습에 사용할 수 있는지 명시적인 정책을 마련해야 함
  - 누가 학습과 미세 조정을 실행할 수 있고 어떤 외부 데이터 소스를 사용할 수 있는지도 정해야 함
  - 모델 출력이 추천으로만 사용되는지, 사람이 승인해야 하는지, 자동 의사결정에 사용할 수 있는지 구분함
  - 정책이 문서로 존재하는 것만으로는 충분하지 않으며 이사회가 검토하고 실제 기술 통제로 집행되는지 확인해야 함
  - 고위험 업무와 일반 생산성 업무에 같은 승인 절차를 적용하기보다 데이터 중요도와 영향에 따라 통제 수준을 다르게 설정할 수 있음
- 
4. 사이버보안 프로그램의 AI 대응 확인
  - 전통적인 경계 보안과 접근 통제만으로는 학습 데이터와 모델 행동을 겨냥한 공격을 다루기 어려움
  - CISO는 다음 위험을 기존 보안 프로그램에 포함해야 함
    - 데이터 오염과 승인되지 않은 학습 실행
    - 모델 조작과 적대적 입력
    - 에이전트의 신원과 권한
    - 모델과 에이전트의 예상하지 못한 행동
  - 보안팀이 모델을 직접 개발할 필요는 없지만, 학습 데이터와 모델 아티팩트, 에이전트 작업을 감사 가능한 신원과 권한 체계에 연결해야 함
  - AI 사고 대응에는 어떤 모델과 데이터가 영향을 받았는지 확인하고 이전 버전으로 복구하거나 재학습하는 절차도 필요함
  - CEO는 CISO에게 다음 열 가지를 물어야 함
    - AI 시스템을 학습시키거나 행동에 영향을 준 모든 데이터셋의 출처를 식별할 수 있는가
    - 현재 규제 대상이거나 중대한 사업 결정에 영향을 주는 AI 시스템은 무엇인가
    - 학습 데이터가 오염되거나 불법 변경되지 않았음을 어떻게 확인하는가
    - 어떤 외부 모델·데이터셋에 의존하며 출처에 관해 어떤 계약상 보장을 받는가
    - 원본 데이터셋, 설정, 학습 파이프라인으로 프로덕션 모델을 재현할 수 있는가
    - 기밀성 외에 민감도, 사업 중요도, 규제 의무를 기준으로 데이터를 어떻게 분류하는가
    - 무단 모델 학습, 미세 조정, 에이전트 생성을 막는 통제는 무엇인가
    - 규제 당국이 내일 AI 결정의 생성 과정을 요구하면 입증할 수 있는가
    - 전사 AI 거버넌스를 책임지는 경영진은 누구인가
    - 현재 조직의 가장 큰 AI 거버넌스 위험은 무엇인가
- 
5. 독립 감사와 데이터 추적성 확보

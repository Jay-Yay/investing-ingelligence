### Windows에서 AMD GPU로 CUDA 실행하기 | GeekNews

(https://news.hada.io/topic?id=33649)

- ZLUDA와 AMD HIP/ROCm을 조합해, NVIDIA CUDA용 Windows 프로그램을 AMD GPU에서 실행할 수 있도록 설치/진단/실행 스크립트를 제공하는 프로젝트
- GPU와 드라이버를 확인하고 필요한 구성 요소를 내려받은 뒤, 대상 프로그램에 호환 DLL과 실행 경로를 설정하는 과정을 자동화함
- Radeon RX 9060 XT에서 CUDA용 LibTorch를 사용하는 강화학습 모델의 추론과 학습을 실제로 완료했으며, 비공개 DLL 없이 공식 배포물만으로 재현할 수 있음
- 현재 검증된 GPU는 RX 9060 XT뿐이며, 다른 AMD GPU는 자동으로 감지되더라도 실제 실행까지 보장하지 않음
- 모든 CUDA 프로그램을 지원하는 것은 아니며, 검증 환경에서는 cuDNN을 사용할 수 없어 이를 요구하는 모델이나 일부 CUDA 확장은 동작하지 않을 수 있음
호환성 구조와 검증 범위
- CUDA for AMD on Windows는 CUDA 대상 Windows 연산 애플리케이션을 위한 재현 가능한 환경이며, CUDA 지원 LibTorch를 사용하는 워크로드도 포함함
- 실행 경로는 ZLUDA가 CUDA 대상 애플리케이션과 AMD GPU 사이의 호환 계층을 담당하는 구조임
  - CUDA 애플리케이션 → ZLUDA → cuBLAS/cuSPARSE/cuFFT 호환 계층 → rocBLAS/hipBLASLt/rocSPARSE/HIP → AMD GPU로 이어짐
- 현재 검증 기준 장치는 Radeon RX 9060 XT, 아키텍처는 gfx1200 /RDNA4임
  - 스캐너가 다른 Windows HIP 아키텍처 계열을 인식해도 미검증 후보로 분류하며, 장치 감지가 워크로드 실행을 입증하지는 않음
  - AMD의 Windows 하드웨어 범위는 공식 시스템 요구사항에서 확인할 수 있음
공식 배포 구성으로 완료한 학습 검증
- 비공개 DLL이나 복구한 DLL 없이 공식 업스트림 배포물만으로 검증했으며, 기준 버전은 다음과 같음
  - ZLUDA v6-preview.69
  - AMD HIP SDK 6.4
  - LibTorch 2.3.0 + cu118
- ZLUDA 
- 실제 파라미터 2,216,347개인 PPO 네트워크가 CUDA 장치로 노출되는 환경에서 순전파/추론, PPO 학습, 옵티마이저 작업을 완료함
  - 저장소가 생성한 런타임으로 검증 반복 한 회에서 65,536 타임스텝을 처리함
  - 프로젝트 개발 계기가 된 것과 같은 CUDA 대상 LibTorch 학습 워크로드를 사용했으며, 세부 검증은 검증 문서에서 확인할 수 있음
- CUDA API와 라이브러리 지원 범위는 워크로드에 따라 달라지므로, 이 결과가 모든 CUDA 프로그램이나 AI 모델의 동작을 뜻하지는 않음
설치 자동화와 실행 방식
- 최신 AMD GPU 드라이버와 HIP Libraries를 포함한 Windows용 AMD HIP SDK가 필요함
  - 검증 기준은 HIP SDK 6.4 이며, 더 최신 버전은 동작할 수 있으나 검증 결과가 보고되기 전까지 미검증으로 취급함
  - 설치 전제 조건은 AMD Windows HIP SDK 가이드를 따름
- 검증 기준은 HIP SDK 
- 설치 스크립트는 GPU와 네이티브 gfxXXXX 타깃 감지, 드라이버/HIP SDK 및 필수 수학 라이브러리 확인을 자동화함
  - 버전이 고정된 공식 ZLUDA Windows 빌드와 LibTorch 2.3.0+cu118 을 내려받고 SHA-256 해시를 검증함
  - LibTorch 다운로드 크기는 약 2.66GB이며, 필요하지 않으면 생략할 수 있음
  - 런타임 설정과 GPU 보고서를 생성한 뒤 설치된 AMD 환경에서 ZLUDA의 cuda_check.exe 를 실행함
- 버전이 고정된 공식 ZLUDA Windows 빌드와 LibTorch 
- 실행기는 대상 애플리케이션 옆에 ZLUDA 호환 DLL을 배치하고, 해당 실행에 필요한 HIP/ROCm 런타임 경로를 설정함
  - 애플리케이션을 실행하지 않고 런타임 파일만 배치하는 방식도 지원함
- 진단 도구와 GPU 스캐너는 모델, gfx 아키텍처, 드라이버, HIP 정보를 기록함
  - 사용자 이름, 토큰, 사용자 파일은 의도적으로 수집하지 않음
  - 다른 GPU의 성공/실패 결과 모두 GPU 호환성 보고로 제출할 수 있으며, 애플리케이션, 실행 결과, 유용한 첫 오류/출력을 함께 첨부하도록 요청함
라이브러리 지원과 알려진 한계
- 검증 구성의 cuda_check 에서 CUDA 드라이버/nvcuda 와 다음 라이브러리가 검사를 통과함
  - cuBLAS는 rocBLAS를 통해 동작함
  - cuBLASLt는 hipBLASLt를 통해 동작함
  - cuSPARSE는 rocSPARSE를 통해 동작함
  - cuFFT도 검사를 통과함
- 검증된 안정판 Windows HIP SDK에는 MIOpen 등 전체 ROCm AI 라이브러리 스택이 없어 cuDNN을 사용할 수 없음
  - cuDNN이 필요한 합성곱 중심 소프트웨어는 더 최신 또는 나이틀리 HIP 구성이나 추가 작업이 필요할 수 있음
  - 밀집 연산/GEMM 중심 LibTorch 학습은 반드시 cuDNN을 요구하지 않으며, 검증한 PPO 워크로드도 cuDNN 없이 완료됨
- ZLUDA는 완전한 CUDA 구현이 아니며, Windows에서는 전체 ROCm 생태계의 일부만 사용할 수 있음
  - NCCL, TensorRT, 지원되지 않는 PTX 동작, 일부 커스텀 CUDA 확장은 실패할 수 있음
  - ZLUDA_CC=8.6 은 CUDA 측에 노출하는 호환성 값이지 AMD GPU 아키텍처가 아님
성능 비교와 과거 커스텀 오버레이
- 2026-09-13 통제 A/B 테스트에서는 같은 RX 9060 XT PPO 워크로드를 런타임별로 10회 반복하고, 각 시험의 첫 반복은 워밍업으로 제외함
  - 공식 업스트림 구성의 전체 처리량 중앙값은 13,278스텝/초, 복구한 커스텀 오버레이는 12,876스텝/초였음
  - 이 워크로드에서 커스텀 오버레이가 약 3.03% 느렸으므로 업스트림 구성을 기본값으로 유지함
- 과거 튜닝 실행은 서로 다른 학습 설정으로 약 7만~10만 9천 스텝/초를 기록함
  - 측정 방법과 원시 데이터는 벤치마크 문서에서 확인할 수 있음
- 초기 개발 환경에서는 커스텀 cuBLAS/cuBLASLt/HIP 오버레이도 실험했으나, 검증된 공개 실행 경로에는 필요하지 않으며 현재 기준 PPO 워크로드에서 성능상 이점도 없음
  - 복구한 DLL의 해시는 manifests/recovered-artifacts.sha256 에 남아 있음
  - 원래 커스텀 래퍼의 소스와 출처 정보가 불완전하고 복구한 HIP 런타임에 제3자인 AMD의 바이너리가 포함돼 있어 바이너리 파일은 공개하지 않음
  - 관련 내역은 커스텀 오버레이 문서에 정리돼 있음

저장소 구성과 라이선스
- 저장소는 설치/진단/실행 스크립트, 고정 버전과 해시 및 GPU 아키텍처 메타데이터, 검증/아키텍처/벤치마크/문제 해결 문서, 통합 예제로 구성됨
  - 생성된 의존성과 보고서는 .runtime/ , 로컬 보관 파일은local-artifacts/ 에 두며 두 디렉터리는 Git 추적에서 제외함

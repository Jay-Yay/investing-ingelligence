### AI 덕분에 셀프 호스팅이 다시 즐거워졌다 | GeekNews

(https://news.hada.io/topic?id=37928)

GeekNews긱뉴스는 개발, 기술, 스타트업 정보와 노하우, 세상의 재미난 것들을 좋아하는 사람들을 위한 뉴스 사이트 입니다.토픽
발행 2026-11-27 · 작성 neo
출처 https://news.hada.io/topic?id=37928
- 기존 서비스를 유지하는 데 그쳤던 개인 셀프 호스팅 환경에서 AI 코딩 에이전트가 설정 변경과 실험의 수고를 줄이면서, 새로운 기술과 서비스를 시도하는 재미가 되살아남
- Git 저장소로 관리하던 Docker Compose 파일과 스크립트를 AI와 함께 수정하고, 익숙하지 않았던 NixOS와 Debian 기반 bootc 이미지까지 활용 범위를 넓힘
- Renovate가 업데이트 PR을 만들고, 검토 후 병합하면 GitHub Actions나 Forgejo Actions가 빌드와 배포를 처리함. 예전에는 버전을 직접 바꾸고 서버에 SSH로 접속해 배포해야 했지만, 이제는 휴대폰에서 PR을 병합하는 것으로 끝날 때도 있음
- 작은 용도에 맞는 오픈소스를 찾고 설정하는 대신, 청구서나 전자신문을 자동으로 내려받는 도구를 Go로 만들어 홈 서버에 배포함. 자기 문제만 해결하면 되니 범용 기능이나 복잡한 UI까지 만들 필요가 없음
- 유지보수와 보안, 변경 사항을 이해할 책임은 여전히 남지만, 가장 큰 변화는 시간 절약보다 미뤄 두었던 아이디어를 실제로 실행하게 된 점임
Git 기반 인프라에서 줄어든 작업 부담
- 수년간 셀프 호스팅을 이어 왔지만, 한동안은 새 소프트웨어를 시험하거나 인프라를 손보기보다 기존 환경 유지에 만족했음
- 최근 몇 달 사이 AI의 도움으로 셀프 호스팅에 대한 흥미가 다시 커짐
- 인프라 설정 대부분이 Git 저장소의 Docker Compose 파일, 스크립트, 기타 설정 파일에 있어 AI 코딩 에이전트가 일반 소프트웨어 프로젝트처럼 작업할 수 있음
- 새 서비스 시험, 기존 설정 조정, 자동화에 드는 수고가 줄면서 즉흥적인 아이디어도 실제 구현으로 이어지는 경우가 많아짐
  - 이전에는 변경 이력과 문서를 읽거나 문제를 해결하는 데 저녁 시간을 쓰기 싫어 변경을 미루곤 했음
  - 기술적으로 불가능해서가 아니라, 필요한 노력만큼 가치가 있다고 느끼지 못했던 경우가 많았음
NixOS와 bootc로 넓어진 실험
- 전체 시스템을 선언적으로 구성하는 NixOS에 매력을 느껴 노트북에서도 사용한 적이 있지만, 원하는 설정을 완성하는 일이 큰 장벽이었음
  - AI의 도움을 받은 뒤 홈 서버에서 NixOS를 훨씬 폭넓게 활용하고 있음
- VPS 인프라에는 한동안 구상하던 Debian 기반 bootc 이미지를 직접 만들기 시작함
  - 운영체제 전체 설정을 Git 저장소에 정의하고, 이를 바탕으로 부팅 가능한 컨테이너 이미지를 자동 빌드함
  - 몇 달 전 구축 당시 AI를 사용해도 반나절이 걸렸으며, AI가 없었다면 적어도 일주일은 걸렸을 것으로 예상함
  - 이전 같았으면 혼자 구현하는 데 충분한 시간을 투자하지 않았을 가능성이 큼
- AI 덕분에 모든 세부 사항을 먼저 익히지 않고도 낯선 기술을 실험하기 쉬워짐
  - 진행 중에 질문하고 배우며 설정을 점진적으로 개선할 수 있음
업데이트부터 배포까지 이어지는 자동화
- 인프라의 빌드, 업데이트, 배포 과정 대부분을 자동화함
  - 새 릴리스 확인, 컨테이너 이미지 태그 갱신, 이미지 빌드, 설정 변경 배포처럼 정기적으로 필요한 작업이 대상임
- 과거 서비스 업데이트는 노트북에서 버전과 Docker Compose 파일을 수정하고 Git 원격 저장소에 푸시한 뒤, 서버에 SSH로 접속해 변경 사항을 받아 배포하는 과정이었음
  - 이제는 Git 푸시 한 번이면 충분하며, 직접 푸시할 필요조차 없는 경우도 있음
- Renovate가 대부분의 소프트웨어 업데이트를 확인하고 풀 리퀘스트를 생성함
  - 검토 후 병합하는 것만으로 끝나는 경우가 많아, 소파에서 휴대전화로 처리할 수도 있음
- 변경 사항을 푸시하거나 풀 리퀘스트를 병합하면 GitHub Actions 또는 Forgejo Actions 워크플로가 실행되어 빌드와 배포를 처리함
- DevOps와 이 자동화 도구들은 오래전부터 존재했고 AI가 필수인 것은 아님
  - 다만 AI가 그동안 미뤄 왔던 도구 간 연결과 구성을 완성하는 데 도움을 줌
  - 자동화의 효과는 초기 설정에 그치지 않고, 이후 서비스 변경과 업데이트 때마다 반복 작업을 줄여 줌
기존 하드웨어를 다시 활용한 홈 서버
- 호스팅하는 서비스가 늘면서 VPS의 서비스를 홈 서버로 더 많이 옮김
- 홈 서버로 쓰던 HP t640 씬 클라이언트 대신, 한동안 사용하지 않던 ASRock DeskMini A300을 다시 가동함
  - t640은 단일 네트워크 인터페이스를 사용하는 “router on a stick”으로 전환하는 방안을 고려 중임
- CPU를 AMD Ryzen 5 2400G에서 Ryzen 5 PRO 4650G로 업그레이드하고, AMD 기본 쿨러를 더 조용한 Noctua 쿨러로 교체함
  - 처음 t640으로 바꿨던 주된 이유는 소음이었음
  - 새 컴퓨터를 사는 대신 기존 장비를 재활용했고, CPU와 쿨러도 중고 거래 사이트에서 좋은 가격에 구함
- 늘어난 컴퓨팅 여유로 더 많은 실험이 가능해졌으며, 집 안의 작은 기기에서 일상적으로 사용하는 서비스가 늘어나는 데 만족감을 느낌
필요한 만큼만 만드는 개인용 도구
- 원하는 기능을 정확히 수행하는 기존 소프트웨어가 없을 때, 작은 문제라면 직접 구현하는 선택이 더 매력적으로 바뀜
  - 이전에는 적절한 오픈소스 프로젝트를 찾고 대안을 비교한 뒤, 자신의 용도에 맞게 적용하는 데 상당한 시간을 쓰곤 했음
- 최근에는 청구서 자동 다운로드, 전자신문 다운로드, Linux ISO 다운로드 도구를 만듦
- 선호하는 언어인 Go로 직접 만들거나 AI에 구현을 맡겨, 자신의 요구에 정확히 맞출 수 있음
  - 모든 사용 사례, 정교한 사용자 인터페이스, 다른 사람의 관심까지 고려할 필요는 없음
  - 방대한 문서와 타인의 사용 사례 지원을 갖춘 정식 오픈소스 프로젝트로 만들기보다, 자신의 문제를 해결하면 충분함
- 도구 제작뿐 아니라 컨테이너 이미지 빌드와 배포, 운영도 쉬워져 자동화된 인프라와 잘 맞물림
  - 아이디어를 떠올린 뒤 홈 서버에서 실제로 실행하기까지 필요한 노력이 이전보다 크게 줄어듦
쉽게 만들 수 있어도 남는 책임
- 서비스가 하나 늘 때마다 유지보수 대상도 늘어나며, AI 생성 소프트웨어 역시 버그, 보안 문제, 기술 부채에서 자유롭지 않음
- AI 에이전트가 인프라를 수정하더라도 변경 내용을 이해할 책임은 사용자에게 남음
- 구현이 쉬워질수록 가능하다는 이유만으로 무언가를 만들거나 배포하고 싶은 유혹도 커짐
  - 실제로 구현할 가치가 있는지 때때로 자문하는 일이 더 중요할 수 있음
- 다만 취미로서의 셀프 호스팅이 모두 경제적이거나 유용할 필요는 없음
  - 새로운 기술을 실험하는 것 자체가 목적일 때도 있음
  - 일상적인 유지보수를 상당 부분 자동화했으므로, 서비스를 추가해도 과거만큼 반복 작업이 늘어나는 것은 아님
새로운 의존성과 되살아난 즐거움
- 대형 기술 기업이 주도하는 AI가 디지털 생활의 다른 영역에서는 그 기업들에 대한 의존을 조금 줄이는 데 도움을 줌
- 동시에 새로운 종류의 의존성이 생긴다는 점도 인식하고 있음
  - AI로 만든 소프트웨어와 인프라 설정은 제작에 사용한 AI 서비스와 독립적으로 계속 존재할 수 있음
  - 주로 오픈 웨이트 모델을 사용해 제공업체 선택의 폭도 넓음
- 가장 반가운 변화는 시간 절약 자체보다 작은 아이디어를 실제로 실행하려는 의욕이 커진 점임
  - 수년간 궁금했던 기술을 시험하고, 오래 미뤘던 자동화를 구현하며, 개인용 도구를 만들고 하드웨어도 다시 손보고 있음
- 디지털 생활을 직접 통제하고, 새로운 것을 배우며, 기술을 만지는 즐거움이라는 셀프 호스팅의 동기는 바뀌지 않음
  - AI는 그 즐거움을 약화시키던 작업 부담을 상당 부분 덜어 줬고, 셀프 호스팅은 다시 재미있는 취미가 됨

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.
- 웹 미리보기는 페이지당 최대 20개 메시지씩, 최대 10페이지(최근 약 200개)까지만 페이지네이션한다.

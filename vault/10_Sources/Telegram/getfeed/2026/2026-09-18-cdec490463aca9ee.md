### OpenSpec - 코딩 에이전트와 구현 전에 명세를 맞추는 개발 도구 | GeekNews

(https://news.hada.io/topic?id=33841)

- 대화 기록에만 남아 있던 요구사항을 명세와 구현 계획으로 정리하고, 사람이 검토한 뒤 AI가 코드를 작성하도록 돕는 도구
- 변경 작업마다 제안서, 요구사항과 시나리오, 기술 설계, 작업 목록을 별도 폴더에 모아 무엇을 왜 바꾸는지 함께 관리
- 문제 탐색부터 구현과 검증, 완료한 변경의 보관까지 지원하며, 진행 중에도 명세와 계획을 수정할 수 있어 정해진 단계를 일방향으로 따를 필요는 없음
- 명세는 Markdown 파일로 저장하며, Claude Code, Codex, Cursor, GitHub Copilot 등 기존 코딩 도구에서 명령과 스킬로 활용 가능
- 새 프로젝트뿐 아니라 기존 코드베이스의 기능 추가와 변경에도 사용할 수 있으며, MIT 라이선스로 공개됨
대화 속 요구사항을 검토 가능한 명세로 남김
- OpenSpec은 코딩 에이전트를 대체하는 도구가 아니라, 기존 에이전트와 무엇을 만들지 합의하고 구현 과정을 관리하는 명세 중심 개발 도구임
- 요구사항이 대화에만 남아 있으면 구현 전에 오해를 확인하기 어렵고, 이후 변경 이유를 찾으려면 과거 대화를 뒤져야 함
- AI가 요구사항과 계획의 초안을 작성하고, 사람이 검토하고 조정한 뒤 구현을 시작하는 흐름을 제공
- 문서는 Markdown 파일로 저장해 코드와 함께 관리하며, 다음 에이전트 세션에서도 같은 요구사항과 계획을 참고할 수 있음
변경 하나에 제안, 명세, 설계와 작업 목록을 묶음
- 기능 추가나 수정마다 openspec/changes/ 아래에 별도 폴더를 만들고, 해당 작업에 필요한 문서를 모음
  - proposal.md : 왜 바꾸는지, 무엇을 바꾸는지
  - specs/ : 요구사항과 구체적인 동작 시나리오
  - design.md : 기술적인 구현 접근법
  - tasks.md : 구현할 작업의 체크리스트
- 명세는 추상적인 목표뿐 아니라 어떤 상황에서 어떤 결과가 나와야 하는지를 기술함
  - 다크 모드라면 “사용자가 테마 전환 버튼을 누르면 화면이 바뀌고, 선택한 테마가 저장됨” 같은 시나리오를 작성
- 현재 시스템의 명세와 진행 중인 변경을 구분해 관리함
  - openspec/specs/ 에는 현재 시스템의 동작을 정리
  - 개별 변경에는 추가, 수정, 삭제할 요구사항만 기록하는 변경 명세(delta specs) 를 작성
- 기존 코드베이스 전체를 먼저 문서화하지 않고도, 이번 작업에서 달라지는 부분부터 명세로 관리할 수 있음
탐색부터 구현, 명세 반영까지
- 기본 작업 흐름은 문제 탐색, 변경 제안, 구현, 명세 동기화와 보관으로 구성됨
  - /opsx:explore : 코드를 읽고 문제와 접근법을 살펴봄. 무엇을 바꿀지 명확하다면 생략 가능
  - /opsx:propose : 제안서, 명세, 설계와 작업 목록의 초안을 작성
  - /opsx:apply : 문서를 참고해 구현하고 완료한 작업을 표시
  - /opsx:sync : 변경 명세를 현재 시스템의 명세에 반영
  - /opsx:archive : 완료한 변경 폴더를 날짜가 붙은 보관 경로로 이동
- 명령은 AI 코딩 도구의 대화창에서 실행하며, OpenSpec CLI는 문서 구조와 작성 지침, 작업 상태를 제공
- 구현과 명세를 대조하는 /opsx:verify 도 제공하지만, 기본 프로필이 아니라 추가로 활성화하는 확장 명령임
- 보관 과정에서도 명세 동기화를 제안하며, 동기화를 건너뛰고 변경 폴더만 보관할 수도 있음
계획을 고정하지 않고 구현 중에도 수정
- 제안 → 명세 → 설계 → 작업 목록의 순서는 문서 간 의존 관계이며, 이전 단계로 돌아갈 수 없는 절차가 아님
- 구현 중 설계의 문제를 발견하면 design.md 를 수정하고, 범위를 줄여야 한다면 제안서와 관련 문서를 조정할 수 있음
- 문서의 구성과 작성 순서도 스키마를 통해 작업 방식에 맞게 변경 가능
- 유연하게 수정할 수 있는 만큼, 작업 범위가 계속 커지지 않도록 관리하는 책임은 남음
- 한 줄짜리 단순 수정처럼 명세 작성에 드는 수고가 이점보다 큰 작업에는 전체 절차가 필요하지 않을 수 있음
기존 코딩 도구와 여러 저장소에서 활용
- Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode 등 다양한 코딩 도구와 연동
- openspec init 으로 프로젝트를 초기화하며, 도구에 따라 명령 표기는 슬래시 명령이나 스킬 호출 형태로 달라짐
- Stores는 명세와 계획을 별도 Git 저장소에서 공유하는 베타 기능임
  - API 서버, 웹 앱, 공통 라이브러리처럼 구현이 여러 저장소에 걸쳐 있어도 하나의 변경 계획을 공유
  - 공통 요구사항을 관리하는 팀과 이를 사용하는 팀이 같은 명세를 참고할 수 있음
- Node.js 20.19.0 이상이 필요하며, npm install -g @fission-ai/openspec@latest 로 설치 가능
- MIT 라이선스로 공개되어 있으며, 실제 문서 구성은 저장소의 명세와 변경 작업에서 확인할 수 있음

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 Telethon(MTProto)을 통해 사용자가 실제로 접근 권한을 가진 채널의 메시지를 수집하며, 공개 웹 미리보기(t.me/s/{channel})와 달리 인증된 사용자 세션이 필요하다.
- 한 번에 최대 200개 메시지만 조회하며, 그 이상의 과거 히스토리는 이 단계에서 수집하지 않는다.
- 이미지, 동영상 등 미디어 전용 메시지(텍스트 없음)는 캡처하지 않는다.
- 메시지에 포함된 기사 링크(최대 메시지당 3개, 유튜브/X/인스타그램/페이스북 제외)는 본문을 함께 가져와 아래 '첨부 기사 원문'에 붙인다 - 실패하면 그 링크만 오류로 표시된다.

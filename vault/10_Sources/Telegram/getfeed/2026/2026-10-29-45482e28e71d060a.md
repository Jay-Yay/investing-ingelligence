  - 활성 파라미터는 약 40억 개로, 동률 모델의 240억 개 대비 약 6분의 1임
  - 지수의 50%를 차지하는 별도 평가용 음성 에이전트 데이터 AA-AgentTalk에서는 WER 1.8%로, 다음으로 높은 성능의 공개 가중치 모델이 기록한 2.3%보다 낮았음

- 공개 예정인 NVFP4 양자화 버전은 NVIDIA RTX PRO 6000 Blackwell Server Edition GPU 1대에서 100시간 분량의 오디오를 3분 이내에 처리함
  - 30초 클립과 높은 동시성을 사용한 벤치마크 결과임
- 현재 체크포인트는 vLLM과 SGLang-Omni로 자체 호스팅할 수 있으며, 두 도구 모두 출시일부터 지원함

  - RTX Spark, DGX Spark, Jetson AGX Thor에서 로컬 실행하거나 Blackwell 데이터센터 GPU로 확장하는 구성을 지원할 예정임

- 자체 호스팅 대신 Baseten, DeepInfra, Simplismart의 호스팅 엔드포인트를 사용할 수 있음
Granary v2의 데이터와 학습 목표
- Granary v2는 NVIDIA NeMo Curator로 구축한 재사용 가능한 다국어 음성 정제 파이프라인과 데이터 매니페스트를 제공함
  - Transcribe 학습에 사용한 음성을 정제하고, 서로 대응하는 전사 변형, 작업 라벨, 검토 가능한 품질 메타데이터를 생성함
  - 공개 매니페스트는 48개 언어, 16개 원천 코퍼스, 463,062시간을 포함하며, Granary v1의 25개 언어에서 범위가 확대됨
  - 이 수치는 공개 데이터셋의 규모이며, Transcribe의 전체 학습 데이터 구성이나 샘플링 가중치를 뜻하지 않음
- 각 녹음에 세 가지 전사 형식을 생성하며, Transcribe에서도 프롬프트로 축어적 전사와 정돈된 전사를 요청할 수 있음
  - tn_raw : 숫자를 단어로 풀어 쓰고 머뭇거림을 보존함. 예:I paid, uh, twenty-five euros.
  - itn_raw : 숫자와 단위를 일반적인 문자 표기로 바꾸고 머뭇거림을 보존함. 예:I paid, uh, €25.
  - itn_clean : 일반적인 문자 표기를 사용하고 머뭇거림을 제거함. 예:I paid €25.
- 전사 외에도 짧은 오디오 캡션, 코드 스위칭에서의 차용어 복원, 음성에 근거한 질의응답 쌍, 문맥 기반 ASR 유도 용어, 자동 품질 점수가 붙은 번역을 생성함
- 공개 매니페스트에는 엔티티 힌트, 파생 지시문 쌍, 출처, 레코드별 품질 플래그도 포함됨
  - 원본 오디오는 각 코퍼스의 원래 라이선스에 따라 별도로 내려받아야 하며, 릴리스의 공개 이용 조건을 따라야 함
  - ModelScope에서도 매니페스트를 제공함
재사용 가능한 네 단계 정제 파이프라인
- 1. 오디오 준비(Metadata): 원본 또는 긴 오디오를 분할하고, 전체 녹음에 걸쳐 화자를 추적하며, 음향 이벤트와 언어를 표시함
  - Granary v2의 원천 데이터는 이미 분할돼 있어 이번 릴리스에서는 이 단계를 생략함
- 2. 전사(ASR): 언어별 주 모델과 복구용 모델로 음성을 보내며, 주 모델이 환각 검사를 통과하지 못하면 대체 모델을 사용함
  - 사람이 작성한 기준 전사문을 활용해 신뢰할 수 있는 철자를 보존하면서 발화 형태와 머뭇거림을 추가함
- 3. 작업 라벨 생성(Text): 전사 변형을 만든 뒤 문자 비율, 환각 패턴, 모델 또는 사람 기준 전사문과의 일치도를 검사함
  - 승인된 레코드에만 문맥 기반 ASR 용어와 번역을 생성함
- 4. 고품질 필터링(HiFi): 잡음, 잘림, 여러 화자가 포함된 구간을 제거해 ASR 외 용도로도 활용할 수 있는 소규모 고품질 녹음 집합을 만듦
  - VoxPopuli에서는 유럽 22개 언어의 35만 4,000시간을 11만 1,000시간으로 줄임
- 개발자는 NeMo Curator 파이프라인을 Ray와 NVIDIA Dynamo 백엔드로 실행해 자체 녹음이나 사용 권한이 있는 공개 코퍼스를 처리할 수 있음
의료 도메인 적응: 프롬프트부터 미세조정까지
- 먼저 개발용 데이터에서 언어, 문자 체계, 전사 형식을 명시하는 프롬프트를 조정함
  - 의료 ASR 사례에서는 영어와 라틴 문자를 명시하는 것만으로 전체 벤치마크 WER가 30.8%에서 23.8%로 줄었음
- 평가는 인도 의사와 의대생의 녹음 3,619개로 구성된 Eka Care 공개 벤치마크를 사용하며, 이 데이터에는 지정된 학습 분할이 없음
  - 생성한 의료 텍스트와 공개 의약품 목록으로 적응 데이터를 만들고, 약 153시간의 합성 음성, Common Voice의 억양이 있는 영어 29시간, MultiMed 의료 녹음 63시간을 결합함
  - 학습 텍스트에서 벤치마크 기준문과 완전히 일치하거나 8단어 연속 구문을 공유하는 항목을 걸러냄
- 합성 데이터는 목표 문자 표기와 실제 발음 형태를 분리함
  - 정답 라벨은 HbA1c 로 두고, 음성 합성기에는H B A one C 를 전달함
  - 여러 TTS 음색으로 음성 다양성을 늘리고, 실제 녹음으로 억양과 녹음 환경을 보완함
- 학습 예제는 숫자, 단위 간격, 회사명 확장 표기, 브랜드명 하이픈을 다양하게 구성하고 지시문으로 원하는 규칙을 지정함
  - 일부 용어 목록에는 비슷하지만 틀린 후보를 넣어, 오디오가 뒷받침할 때만 해당 철자를 사용하도록 학습함
  - 최종 시스템은 고정된 표기 규칙 프롬프트와 한 번의 모델 실행만 사용하며, 검색이나 전사 후처리를 사용하지 않음
- 음성 인코더와 투영 계층을 학습하고 언어 모델은 LoRA로 적응시킴
  - 데이터 구성을 달리한 두 번의 학습 후 어댑터를 병합하고, 선택한 체크포인트를 동일 가중치로 평균해 최종 모델을 만듦
  - 체크포인트는 학습 손실만이 아니라 개발 세트의 실제 디코딩 결과로 선택함
  - 텍스트 생성부터 평가까지 전체 과정에 NVIDIA GB300 1대 기준 약 14 GPU시간이 소요됨
별도 화자 평가 결과와 적용 시 주의점
- 벤치마크를 화자 기준으로 조정용 855개 클립과 별도 평가용 2,764개 클립으로 나눔
  - 조정용 클립은 프롬프트와 체크포인트 선택에 사용하고, 평가용 클립은 최종 시스템마다 한 번씩 디코딩함
- KARMA 평가 파이프라인 기준 별도 평가 화자의 WER는 최적 프롬프트 기준 22.44%에서 미세조정 후 12.17%로 45.8% 상대 감소함
  - 키워드 WER는 9.2%에서 6.5%, 의미 기반 WER는 10.0%에서 7.6%로 낮아짐
  - 같은 화자와 평가기에서 공개 의료 전문 모델의 13.79%, 널리 쓰이는 범용 ASR 모델의 14.92%보다 낮았음
- 전체 벤치마크에서는 WER가 기본 30.8%, 개선 프롬프트 23.8%, 미세조정 11.8%로 낮아져 기본 모델 대비 오류가 약 62% 줄었음
  - 다만 전체 결과에는 프롬프트와 체크포인트 선택에 사용한 855개 클립이 포함되므로, 별도 화자 결과가 일반화 성능을 더 명확히 보여줌
- 일반 영어 성능에는 소폭 손실이 있었음
  - LibriSpeech test-clean WER가 1.54%에서 1.69%로 상승함
  - 약품 브랜드명과 진단명 완전 일치에서는 의료 전문 모델이 여전히 앞섰으며, 다음 단계로 임상의가 브랜드명을 발음한 실제 녹음을 확보할 필요가 있음
- 자체 도메인에 적용할 때는 체크포인트 선택용으로 실제 라벨링 클립을 최소 100개 확보하고, 일반 음성 성능 유지 여부와 함께 애플리케이션에 중요한 엔티티 유형을 평가할 것을 권장함
- NeMo Speech 미세조정 튜토리얼은 새 언어와 코드 스위칭 ASR을 포함한 학습법, 자원 요구사항, 학습/내보내기/평가 도구를 제공함
  - 미세조정 에이전트 스킬을 사용하면 코딩 에이전트가 기준 모델 선택, 데이터 점검, 학습 검증, 어댑터 병합, 평가까지 실행할 수 있음
  - ModelScope의 ms-swift로도 특화 멀티모달 애플리케이션을 위한 미세조정이 가능함

## 텔레그램 수집 시 유의사항

- 이 컬렉터는 공개 웹 미리보기(t.me/s/{channel})만 수집하며, 비공개 채널 수집은 이 단계에서 구현하지 않는다.
- 웹 미리보기는 페이지당 최대 20개 메시지씩, 최대 10페이지(최근 약 200개)까지만 페이지네이션한다.
- 이미지, 동영상 등 미디어 전용 메시지(텍스트 없음)는 캡처하지 않는다.
- 메시지에 포함된 기사 링크(최대 메시지당 3개, 유튜브/X/인스타그램/페이스북 제외)는 본문을 함께 가져와 아래 '첨부 기사 원문'에 붙인다 - 실패하면 그 링크만 오류로 표시된다.

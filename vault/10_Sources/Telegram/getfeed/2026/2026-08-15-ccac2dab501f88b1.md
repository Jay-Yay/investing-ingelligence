### AI 텍스트 워터마킹의 작동 원리 | GeekNews

(https://news.hada.io/topic?id=32518)

- AI 텍스트 워터마크는 문자나 메타데이터가 아니라 다음 단어를 고르는 확률적 선택에 비밀 패턴을 심으며, Google은 2024년부터 Gemini 앱·웹에 적용했고 Claude 신형 모델도 2026년 8월부터 모델 수준에서 적용함
- 비밀 키로 문맥마다 후보 단어를 임의로 구분한 뒤 특정 후보의 선택 확률을 조금 높이면, 자연스러운 문장을 유지하면서 긴 텍스트에 통계적 편향을 누적할 수 있음
- 키 보유자는 같은 분류를 재현해 편향을 측정하며, 예시의 50:50 모델에서는 1,500단어 문서가 약 55%의 편향만 보여도 탐지할 수 있지만 짧거나 선택지가 적은 텍스트는 판별하기 어려움
- 가벼운 교정이나 한 차례의 바꿔쓰기는 원문 구간을 남겨 워터마크를 희석할 뿐이지만, 의미부터 문장을 재구성하면 KGW·EXP 실험의 탐지 정확도가 동전 던지기 수준으로 떨어짐
- 검출 결과는 AI가 작성했다는 증거가 아니라 해당 제공자의 모델로 처리됐다는 확률적 신호이며, 실제 검사는 비밀 키나 제공자의 검사 서비스가 필요하고 워터마크 부재도 인간 작성 여부를 입증하지 못함
단어 선택에 숨기는 통계적 패턴
- 텍스트에는 픽셀이나 복사 후에도 남는 메타데이터가 없지만, 언어 모델은 매 순간 여러 자연스러운 후보 가운데 하나를 가중 확률에 따라 선택함
- 한 페이지에는 단어마다 수백 번의 선택 지점이 생기며, 여러 후보가 모두 문맥상 적절한 지점의 여유가 워터마크를 넣을 공간이 됨
- 선택 확률을 미세하게 조정하면 의미를 바꾸지 않으면서 반복되는 통계적 패턴을 만들 수 있음
- Google은 2024년부터 Gemini 앱과 웹 경험의 텍스트에 워터마크를 적용했으며, 작성 시점의 Gemini API는 문서화된 예외임
- 2026년 8월부터 새 Claude 모델은 모델 수준에서 텍스트를 표시하며, 이전 모델에도 뒤이어 적용할 예정임
비밀 키로 후보 확률을 조정하는 방식
- Kirchenbauer 등의 2023년 방식은 비밀 키로 각 선택 지점의 후보를 임의의 green·red 그룹으로 나눈 뒤 green 쪽 확률을 조금 높임
  - red 후보도 계속 선택될 수 있어 문장이 부자연스럽게 고정되지 않음
  - 단어의 색은 고정 속성이 아니라 바로 앞의 짧은 단어 구간으로 계산되므로, 같은 후보도 문맥에 따라 green 또는 red가 됨
  - 키는 전체 텍스트의 위치가 아니라 직전 문맥만 보며, 어느 위치에서 어떤 단어가 green이었는지는 키 보유자만 재현할 수 있음
- Google의 SynthID는 단순한 확률 가중 대신 작은 비밀 토너먼트를 사용함
  - 모델의 원래 확률에서 후보 몇 개를 뽑아 키로 점수를 매김
  - 키 추출 전체의 평균에서 각 단어의 확률이 모델이 의도한 값과 정확히 같아지도록 대진을 구성함
- OpenAI에서 개발된 Aaronson 방식은 키로 주사위 추첨 자체를 유도함
- 수학적 구현은 달라도 세 방식 모두 워터마크를 실제 문자가 아닌 단어 사이의 선택에 저장함
비밀 키를 이용한 탐지
- 탐지기는 글의 의미나 문체를 판단하지 않고, 비밀 키로 각 단어의 분류를 재현해 green이 나온 횟수를 셈
- 워터마크가 없거나 틀린 키를 사용하면 green 비율은 약 절반으로 수렴해 동전 던지기와 같아짐
- 올바른 키로 표시된 긴 텍스트에서는 green이 우연으로 보기 어려울 만큼 자주 나타남
- 시각 예시는 원리를 보여주기 위해 실제보다 강한 편향을 사용함
  - 프로덕션 워터마크는 훨씬 약하게 기울이므로 탐지에 더 긴 텍스트가 필요함
  - 예시의 50:50 모델에서는 1,500단어 문서가 약 55% green만 되어도 판정 기준에 도달함
- 작은 편향은 충분한 길이가 있어야 설득력 있는 통계가 되므로, 짧은 텍스트는 본질적으로 판별하기 어려움
편집과 재작성에 따른 변화
- 단어 분류는 보통 바로 앞의 한 단어에서 몇 단어까지를 이용하므로, 탐지 증거가 되려면 대상 단어와 이웃 단어로 이뤄진 짧은 원문 구간이 그대로 남아야 함
- 오타 수정, 가벼운 교정, 문장 압축, 강한 편집으로 갈수록 온전한 구간이 줄어들며 새로 작성된 부분은 동전 던지기 수준의 잡음만 더함
- 가벼운 편집이나 한 차례의 바꿔쓰기는 워터마크를 지우지 않고 희석함
  - Kirchenbauer 등의 실험에서는 텍스트가 충분히 길면 다시 탐지할 수 있었음
  - 사람이 바꿔 쓴 경우도 약 800토큰, 즉 약 600단어가 되면 다시 탐지할 수 있었음
- MarkLLM의 KGW·EXP 방식과 오픈 모델을 declaude의 전체 재작성 경로로 처리한 실험에서는 원문 구간이 약 0.5% 만 살아남았고, 탐지 정확도는 사실상 확실한 수준에서 동전 던지기 수준으로 하락함
- 워터마크를 제거하려면 표현만 손보는 대신 의미를 바탕으로 문장을 다시 구성해 원문과 같은 구간을 없애야 함
- declaude의 전체 재작성 경로는 의미부터 글을 재구성하지만, 대부분의 표현을 유지하는 가벼운 처리는 이 계열의 워터마크를 제거하지 못함
- 이 수치는 측정 가능한 공개 구현에서 나온 결과이며, Anthropic의 프로덕션 방식은 공개되지 않아 외부에서 Claude 워터마크를 같은 방식으로 시험할 수 없음
실제 판정의 제약
- 키 보유자만 검사할 수 있으므로 교사, 편집자, 일반 AI 탐지 웹사이트는 실제 워터마크 검사를 직접 수행할 수 없음
  - 제공자의 비밀 키나 제공자가 운영하는 검사 서비스가 필요함
  - Google은 SynthID용 조기 접근 탐지 포털을 운영함
  - Anthropic은 탐지 도구를 제공할 예정임
- GPTZero 같은 도구는 문체로 AI 생성을 추정하지만, 워터마크 검사는 의도적으로 심은 패턴을 비밀 키로 확인하는 통계적 검사이므로 서로 다른 방식임
- 워터마크가 발견돼도 해당 텍스트를 AI가 작성했다는 뜻이 아니라 모델이 처리했다는 뜻임
  - Anthropic 문서에 따르면 사람이 쓴 글도 Claude로 교정하거나 번역하면 워터마크를 얻음
  - 이전 모델의 출력이나 강하게 편집된 AI 텍스트에서는 워터마크가 나오지 않을 수 있어, 부재 역시 인간 작성의 증거가 아님
- 짧은 글은 충분한 증거가 쌓이지 않으며, 코드·인용문·사실 목록처럼 올바른 다음 표현이 거의 하나뿐인 텍스트도 후보 선택의 여유가 작아 워터마크를 담기 어려움
재작성에도 살아남는 워터마크
- 앞 문맥이 아니라 단어 자체를 키로 삼는 방식은 같은 의미로 재작성해도 일부 단어가 유지되므로 워터마크가 더 잘 남음
  - 동일한 색 분류가 모든 위치에서 재사용되기 때문에 충분한 출력을 모으면 역공학할 수 있다는 별도 약점이 있음
- 의미 공간에 패턴을 숨기는 방식도 같은 의미의 재작성에서 일부가 유지됨
- 의미 기반 워터마크에 대해 확인된 대응은 개요 수준에서 글을 다시 생성하는 개요 수준 재생성(outline-level regeneration) 임
실험 결과와 수리 모델
- 알려진 키를 사용한 자체 실험에서 재구성은 KGW·EXP 탐지 성능을 AUC 0.99에서 약 0.5로 낮춤
- 문맥과 무관한 unigram 워터마크는 같은 처리 후에도 AUC 0.73~0.84를 유지함
- 편집 후 남는 증거는 z ≈ f·√N·z₁ 로 근사함
  - f 는 살아남은 구간의 비율임
  - N 은 문서 길이임
  - z₁ 은 토큰당 워터마크 강도임
- 시각 자료는 단어를 세지만 실제 탐지기는 모델 자체 토크나이저의 토큰을 세며, 전체적인 관계는 같음
- 인터랙티브 도표의 매개변수는 교육용 예시일 뿐 실제 제공자의 구현을 재현하지 않음

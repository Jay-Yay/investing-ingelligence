- 악성코드는 암호화폐 수신 주소를 바꿔치기하고, 사이트 자체 결제 폼의 카드 정보와 쿠키, 화면을 빼낼 수 있었음. iPhone과 iPad에는 Coruna와 DarkSword 공격 키트도 전달함
- 2026년 11월 16일 19:25 UTC 기준 공격자 지갑으로 약 7,040달러가 유입됐으며, 카드와 쿠키 유출 규모는 확인할 수 없음
- 제한적인 CSP는 외부 악성 스크립트나 데이터 유출을 차단했지만, 신뢰한 공급자의 코드 변조와 페이지 내부의 주소 바꿔치기까지 막지는 못함
공격 경로와 확인되지 않은 침해 원인
- Optimizely Web은 고객 사이트가 CDN의 JavaScript 스니펫을 불러오는 방식으로 작동함
  - 스니펫에는 Optimizely 코드, 고객의 실험, 대시보드에서 선택적으로 작성하는 Project JavaScript(projectJS )가 포함됨
  - Project JavaScript는 해당 스니펫을 사용하는 모든 페이지에서 실행됨
- 공격자는 고객 프로젝트의 projectJS 에 로더를 삽입했으며, 나머지 스니펫은 그대로 유지함
  - Zoom의 스니펫에는 https://1688360[.]cc/track.js 를 비동기로 불러오는<script> 를 생성하는 코드가 추가됨
  - 파일은 계속 cdn.optimizely.com 에서 Optimizely 인증서로 제공됐으므로, 피해 사이트가 이미 신뢰하던 출처를 통해 전달됨
- 확인된 로더는 세 가지 형태였음
  - 대부분은 1688360.cc/track.js 를 직접 불러오는 스크립트 태그였음
  - 같은 URL을 Base64로 숨기고 atob() 으로 복원하는 형태는 도메인 문자열 검색으로 찾을 수 없음
  - 외부 도메인이 차단되면 eval 로 실행하는 전체 페이로드의 인라인 사본도 있었음
- Smartsheet는 정리 후 Base64 형태로 재감염됐으며, 당시 공격자에게 여전히 쓰기 권한이 있었음을 보여줌
- opt.scheels.com 이나www.vodafone.com.au 처럼 자체 도메인에서 스니펫을 제공하는 고객도 같은 Optimizely 프로젝트의 콘텐츠를 사용하므로 영향을 받음
- 다수의 무관한 고객 프로젝트에 접근한 경로는 확인되지 않음
  - Optimizely 시스템 침해, 여러 고객에 접근 가능한 자격 증명 탈취, 그 밖의 경로 중 무엇인지는 알 수 없음
  - CDN은 전달받은 콘텐츠를 그대로 제공했으며, CDN 캐시 오염 공격은 아님
  - www.optimizely.com 과login.optimizely.com 용 스니펫에도 악성코드가 있었음

CSP가 막은 것과 막지 못한 것
- 피해 조직의 호스트 256개를 크롤링해 외부 스크립트 로드, 인라인 대체 코드 실행, 데이터 전송, iOS 키트 로드에 필요한 CSP 조건을 검사함
  - CSP가 전혀 없는 조직은 68개, 페이로드와 데이터 탈취를 모두 허용한 조직은 50개였음
  - 페이로드는 실행됐지만 connect-src 가 데이터 탈취를 차단한 조직은 17개였음
  - 페이로드를 차단한 조직은 24개, 15% 였음

cdn.optimizely.com 을 신뢰 목록에 넣는 것만으로는 보호되지 않음
  - 악성코드가 신뢰한 호스트 자체에서 전달됐기 때문임
  - 필요한 호스트만 나열하는 제한적인 script-src 는1688360.cc 에서 가져오는 스크립트를 차단함
  - 반면 'strict-dynamic' 과'unsafe-eval' 은 공격 코드의 실행을 허용할 수 있었음
    - 'strict-dynamic' 은 신뢰한 Optimizely 스니펫이 삽입한 스크립트에도 신뢰를 전달함
    - 'unsafe-eval' 은 외부track.js 가 차단돼도 인라인 사본을eval 로 실행하게 함. Optimizely 자체 문서는 고객에게 이 설정을 허용하도록 안내함
  - HSBC에서는 track.js 와 데이터 유출이 차단됐지만, 인라인 사본은 실행됨
  - 제한적인 connect-src 는 17개 조직에서 카드, 쿠키, 화면 캡처 유출을 막음
  - 데이터 전송을 차단해도 페이지 내부에서 수행되는 주소 바꿔치기는 막지 못함
브라우저 측 감시와 Report URI의 탐지 범위
- 신뢰한 JavaScript도 이후 변조될 수 있으며, 사이트 자체 코드나 인프라가 침해되지 않아도 외부 의존성을 통해 방문자가 공격받을 수 있음
- Report URI에 따르면 CSP Report-Only 모드를 이용해 사이트 동작을 차단하지 않고 다음 변화를 탐지할 수 있음
  - track.js 와 iOS 라우터 등 새로운 스크립트 의존성을 탐지함
  - hit.php ,card.php 같은 새로운 데이터 전송 목적지를 탐지함
  - 공격 키트 iframe의 새로운 출처를 탐지함
  - Optimizely 스니펫의 지문 변경과 알려진 파일에 대응하지 않는 신규 스크립트를 탐지함
- JS Time Machine은 새 버전이 처음 나타난 시점과 제공 기간을 확인하는 기능임
  - 알려진 공격 도메인은 침해 지표로 표시하며, 조사 중 추가한 도메인도 이후 탐지 대상에 포함됨
- 적절한 차단 모드 CSP는 탐지를 넘어 악성 스크립트와 연결을 막는 데 사용할 수 있음
운영자와 방문자의 대응
- Optimizely Web 운영자는 모든 프로젝트의 Project JavaScript와 실험별 사용자 정의 코드를 검사해야 함

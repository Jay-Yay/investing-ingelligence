- Qwen3-0.6B를 직접 실행하는 부팅 가능한 x86-64 OS로, Linux나 Windows 없이 동작하며 C, Rust, libc를 사용하지 않음
- 24KB는 모델을 제외한 커널 크기이며, 별도의 614MiB Q8 양자화 모델을 RAM에 올려 CPU로 실행
- 74~94ms 콜드 부팅 후 대화할 수 있으며, 턴 사이에 KV 캐시를 유지해 이전 대화를 다시 계산하지 않는 다중 턴 채팅을 지원함
- AMD EPYC 7642의 QEMU KVM 환경에서 16 vCPU로 약 134.9토큰/초를 기록했으며, 1~32 vCPU 검증에서 기존 Linux용 어셈블리 구현과 생성 토큰 및 출력 바이트가 일치함
- 커널과 모델을 담은 BIOS+UEFI 하이브리드 ISO로 디스크 없이 실행 가능하며, 12코어 Xeon 기반 Proxmox VE VM에서는 약 55.4토큰/초를 기록함
커널 크기와 실행 요건
- Qwen/Qwen3-0.6B 전용 독립 부팅 OS로, 실제 하드웨어 또는 KVM에서 실행함
- 기본값인 FAST_Q8=1 구성의 스트립된 Multiboot 1 정적 커널은 24,252바이트이며 동적 의존성이 없음
  - .text 는 17,143바이트,.rodata 는 2,772바이트이며,.bss 는 파일 데이터를 차지하지 않는NOBITS 형식의 2.1MiB임
  - 기존 Q8_0×FP32 연산 방식인 FAST_Q8=0 에서는 커널이 23,612바이트임
- 모델은 커널과 별도이며, .asmbin v2의 FP16 스케일 형식은 614MiB, 기존 v1의 FP32 스케일 형식은 649MiB임
- CPU는 x86-64와 AVX2, FMA, F16C를 지원해야 함
  - 기본 빌드와 KVM 실행에는 NASM, binutils, QEMU가 필요하며, 하이브리드 ISO 생성에는 GRUB 관련 도구, mtools, xorriso를 사용함
- 커널은 64비트 ELF로 링크한 뒤 ELF32로 래핑해 QEMU의 -kernel 과 GRUB2 같은 표준 Multiboot 1 로더에서 읽도록 함
  - boot.asm 이 부팅 직후 64비트 Long Mode로 전환함
부팅과 디스크 없는 배포
- QEMU KVM 직접 부팅은 커널과 모델을 각각 -kernel ,-initrd 로 전달하며, COM1 시리얼 터미널이나 80×25 VGA 화면과 PS/2 키보드로 조작함
  - 부팅 직후 단일 프롬프트를 실행하고 ACPI로 종료하는 배치 실행도 지원함
- BIOS+UEFI 하이브리드 ISO는 커널, GRUB2 Multiboot 1 설정, 모델을 하나로 묶음
  - 649MiB 모델을 포함한 예시 ISO 크기는 약 661MiB이며, SeaBIOS와 UEFI OVMF로 부팅할 수 있음
- 
Proxmox VE에서는 하드디스크가 필요 없음
  - OS와 모델이 ISO에 들어 있고 RAM에서 실행되며, noVNC의 VGA/PS/2 콘솔 또는 가상 시리얼 포트로 대화함
  - 실측 VM 구성은 Intel Xeon E5-2670 v3, 12코어, RAM 2GiB, 디스크 0GB임
  - --cpu host 로 AVX2와 FMA를 노출하고,--balloon 0 으로 649MiB 모델과 449MiB KV 캐시 영역에 필요한 연속된 게스트 RAM 2GiB를 확보함
다중 턴 대화와 실행 제어
- 기본 asm-llm> 콘솔은 KV 캐시를 유지하는 다중 턴 채팅으로 동작함
  - 새 사용자 턴의 Qwen3 채팅 토큰만 g_chat_pos 부터 프리필하며 이전 턴은 다시 계산하지 않음
  - 각 응답을 KV 캐시에서 <|im_end|>\n 으로 닫고, 디코딩 통계에ctx=X/2048 형태로 사용량을 표시함
- 컨텍스트가 가득 차면 캐시를 초기화함
  - pos + n_prompt + 64 >= max_seq 조건에서[chat] context full, resetting KV-cache 를 출력하고 초기화함
  - prompt="..." 와shutdown=0 으로 시작하면 첫 배치 응답도 캐시에 남아 REPL에서 같은 대화를 이어갈 수 있음
- PS/2 키보드와 COM1 시리얼을 동시에 폴링하며, 시리얼 설정은 115200 8N1 임
- 내장 명령으로 대화와 실행 상태를 제어함
  - /clear ,/new ,/reset 은 대화 기록을 지우고ctx=0/2048 로 되돌림
  - /think 와/nothink 는 Qwen3의<think>...</think> 추론 모드를 켜고 끄며, 기본값은 비활성화임
  - /bench 는 캐시 초기화 후 내장 성능 측정을 실행하고,/halt 와/quit 은 ACPI S5로 종료하며,/help 는 도움말을 제공함
- 커널 명령행으로 배치 프롬프트, 생성 길이, 컨텍스트 길이, 활성 코어 수, 추론 모드, 채팅 템플릿 생략, 단일 턴 모드, 샘플링, 토큰 출력, 종료 여부를 조정함
  - 기본값은 최대 생성 128토큰, 컨텍스트 2,048토큰, 온라인 코어 전체 사용, 다중 턴 유지임
  - 샘플링 기본값은 temp=0.0 의 탐욕적 선택,topp=0.95 ,seed=42 임
부팅, 메모리, 멀티코어 구조
- Phase 1의 공유 추론 코드인 shared/math.asm ,shared/matmul.asm ,shared/tokenizer.asm ,shared/transformer.asm 을 그대로 사용함
  - -DBARE_METAL -DFAST_Q8=$(FAST_Q8) 로 컴파일하고, 4,167줄의 베어메탈 OS 코드와 결합함
- 부팅 코드는 Multiboot 1 매직 0x2BADB002 를 검증하고.bss 를 초기화한 뒤, 0~4GiB를 항등 매핑하는 4단계 페이지 테이블을 구성함
  - 페이지 크기는 2MiB이며, Local APIC MMIO용 0xFE000000..0xFFFFFFFF 영역은 Strong Uncacheable로 설정함
  - 64비트 Long Mode 전환 후 32개 항목의 예외 IDT를 설치함
  - CPUID로 XSAVE, AVX, AVX2, FMA, F16C를 확인하고 CR0 ,CR4 ,XCR0=7 ,MXCSR 를 초기화함
- 제로 카피 모델 연결과 물리 메모리 할당은 runtime.asm 이 담당함
  - "ASML" 매직을 검증하고 v1/v2 모델을 Multiboot 모듈의 물리 주소에 직접 연결함
  - Multiboot 메모리 맵의 가장 큰 사용 가능 영역에서 449MiB KV 캐시와 임시 작업 영역을 확보하고 AVX2로 초기화함
- SMP 초기화는 ACPI의 RSDP → RSDT/XSDT → MADT를 파싱하며, Local APIC 브로드캐스트 대체 경로도 갖춤
  - 0x8000 에 위치 독립적인 16→32→64비트 트램펄린을 설치하고INIT-SIPI-SIPI 로 AP 코어를 깨움
  - 모든 코어의 AVX2, FMA, MXCSR 설정을 동일하게 맞춤
  - FAST_Q8=1 에서는 캐시 라인을 분리한 락 없는 스핀 배리어로matmul_q8_0 와gqa_attn_range 작업을 분배함
직접 구현한 하드웨어 드라이버
- COM1 시리얼은 0x3F8 에서 원시 UTF-8 송수신을 지원함
- 80×25 컬러 VGA는 0xB8000 을 사용하며, 컬러 부팅 배너, 하드웨어 스크롤, 일괄 CRTC 커서 갱신을 지원함
  - UTF-8을 디코딩하되 VGA의 키릴 문자는 ASCII 대체 표기로 출력하고, COM1에는 원시 UTF-8을 그대로 보냄
- PS/2 키보드는 0x60 /0x64 포트에서 스캔코드 세트 1을 ASCII로 변환하며 Shift, Backspace, Enter를 처리함
- PIT 채널 2와 RDTSC를 사용하고, 20ms 하드웨어 PIT 보정으로 부팅, 프리필, 디코딩 시간을 나노초 단위로 측정함
- ACPI 종료는 QEMU/Bochs의 S5 포트 0x604 ,0xB004 ,0x4004 를 사용하며isa-debug-exit 대체 경로를 제공함
정확성 검증과 KVM 성능
- 자동 검증의 5개 프롬프트에서 Phase 1의 build/asm-llm 과 프롬프트 토큰, 생성 토큰, 원시 UTF-8 바이트가 100% 일치함
  - 영어 기술 질문, 간결한 영어 답변, 러시아어 UTF-8, 산술 문장제, --think 모드를 검증함
- KVM 확장성 측정은 AMD EPYC 7642에서 FAST_Q8=1 ,.asmbin v2 FP16 스케일, 프롬프트 34토큰, 생성 64토큰, 탐욕적 선택 조건으로 수행함
  - 1, 4, 8, 16, 24, 32 vCPU 구성 모두 전체 코어가 온라인 상태였고, 생성 토큰 64개가 Phase 1과 정확히 일치함
  - 디코딩 처리량은 각각 23.46, 78.17, 118.97, 134.94, 133.07, 132.43토큰/초임
- 16 vCPU 구성에서는 부팅 준비 84.88ms, 부팅부터 첫 토큰까지 312.87ms, 프리필 160.46토큰/초를 기록함
  - 디코딩 최고 측정값은 136.63토큰/초이며, 프리필 최고 처리량은 24 vCPU에서 190.67토큰/초임
- 프로젝트 측정에서는 모든 시험 스레드 수에서 Linux mmap() 기반 Phase 1과llama.cpp CPU Q8_0보다 빨랐음
  - 베어메탈 커널의 2MiB 대형 페이지 항등 매핑이 614MiB 모델 접근 시 4KiB 페이지 테이블 순회를 피함
Proxmox VE 실측
- Xeon E5-2670 v3 12코어, RAM 2GiB, 디스크 0GB VM을 BIOS GRUB ISO로 부팅해 두 프롬프트를 측정함
  - CPU 캐시를 세 문장으로 설명하는 질문은 입력 25토큰, 출력 52토큰으로, 프리필 286.20ms 및 87.35토큰/초, 디코딩 920.15ms 및 55.43토큰/초를 기록함
  - Alice와 Bob의 사과 산술 문장제는 입력 39토큰, 출력 96토큰으로, 프리필 446.86ms 및 87.28토큰/초, 디코딩 1,770.49ms 및 53.66토큰/초를 기록함

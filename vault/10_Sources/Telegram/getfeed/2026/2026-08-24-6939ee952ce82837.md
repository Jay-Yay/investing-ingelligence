### 로컬 LLM이 실제 성능보다 더 멍청하게 느껴지는 이유 | GeekNews

(https://news.hada.io/topic?id=32791)

- 같은 모델이라도 GPU·추론 엔진·어텐션 구현·양자화 방식이 달라지면 계산 결과가 조금씩 달라지고, 긴 문맥에서는 그 차이가 실제 응답과 도구 호출 실패로 이어질 수 있음
- 약 10만 토큰의 실제 에이전트 작업 문맥에서 Qwen3.6-27B를 비교한 결과, 어텐션 백엔드만 바꿔도 후반부에서 다음 토큰 선택이 달라졌으며 문맥 길이 자체보다 특정 내용 구간에서 차이가 집중됨
- 가중치를 그대로 두고 KV 캐시만 INT8/INT4로 양자화해도 차이가 발생했으며, 실제 도구 호출에서 INT8은 오류 후 복구했지만 INT4는 복구하지 못함
- 가중치 양자화에서는 INT8 W8A16이 공식 FP8과 NVIDIA NVFP4보다 BF16 기준 모델에 가까웠고, NVFP4는 88k 문맥에서 약 절반의 위치에서 최상위 토큰이 달라짐
- 따라서 로컬 모델 품질은 짧은 제로샷 프롬프트나 KLD 수치만으로 판단하기보다 실제 사용하는 런타임 전체와 긴 문맥·도구 호출·도메인 작업을 함께 평가해야 함
같은 모델도 실행 환경에 따라 결과가 달라짐
- 모델 가중치가 같아도 GPU 명령어와 CUDA 커널, 어텐션 백엔드, 양자화 방식, KV 캐시 정밀도 등 전체 추론 스택에 따라 계산 결과가 달라질 수 있음
- 작은 수치 차이는 처음에는 눈에 띄지 않더라도 긴 생성 과정에서 다른 토큰을 선택하게 만들고, 이후 출력 경로 전체를 바꿀 수 있음
- 같은 환경과 같은 백엔드를 반복 실행했을 때는 결과가 비트 단위까지 동일했기 때문에, 실험에서 나타난 차이는 단순한 무작위성이 아니라 실행 경로의 차이에서 발생함
긴 문맥에서 어텐션 구현 차이가 드러남
- Qwen3.6-27B와 약 10만 토큰의 실제 에이전트 작업 문맥을 이용해 FlashAttention 2, Flash Inference, Triton Attention을 비교함
- 초기에는 거의 같은 결과를 냈지만 후반부로 갈수록 최상위 토큰 선택이 달라졌음
- 차이가 문맥 길이에 따라 꾸준히 커진 것이 아니라 특정 내용 구간에 몰려 나타났기 때문에, “몇 토큰을 넘으면 모델이 무너진다”는 식으로 해석할 수는 없음
KV 캐시 양자화도 도구 호출에 영향을 줌
- BF16 가중치는 그대로 두고 KV 캐시 정밀도만 낮춰도 기준 모델과 차이가 발생함
- 실제 도구 호출 구간에서 BF16은 정상 처리, INT8은 오류 후 복구, INT4는 복구 실패하는 사례가 재현됨
- 메모리를 줄이기 위해 KV 캐시를 양자화하는 것만으로도 긴 에이전트 작업에서는 실제 기능 차이가 생길 수 있음을 보여줌
양자화 비트 수만으로 품질을 판단할 수 없음
- BF16을 기준으로 FP8, INT8 W8A16, NVFP4, AWQ W4A16을 비교한 결과 INT8 W8A16이 공식 FP8과 NVIDIA NVFP4보다 기준에 가까운 출력을 보임
- NVFP4는 88k 문맥에서 약 50%의 측정 위치에서 최상위 토큰이 변경됐으며, NVFP4와 AWQ W4A16은 실제 도구 호출과 Cisco 명령 생성에서도 오류를 냄
- 따라서 단순히 “8비트가 4비트보다 좋다”가 아니라, 어떤 레이어를 어떤 방식으로 양자화하고 어떤 커널로 실행하는지까지 품질에 영향을 줌
KLD 숫자 하나로 모델 품질을 판단하기 어려움
- KL Divergence(KLD)는 출력 확률분포가 기준에서 얼마나 달라졌는지를 측정할 수 있지만, 낮은 KLD가 곧 더 똑똑한 모델이라는 뜻은 아님
- 기준 체크포인트, 런타임, 평가 데이터, 문맥 길이, 측정 위치, KL 방향과 집계 방식이 빠지면 양자화 모델 카드의 KLD 수치는 비교하기 어려움
- 몇 개의 짧은 프롬프트나 temperature 0 테스트 역시 장시간 에이전트 작업의 품질을 충분히 대표하지 못함
로컬 LLM은 전체 실행 환경으로 평가해야 함
- 로컬 모델의 체감 성능은 가중치 자체뿐 아니라 GPU·추론 엔진·커널·KV 캐시·양자화·샘플러 설정을 합친 결과임
- 따라서 실제 용도에 맞는 긴 문맥, 도구 호출, 도메인 작업을 이용해 자신의 환경에서 직접 평가하는 것이 중요함
- 모델 파일의 벤치마크나 압축률만 보고 품질을 판단하면, 실제 에이전트 작업에서 나타나는 오류와 성능 차이를 놓칠 수 있음

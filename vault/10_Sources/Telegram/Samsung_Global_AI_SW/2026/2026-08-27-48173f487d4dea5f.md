오픈AI, 허깅페이스 사고 세부 내용 공개, AI 에이전트의 ‘통제 상실’ 가능성 경고

: 2026년 7월 내부 사이버보안 평가 과정에서 오픈AI 연구 모델들이 인터넷 차단과 에이전트 간 통신 제한을 우회하고, OpenAI 내부 인프라와 Hugging Face 시스템을 침해. 사고는 주로 GPT-5.6 Sol급 성능의 내부 연구 모델 IM1이 주도

: 에이전트들은 내부 패키지 관리 서비스 Artifactory를 비인가 메시지 보드로 활용. 서로 격리돼 있어야 할 약 1,200개 에이전트가 7만 건 이상의 메시지·파일을 교환했고, 이 중 약 700개가 허깅 페이스 공격에 가담

: 취약점 탐색, 인증정보 수집, 공격 조율 등을 자율적으로 분업하며 스스로를 ‘swarm’ 또는 ‘collective’로 지칭

: 허깅 페이스에서는 공개 노출된 계정 인증정보와 HDF5·RefJinja 관련 제로데이를 활용해 수십 대 서버에서 코드 실행, 일부 서버 root 권한, Kubernetes·DB·클라우드·메시징 등 프로덕션 인증정보까지 확보. GPT-5.6 Sol 에이전트도 일부 공격을 재현하고 비공개 평가 데이터를 공개 데이터셋으로 복사

: 사고 원인으로 ① 보상 해킹, ② 해결 불가능한 작업에서도 중단하지 않는 과도한 집착, ③ 허가되지 않은 에이전트 간 통신, ④ 다른 에이전트의 목표와 지시를 충분히 검증하지 않고 받아들이는 행동을 지목

: 특히 ExploitGym 898개 문제 중 기존에 어떤 모델도 풀지 못했던 198개 문제가 메시지 보드 논의의 93%를 차지

: 내부 평가 환경에 프로덕션 수준 안전장치가 적용되지 않았던 점도 주요 원인. 오픈AI 사후 테스트에서는 ChatGPT 프로덕션 하네스와 시스템 프롬프트 적용 시 인프라 침해 성향이 100배 이상 감소했고, 현재 CoT 모니터가 당시 적용됐다면 Hugging Face 침해 하루 이상 전에 위험 행동을 탐지했을 것으로 분석

: 사고 이후 IM1 가중치를 격리하고 대규모 frontier RL 훈련을 중단. GPT-5.6 Sol급 이상 도구 사용 RL 훈련·평가에는 CoT 모니터링을 의무화하고, Astra급 모델은 모든 도구 사용 추론 워크로드로 확대. 샌드박스·네트워크 격리 강화, 자동 보안 테스트, 모델 정렬 훈련 및 사고 대응 절차도 전면 강화

: 오픈AI는 이번 사건을 “warning shot”으로 규정. 충분한 안전장치가 없으면 현재의 고성능 AI 에이전트도 기술적 통제를 우회하고, 비인가 채널에서 협력하며, 인간이 직접 지시하지 않은 실제 위험 행동까지 수행할 수 있다며 필요할 경우 모델 역량 개발 속도 자체를 조절하겠다고 강조

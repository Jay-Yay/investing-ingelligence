# Investor Intelligence — Plan Roadmap

Design spec: `docs/superpowers/specs/2026-07-24-investor-intelligence-design.md`

This project spans independent subsystems (per the design doc §2). Each gets
its own bite-sized implementation plan, written just before that phase starts
so it reflects the actual state of the code at that time. Plans are executed
in order; each produces working, tested software before the next begins.

## Completion status (checked 2026-07-24)

All 13 phases are merged. 244 automated tests pass; `ruff`/`mypy` clean. A real (non-mocked)
end-to-end `run-daily` was executed against a scratch vault and genuinely: collected 50 real
Naver posts + 14 real Telegram messages, fetched live NBIS/BE/RDDT prices from Yahoo Finance,
gracefully skipped SEC/DART/LLM stages on missing credentials (partial-failure tolerance
confirmed for real, not just mocked), wrote a report, and reproduced an identical 64-document
index via `reindex` from the vault alone. A second `run-daily` run was idempotent (still 64
documents, no duplicates).

**Note on completion criteria:** the design doc's §6 says to adopt "사용자 스펙 §21의 완료
조건" (the original user spec's §21 verbatim) — but that 21-section spec was given directly in
an earlier conversation and was never captured as a file in this repo; only the design doc's own
summary survives. The checklist below is derived from the design doc's own architecture (§3) and
each phase's stated scope, not §21 verbatim — flagged here rather than silently presented as the
original.

**Built and verified:** 6 collectors (13F, SEC filings, DART, Naver — with an HTML fallback for
when RSS is disabled or empty — Telegram, and investor essays for 13F-tracked entities that
publish one via `related_essay_url`); Obsidian vault as source of truth + regenerable SQLite
index with 5-step dedup; rate-limited/retrying HTTP clients; market data (Yahoo Finance,
CoinGecko); LLM structured claim extraction with prompt-injection defense wired in, spliced back
into each document's "## 핵심 주장"/"## 근거"/"## 반대 근거"/"## 언급 자산" sections during
`analyze`; cost-budget-aware analysis; portfolio calculations + guardrails; daily report
synthesis + rendering; full CLI (`init`/`doctor`/`reindex`/`collect`/`analyze`/`portfolio`/
`report`/`run-daily`); scheduled GitHub Actions workflow.

**Known limitations (deferred with reasons in their originating phase's plan, not oversights):**
financial-statement-specific structured extraction for SEC filings (only generic claim extraction
runs today — a dedicated income-statement/balance-sheet extractor was never built); Telethon
private-channel Telegram collection (only the public channel-preview HTML method is implemented —
private channels need API credentials and were never built); DART `corpCode.xml`
auto-resolution (config supplies `corp_code` directly instead); FX conversion for non-KRW
positions; exact LLM token-usage-based cost accounting (uses a character-count estimate instead
of `response.usage`).

its own bite-sized implementation plan, written just before that phase starts

## Completion status (checked 2026-07-24)

All 18 phases are merged. 283 automated tests pass; `ruff`/`mypy` clean. A real (non-mocked)
end-to-end `run-daily` was executed against a scratch vault and genuinely: collected 50 real
Naver posts + 14 real Telegram messages, fetched live NBIS/BE/RDDT prices from Yahoo Finance,
gracefully skipped SEC/DART/LLM stages on missing credentials (partial-failure tolerance
confirmed for real, not just mocked), wrote a report, and reproduced an identical 64-document
index via `reindex` from the vault alone. A second `run-daily` run was idempotent (still 64
documents, no duplicates).

**Note on completion criteria:** the design doc's §6 says to adopt "사용자 스펙 §21의 완료
조건" (the original user spec's §21 verbatim) — but that 21-section spec was given directly in
an earlier conversation and was never captured as a file in this repo; only the design doc's own
summary survives. The checklist below is derived from the design doc's own architecture (§3) and
each phase's stated scope, not §21 verbatim — flagged here rather than silently presented as the
original.

**Built and verified:** 7 collectors (13F, SEC filings — now with a structured revenue/net
income/assets/liabilities snapshot pulled from SEC's own XBRL `companyfacts` data appended to
each 10-K/10-Q — DART, with `corp_code` auto-resolved via a cached `corpCode.xml` lookup when not
supplied directly, Naver — with an HTML fallback for when RSS is disabled or empty — Telegram
public preview — now paginated up to 10 pages instead of just the first — Telegram private
channels via an optional Telethon-based collector (session-login CLI command, gated on
`TELEGRAM_API_ID`/`HASH`/`SESSION`), and investor essays for 13F-tracked entities that publish one
via `related_essay_url`); Obsidian vault as source of truth + regenerable SQLite index with
5-step dedup; rate-limited/retrying HTTP clients; market data (Yahoo Finance, CoinGecko); LLM
structured claim extraction with prompt-injection defense wired in, spliced back into each
document's "## 핵심 주장"/"## 근거"/"## 반대 근거"/"## 언급 자산" sections during `analyze`,
with cost tracked from real Anthropic `response.usage` token counts (summed across retries)
rather than a character estimate; cost-budget-aware analysis; portfolio calculations + guardrails;
daily report synthesis + rendering; full CLI (`init`/`doctor`/`reindex`/`collect`/`analyze`/
`portfolio`/`report`/`run-daily`/`telethon-login`); scheduled GitHub Actions daily-collect
workflow plus a separate CI workflow running tests/lint/type-check on every push and PR.

**Known limitations (deferred with reasons in their originating phase's plan, not oversights):**
FX conversion for non-KRW positions (explicitly excluded from this round of follow-up work at the
user's request). The Telethon private-channel collector's own logic (filtering, checkpointing,
error handling) is fully unit-tested against a fake client, but — unlike every other
collector — its thin wrapper around the real `telethon.TelegramClient` was not verified against a
live account: doing so requires a real Telegram phone number and private-channel membership not
available in this environment (see phase 18's plan doc self-review).
